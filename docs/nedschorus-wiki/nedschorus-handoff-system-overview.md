# The handoff-system: an overview

The handoff-system is the subsystem behind reincarnate-seat: it replaces a filling agent-session with a fresh one. The scripts' docstrings write it "the handoff system". Terms are the project glossary's, `docs/nedschorus-wiki/nedschorus-glossary.md`. The code is the master: each Python script's docstring says what it does and why, `scripts/launch-claude-mac` and `scripts/launch-claude-ubuntu` say so in a header comment, and every part below has a test beside it, named for it with `-test.py`. This page names the parts, says why they are built this way, lists the open work, and notes where the design of record has gone stale. Agent-seats, and how one is launched, paused or retired, are in `docs/nedschorus-wiki/nedschorus-agent-seat-model.md`. The design of record, `docs/cross-project/fast-handoff-design.md`, records dated rulings and their reasons and is not updated to track the build; where it and this page disagree, the code decides. Every claim below about the code was checked against the code on 2026-09-16.

## Why it exists

A fleet of agent-seats runs with little attention from the user. An agent-session's context window fills as it works; the work is mostly sequential, so old turns can leave the window. The handoff-system replaces the agent-session before the window gets heavy, with nobody typing into each pane. Rejected for that in the design of record's problem statement: compaction, which summarizes uniformly when turns are not uniformly valuable, and is slow; and `claude --continue` or `--resume`, which restore the context being shed. Crash recovery resumes the crashed agent-session where it can: after a crash nothing was shed.

## The parts

All under `scripts/` unless named otherwise; the files they keep for the handoff-system are under `~/.claude/handoffs/` on the agent-seat's machine.

- **`handoff-context-threshold-hook.py`**, a Stop hook: at a set share of the context window, tells the agent once per agent-session to run the /handoff skill, deferring while a subagent or a young background task is in flight.
- **The /handoff skill**, `.claude/skills/handoff/SKILL.md`: the agent writes its successor's first action and open items to a next-step file and runs the writer script, `handoff-write-and-check-supervisor.py`, on it.
- **`handoff-write-and-check-supervisor.py`**: computes every field but the next step and `dont-restart`, which the agent sets when the user wants to be asked before a relaunch; writes the session-handoff file `<seat>-handoff.md`, and reports whether a handoff-supervisor watches that name.
- **`handoff-supervisor.py`**, the handoff-supervisor: one per agent-seat, in its tmux pane; consumes the session-handoff, kills the agent-session, extracts its conversation tail, launches the successor. Holds `<seat>-supervisor.lock`; heartbeats into `<seat>-supervisor-state.json`.
- **`handoff-extract-conversation.py`**: writes the conversation tail, `<seat>-dialog-NNNN.md` (NNNN is the generation number), which the successor is told to read first; when the tail leaves earlier turns out, it also writes `<seat>-dialog-NNNN-complete.md`, the whole dialog, for the successor to read if it needs more.
- **`launch-claude-mac` and `launch-claude-ubuntu`**: start an agent-seat's tmux session with a handoff-supervisor inside it.
- **Recovery**: `resupervise-seat.py` puts an unwatched agent-seat back under a handoff-supervisor from a waiting session-handoff, ending the agent-session still running there; `recover-crashed-seats.py` brings back an agent-seat whose agent-session died with no session-handoff acted on; `restart-live-seats-at-login.py` brings back, at login on the Mac and at boot on ned-box, the agent-seats whose heartbeats say they were running when the machine stopped, and on the Mac opens a window onto each ned-box agent-seat still running. Designs: `docs/issues/120-recover-crashed-seats-design.md` and `docs/issues/116-fleet-survives-machine-restart-design.md`.

## Why it is built this way

- **A separate process does the killing because an agent cannot end its own agent-session.** Measured 2026-07: `/clear` and `/exit` are unavailable to the agent, and a self-sent SIGTERM trips the safety classifier.
- **The handoff-supervisor runs inside the tmux pane because a successor inherits its stdio.** The writer script once started a handoff-supervisor outside any pane, with a log file for a console, to take over an unwatched agent-session; every successor it launched died at its first need for input. That self-start was removed 2026-08-14; the remedy is `resupervise-seat.py`, run by the user. The handoff-supervisor still accepts `--adopt-session-id` with `--adopt-process-id`, and no launcher or recovery script passes them.
- **The agent writes the next step, and says whether the user wants to be asked before a relaunch; the writer script computes the rest** (user-ruled 2026-08-06). Hand-written fields asked the agent to do arithmetic and failed silently.
- **The conversation tail is cut mechanically, not by the predecessor's judgment** (user-ruled 2026-08-06). The successor is not dumber than the predecessor, so it gets the dialog word for word. No summary.
- **One handoff-supervisor per agent-seat, and no two agent-seats share a name, on either machine.** Two handoff-supervisors would each kill the agent-session and each launch a successor; the lock refuses the second. Files and locks are per-machine, so nothing on disk stops the same name on the Mac and on ned-box, but every launch registers the agent-session for cross-session messages under that name (`--remote-control <name>`), and a name on both machines is ambiguous to a sender. Nothing enforces the name rule across machines; the user keeps it.
- **A handoff-supervisor is alive if its process is running `handoff-supervisor.py` for that agent-seat, not if its heartbeat is recent** (issue [recover-crashed-seats.py: the six changes ruled 2026-09-02 — exit record, process-identity liveness, parking marker, verified restart, by-hand resume, window](https://github.com/nedschorus/nedschorus/issues/242) change 1, 2026-09-12). The rule it replaced read a heartbeat under sixty seconds old as a live handoff-supervisor. Measured on ned-box by killing an agent-seat's tmux server, `recover-crashed-seats.py` refused to recover that agent-seat for the next minute, and `restart-live-seats-at-login.py`, which runs `recover-crashed-seats.py` for each agent-seat soon after boot, could have been refused the same way, depending on how fast the machine boots. The heartbeat now decides only which agent-seats to bring back after a reboot, when no process exists to ask; the writer script's report also prints its age.
- **A handoff-supervisor watches a name; a session-handoff addressed to a name no handoff-supervisor watches goes to a file nobody polls.** Reported by merge-lane-51 on 2026-09-15: its agent-session passed `--agent merge-lane-51`, the name Claude Code lists a running agent-session under, where the agent-seat's name `merge-lane` was wanted. The writer script found no handoff-supervisor for that name and said keep working; the hook had already asked once; the agent-session died of context exhaustion hours later while its handoff-supervisor waited on the right file. PR [Refuse a handoff written under a seat name no supervisor answers to](https://github.com/nedschorus/nedschorus/pull/394) added a refusal in the writer script that names the right name to rerun with, once the agent-seat has handed off under the right name; PR [The handoff skill loses its two fill-in-the-blank placeholders](https://github.com/nedschorus/nedschorus/pull/395) took the name out of the skill's steps; PR [The handoff's seat name and directory come from the handoff-supervisor](https://github.com/nedschorus/nedschorus/pull/414) made the name default to the one the handoff-supervisor watches. A session-handoff addressed to another live agent-seat's name is a different failure: that agent-seat's handoff-supervisor can consume it.
- **Reincarnating kills the agent-session's subagents with it** (user-ruled 2026-08-23; the deferral added 2026-08-27). The session-handoff records the subagents still working so the successor can start fresh ones; the hook defers while one is in flight, since the kill would lose its work, but only up to a ceiling, because waiting on a subagent that never finishes loses more. So a subagent's prompt for a job longer than one step says how work survives a kill: commit after each step, and rewrite the report file as you go.
- **Git is the durable record; the session-handoff is not** (user-ruled 2026-08-02). The session-handoff lives on the agent-seat's machine only and is never committed.

## Open work

- issue [recover-crashed-seats.py: the six changes ruled 2026-09-02 — exit record, process-identity liveness, parking marker, verified restart, by-hand resume, window](https://github.com/nedschorus/nedschorus/issues/242) changes 2, 3 and 5, to `recover-crashed-seats.py` and, for 2 and 5, `handoff-supervisor.py`: record how the agent exited; a durable parking marker for an agent-seat the user set aside; a by-hand launch that resumes a crashed agent-seat. Changes 1, 4 and 6 are built.
- issue [Fleet survives a machine restart without losing seat context: detect, hand off on notice, relaunch at boot, resume from transcript](https://github.com/nedschorus/nedschorus/issues/116): surfacing a pending reboot when a launcher starts an agent-seat; handling an agent-seat `restart-live-seats-at-login.py` cannot bring back (waits on issue [recover-crashed-seats.py: the six changes ruled 2026-09-02 — exit record, process-identity liveness, parking marker, verified restart, by-hand resume, window](https://github.com/nedschorus/nedschorus/issues/242) change 3); the Mac's real login after a real reboot, unmeasured.
- issue [recover-crashed-seats: a dont-restart handoff on the defer path burns the 120s deadline, then is offered the relaunch it declined](https://github.com/nedschorus/nedschorus/issues/350): `recover-crashed-seats.py` never reads a session-handoff's `dont-restart` field when it relaunches an agent-seat whose session-handoff is waiting.
- issue [Two permission-scope decisions for the user: whether the seat launcher names a mode, and whether the global allow list stays](https://github.com/nedschorus/nedschorus/issues/341): whether the handoff-supervisor passes a permission mode at launch; an open decision.
- issue [Run named agents on the Ubuntu box, reachable from iTerm2 by name: launch-claude with tmux attach-or-create, and the migration it requires](https://github.com/nedschorus/nedschorus/issues/45): the handoff-supervisor's adoption of a running agent-session (`--adopt-session-id`) is built, and no launcher or recovery script reaches it.

Fixed 2026-09-16. A running handoff-supervisor keeps the old code until it restarts, and the writer script an agent runs is the copy in its agent-seat's checkout.

- `handoff-supervisor.py`'s pruning of old conversation tails kept the newest two files rather than two generations, so a long dialog's `-complete.md` companion evicted the previous generation's tail (PR [The dialog pruner keeps two generations, not two files](https://github.com/nedschorus/nedschorus/pull/406)).
- The writer script's default name was the working directory's basename, so an agent that had moved into a subdirectory or a worktree handed off under a name no handoff-supervisor watches. The handoff-supervisor now tells each agent-session it launches the agent-seat's name and directory, and the writer script uses them in that agent-session (PR [The handoff's seat name and directory come from the handoff-supervisor](https://github.com/nedschorus/nedschorus/pull/414)).

## Where the design of record is stale

- It marks the multi-line `next-step-verbatim` block form "queued, not built". The block form is built, in the writer script and the handoff-supervisor.
- Its parts list, its self-registration ruling and its known-holes list say a dead handoff-supervisor self-heals through an adopting handoff-supervisor the writer script starts. That path was removed 2026-08-14.
- Its open question, where a successor's output goes in an interactive pane, was settled by the first half of its recommendation: the launchers run the handoff-supervisor as the pane's own command. The second half, adoption as the bootstrap and recovery path, was not built. The design never recorded the answer.
