# The handoff-system: an overview

The handoff-system is the subsystem behind reincarnate-seat: it replaces a filling agent-session with a fresh one. The scripts' docstrings write it "the handoff system". Terms are the project glossary's, `docs/nedschorus-wiki/nedschorus-glossary.md`. The code is the master: each Python script's docstring says what it does and why, `scripts/launch-claude-mac` and `scripts/launch-claude-ubuntu` say so in a header comment, and every program below has a test named for it with `-test.py`, beside it in `scripts/` or under `nc-systems/handoff/tests/`, with four exceptions: the handoff-supervisor's tests are three suites that run in parallel, `handoff-supervisor-successor-prompt-test.py`, `handoff-supervisor-session-launch-and-seat-lock-test.py` and `handoff-supervisor-session-end-and-resume-test.py`, which share `handoff-supervisor-test-fixture.py`; `seat-transcript-worth-resuming.py`, a module, is tested through `resupervise-seat-test.py`; `agent-seat-state-records-reader.py`, a module, is tested through the suites of the three programs that load it; and `scripts/uncommitted-work-snapshot-hook.py` is tested through `nc-systems/handoff/tests/uncommitted-work-snapshots-test.py`, the suite of the module the hook loads. `handoff-census-user-record-shapes.py` has no test. This page names the parts, says why they are built this way, lists the open work, and notes where the design of record has gone stale. Agent-seats, and how one is launched, paused or retired, are in `docs/nedschorus-wiki/nedschorus-agent-seat-model.md`. The design of record, `nc-systems/handoff/handoff-design.md`, records dated rulings and their reasons and is not updated to track the build; where it and this page disagree, the code decides. Work-snapshots have a design of their own, `nc-systems/handoff/uncommitted-work-snapshots-across-crashes-design.md`.

## Why it exists

A fleet of agent-seats runs with little attention from the user. An agent-session's context window fills as it works; the work is mostly sequential, so old turns can leave the window. The handoff-system replaces the agent-session before the window gets heavy, with nobody typing into each pane. Rejected for that in the design of record's problem statement: compaction, which summarizes uniformly when turns are not uniformly valuable, and is slow; and `claude --continue` or `--resume`, which restore the context being shed. Crash recovery resumes the crashed agent-session where it can: after a crash nothing was shed.

## The parts

The system is half moved into `nc-systems/handoff/`: the supervisor, the writer script, the census, the two daily mark programs, the agent-seat records reader and the work-snapshot module below are there, and the rest is still under `scripts/`, held there because a running handoff-supervisor, or Claude Code's hook configuration, names the old path. The files they keep for the handoff-system are under `~/.claude/handoffs/` on the agent-seat's machine, except the daily memory review's marks and the daily overview-refresh reminder marks, which are in the log-store on ned-box, and the work-snapshots themselves, which are refs in the machine's clone.

- **`scripts/handoff-context-threshold-hook.py`**, a Stop hook: at a set share of the context window, tells the agent once per agent-session to run the /handoff skill, deferring while a subagent or a young background task is in flight. It stays silent in a session its caller reincarnates itself, which is ghi-info's under `scripts/ghi-info-ask.py`.
- **`scripts/post-compaction-session-continues-hook.py`**, a SessionStart hook for a compacted session: hands the agent its own conversation tail and tells it to continue, and re-arms the threshold hook.
- **The /handoff skill**, `.claude/skills/handoff/SKILL.md`: the agent writes its successor's first action and open items to a next-step file and runs the writer script, `handoff-write-and-check-supervisor.py`, on it.
- **`nc-systems/handoff/handoff-write-and-check-supervisor.py`**: computes every field but the next step and `dont-restart`, which the agent sets when the user wants to be asked before a relaunch; writes the session-handoff file `<seat>-handoff.md`, and reports whether a handoff-supervisor watches that name.
- **`nc-systems/handoff/handoff-supervisor.py`**, the handoff-supervisor: one per agent-seat, in its tmux pane; consumes the session-handoff, kills the agent-session, extracts its conversation tail, launches the successor. It launches every agent-session with `--name` and `--remote-control-session-name-prefix` as well as `--remote-control`, each given the agent-seat's name. Before each launch that does not adopt a running agent-session, it fast-forwards the checkout to main, on a branch or detached, unless an uncommitted tracked change or a git operation in progress stops it, and prints the outcome as its "branch sync" line. The first prompt of every agent-session it starts, a resume included, lists the agent-seat's lost work-snapshots. At each handoff it also updates the agent binary through `scripts/agent-binary-update-under-lock.py`, which skips the update when another update on the machine holds its lock, and removes finished worktrees and merged branches through `scripts/clean-worktrees.py`, printing a summary that names the uncommitted, untracked or ignored files each removed worktree held. When the agent-session dies without a session-handoff, it resumes that session rather than stopping; on a first launch with no session-handoff waiting and no recorded exit, it resumes the agent-seat's last transcript rather than starting empty, even when it was given a first prompt. It refuses to start unless a launcher has pinned the agent-seat's task list in `CLAUDE_CODE_TASK_LIST_ID`. Holds `<seat>-supervisor.lock` with an exclusive flock for its whole life; heartbeats into `<seat>-supervisor-state.json`, and records there how its agent exited.
- **`nc-systems/handoff/daily-memory-review-mark.py`**: records that the day's review of the two machines' memory stores has started, or is done, as one file per mark. The handoff-supervisor loads it for where the stores and the marks are, the Pacific date and the digest of both stores, so the line the handoff-supervisor gives a successor and the marks cannot disagree about any of these three.
- **`nc-systems/handoff/daily-overview-refresh-reminder-mark.py`**: records that the user has been shown the day's refresh of one system's overview, as one file per system per Pacific day, `nedlern@ned-box:/home/nedlern/nedschorus-logs/daily-overview-refresh-reminder-marks/<YYYY-MM-DD>-<system>.txt`, holding the time it was written. It reads and writes through `daily-memory-review-mark.py`'s reader and writer. A retry passes `--shown-on-pacific-date`, and a retry made after that Pacific day writes nothing, so no mark records a day on which the user saw nothing.
- **`nc-systems/handoff/agent-seat-state-records-reader.py`**: holds the rules `restart-live-seats-at-login.py`, `recover-crashed-seats.py` and `scripts/seat-task-list-read.py` use to read an agent-seat's records from the files it leaves, so that a later reader of the seat-database service of GHI [A small service on ned-box keeps one record of every agent-seat on both machines](https://github.com/nedschorus/nedschorus/issues/972) replaces them in one place. It reads files only. It re-exports the handoff-supervisor's own readers rather than moving them, because `handoff-supervisor.py` owns the file names; it loads the handoff-supervisor, so the handoff-supervisor does not load it.
- **`nc-systems/handoff/uncommitted-work-snapshots.py`**, the work-snapshot module, and its PostToolUse hook **`scripts/uncommitted-work-snapshot-hook.py`**: after every Edit, Write, NotebookEdit and Bash call, the hook keeps a work-snapshot of the uncommitted changes in each worktree the call may have changed, owned by the `claude` process the hook runs under, and deletes that work-snapshot once nothing in the worktree is uncommitted; the hook never changes a worktree's files, index or branch. A work-snapshot whose owner process is gone is a leftover. The module has three callers: the hook; the handoff-supervisor, which lists the agent-seat's lost leftovers in a first prompt with the steps to restore them, and records each one's first listing in `<seat>-work-snapshots-first-listed.json`; and `scripts/clean-worktrees.py --remove`, which deletes a leftover still lost more than ten days after its first listing, and an older leftover that a newer leftover of the same agent-seat and worktree duplicates exactly. The summary of worktree removals the handoff-supervisor prints at each handoff counts those deletions and names each work-snapshot failure. `python3 nc-systems/handoff/uncommitted-work-snapshots.py list --agent-seat <name>` lists an agent-seat's lost leftovers.
- **`scripts/handoff-extract-conversation.py`**: writes the conversation tail, `<seat>-dialog-NNNN.md` (NNNN is the generation number), which the successor is told to read first; when the tail leaves earlier turns out, it also writes `<seat>-dialog-NNNN-complete.md`, the whole dialog, for the successor to read if it needs more. It reads the transcript of the agent-session that wrote the session-handoff. `nc-systems/handoff/handoff-census-user-record-shapes.py` is its receipt: it counts the shapes of user records across every transcript, and a shape it cannot classify is a new prefix for the extractor to drop. `scripts/locate-user-approval-by-question-subject.py` loads its transcript reader too, asking it to keep every agent message, so that a user's reply is matched to the message it followed.
- **`scripts/launch-claude-mac` and `scripts/launch-claude-ubuntu`**: start an agent-seat's tmux session with a handoff-supervisor inside it.
- **Recovery**, all under `scripts/`: `resupervise-seat.py` puts an unwatched agent-seat back under a handoff-supervisor from a waiting session-handoff, ending the agent-session still running there; `recover-crashed-seats.py` brings back an agent-seat the handoff-supervisor did not, because the supervisor stopped or died, offering rather than resuming one whose agent exited cleanly; `seat-transcript-worth-resuming.py` is the one definition of which transcript is worth resuming, shared by this tool and the handoff-supervisor; `restart-live-seats-at-login.py` brings back, at login on the Mac and at boot on ned-box, the agent-seats whose heartbeats say they were running when the machine stopped, and on the Mac opens a window onto each ned-box agent-seat still running. Designs: `docs/issues/120-recover-crashed-seats-design.md` and `docs/issues/116-fleet-survives-machine-restart-design.md`.

## Why it is built this way

- **A separate process does the killing because an agent cannot end its own agent-session.** Measured 2026-07: `/clear` and `/exit` are unavailable to the agent, and a self-sent SIGTERM trips the safety classifier.
- **The handoff-supervisor runs inside the tmux pane because a successor inherits its stdio.** The writer script once started a handoff-supervisor outside any pane, with a log file for a console, to take over an unwatched agent-session; every successor it launched died at its first need for input. That self-start was removed 2026-08-14; the remedy is `resupervise-seat.py`, run by the user. The handoff-supervisor still accepts `--adopt-session-id` with `--adopt-process-id`, and no launcher or recovery script passes them.
- **The agent writes the next step, and says whether the user wants to be asked before a relaunch; the writer script computes the rest** (user-ruled 2026-08-06). Hand-written fields asked the agent to do arithmetic and failed silently.
- **The conversation tail is cut mechanically, not by the predecessor's judgment** (user-ruled 2026-08-06). The successor is not dumber than the predecessor, so it gets the dialog word for word. No summary.
- **One handoff-supervisor per agent-seat, and no two agent-seats share a name, on either machine.** Two handoff-supervisors would each kill the agent-session and each launch a successor; the lock refuses the second. Files and locks are per-machine, so nothing on disk stops the same name on the Mac and on ned-box, but every launch registers the agent-session under that name, for Remote Control with `--remote-control <name>` and for cross-session messages on the same machine with `--name <name>`, and a name on both machines is ambiguous to a sender. Nothing enforces the name rule across machines; the user keeps it.
- **A handoff-supervisor is alive if its process is running `handoff-supervisor.py` for that agent-seat, not if its heartbeat is recent** (issue [recover-crashed-seats.py: the six changes ruled 2026-09-02 — exit record, process-identity liveness, parking marker, verified restart, by-hand resume, window](https://github.com/nedschorus/nedschorus/issues/242) change 1, 2026-09-12). The rule it replaced read a heartbeat under sixty seconds old as a live handoff-supervisor. Measured on ned-box by killing an agent-seat's tmux server, `recover-crashed-seats.py` refused to recover that agent-seat for the next minute, and `restart-live-seats-at-login.py`, which runs `recover-crashed-seats.py` for each agent-seat soon after boot, could have been refused the same way, depending on how fast the machine boots. The heartbeat now decides only which agent-seats to bring back after a reboot, when no process exists to ask; the writer script's report also prints its age.
- **A handoff-supervisor watches a name; a session-handoff addressed to a name no handoff-supervisor watches goes to a file nobody polls.** Reported by merge-lane-51 on 2026-09-15: its agent-session passed `--agent merge-lane-51`, the name Claude Code lists a running agent-session under, where the agent-seat's name `merge-lane` was wanted. The writer script found no handoff-supervisor for that name and said keep working; the hook had already asked once; the agent-session died of context exhaustion hours later while its handoff-supervisor waited on the right file. PR [Refuse a handoff written under a seat name no supervisor answers to](https://github.com/nedschorus/nedschorus/pull/394) added a refusal in the writer script that names the right name to rerun with, once the agent-seat has handed off under the right name; PR [The handoff skill loses its two fill-in-the-blank placeholders](https://github.com/nedschorus/nedschorus/pull/395) took the name out of the skill's steps; PR [The handoff's seat name and directory come from the handoff-supervisor](https://github.com/nedschorus/nedschorus/pull/414) made the name default to the one the handoff-supervisor watches. A session-handoff addressed to another live agent-seat's name is a different failure: that agent-seat's handoff-supervisor can consume it.
- **The handoff-supervisor resumes a death without a session-handoff, and decides on the exit code alone** (user-ruled 2026-09-21). On 2026-09-21 the MD-skills agent-seat was terminated with exit code 143 while idle, beside an intact transcript, and stayed dark until the user looked. A parent process learns how its child died but never who killed it, so the code decides: 0 is a decision and stops the agent-seat; a signal or an error status resumes it, under a budget of consecutive resumes without new work, so a session that dies on every launch is not relaunched forever. Every stop still writes the exit record, so `recover-crashed-seats.py` stays the fallback.
- **A compacted session needs a hook of its own** (user-ruled 2026-09-20). Compaction stops the session until someone types, and it keeps the session id, so the threshold hook's once-per-session marker still stands and an agent-seat that compacts would never be asked to hand off again. Measured 2026-09-20 on the merge-lane agent-seat: one fifty-minute turn with no turn boundary let the context reach 97.2% before the Stop hook could fire. The SessionStart hook answers both: it hands the tail back with an instruction to continue, and clears the marker.
- **Reincarnating kills the agent-session's subagents with it** (user-ruled 2026-08-23; the deferral added 2026-08-27). The session-handoff records the subagents still working so the successor can start fresh ones; the hook defers while one is in flight, since the kill would lose its work, but only up to a ceiling, because waiting on a subagent that never finishes loses more. So a subagent's prompt for a job longer than one step says how work survives a kill: commit after each step, and rewrite the report file as you go.
- **Git is the durable record; the session-handoff is not** (user-ruled 2026-08-02). The session-handoff lives on the agent-seat's machine only and is never committed.
- **A recovered agent-seat's handoff-supervisor runs from the machine's clone at `~/Projects/nedschorus`, whichever checkout the recovery ran from** (user-ruled 2026-09-29; PR [A recovered seat's supervisor runs from the reference clone, not from the checkout the recovery ran from](https://github.com/nedschorus/nedschorus/pull/778)). At every handoff the handoff-supervisor runs the extractor from its own checkout, so one started from a worktree stopped at its first handoff after that worktree was removed (issue [recover-crashed-seats: a recovered seat's supervisor runs from whichever checkout the recovery was run from, and stops at its next handoff once that checkout is removed](https://github.com/nedschorus/nedschorus/issues/659)).
- **The handoff-supervisor tells a successor which systems' overviews have fallen behind their code** (user-ruled 2026-09-23 and 2026-09-29; PR [A reincarnated seat is told when a system's overview has fallen behind its code](https://github.com/nedschorus/nedschorus/pull/764), PR [A seat is not told to refresh an overview while an open pull request already changes it](https://github.com/nedschorus/nedschorus/pull/776)). It checks once per reincarnation; a Stop hook, where the approval-walk that ruled it first placed it, would repeat the line at every turn. Only a successor of the agent-seat agent-instructions-editor is told (user-ruled 2026-10-10), because the other agent-seats have jobs of their own; the line is withheld while an open pull request changes the overview, because every successor replaced before that pull request merges would otherwise send its own, conflicting refresh. It reads the pin through `scripts/stale-code-citation-check.py`, so a pinned line means one thing to both programs, and leaves out Markdown under `nc-systems/<system>/`, where the design's own pinned line would make every refresh due again.
- **A refreshed overview is drafted for the user, and the line goes out once a day** (user-ruled 2026-10-01; PR [The instruction-file guard protects the files the user reviews, by where they sit](https://github.com/nedschorus/nedschorus/pull/852)). The instruction-file guard refuses an edit to a page under `docs/nedschorus-wiki/`, so the line has a subagent write the refresh to `docs/nedschorus-wiki/queue/nedschorus-<system>-system-overview-draft.md`, and the agent-seat shows the user the diff and writes the overview from the draft only once he approves it. The draft takes a name of its own because `scripts/file-name-collision-warning-hook.py` answers a second file under a tracked file's name. Since the pull request that withholds the line opens only after the user has answered, every successor replaced during that wait would draft the same refresh; so once the user has been shown the diff, the agent-seat runs `daily-overview-refresh-reminder-mark.py`, and the line for that system is withheld for the rest of the Pacific day. An agent-session closed before it shows him the diff leaves no mark, so the next successor that day is given the line. The user's floor is a reminder at least once a day, so when the marks cannot be read, every due line is given, with one more line telling the successor to tell the user the marks could not be read (PR [handoff-supervisor: a failure to read the day's reminder marks reaches the successor's prompt](https://github.com/nedschorus/nedschorus/pull/1015)); that line adds the ssh check to run on the Mac only when ned-box did not answer, since an answer that does not parse came from ned-box (PR [handoff-supervisor: an unparsable answer from ned-box is not reported as no answer](https://github.com/nedschorus/nedschorus/pull/1024)). On 2026-10-03 the user turned this daily reminder down in favor of a refresh agent that drafts each refresh itself, not built yet ([the refresh design of GHI 670](https://github.com/nedschorus/nedschorus/blob/main/docs/issues/670-refresh-design-when-a-system-s-code-lands.md)); the reminder runs as described here until that agent replaces it.
- **The handoff-supervisor holds its lock with flock** (user-approved in approval-walk complexity-sweep-findings-2026-10-02, item 6; PR [The handoff supervisor holds its singleton lock with flock](https://github.com/nedschorus/nedschorus/pull/1022)). The lock file was claimed by an exclusive create, and a lock left by a dead handoff-supervisor was reclaimed by judging whether the recorded process was alive. The kernel releases a flock when its holder dies, SIGKILL included, so the next handoff-supervisor claims the lock at once. The handoff-supervisor still writes its process ID into the file, so every reader of the liveness rule above works unchanged. A lock directory not confirmed to be on a local filesystem is refused, because flock is not reliable on a network filesystem.
- **A crashed agent-seat's transcript wins over a first prompt** (PR [handoff-supervisor: a crashed seat's transcript wins over --first-prompt-file](https://github.com/nedschorus/nedschorus/pull/1068)). Relaunch commands keep the founding `--first-prompt-file` long after the founding boot. On 2026-10-04 every process on ned-box was sent SIGTERM; the Mac relaunched the agent-seats, and the one relaunched with that flag started fresh on its founding brief beside a transcript of a day's work, while the others resumed. The handoff-supervisor cannot tell a stale founding brief from a deliberate ignition prompt by the flag alone, so the caller that means its prompt to win says so with `--first-prompt-file-wins-over-crashed-transcript`; `recover-crashed-seats.py --ignite-fallback`, which chooses not to resume, passes it. A waiting session-handoff still wins over both.
- **The launcher's pinned task list is the only carrier of tasks across generations** (user-approved in approval-walk complexity-sweep-findings-2026-10-02, item 18; PR [The handoff-supervisor requires the launcher-pinned task list](https://github.com/nedschorus/nedschorus/pull/998)). Every launcher sets `CLAUDE_CODE_TASK_LIST_ID`, so every generation of an agent-seat opens one task list and nothing is copied. The path that copied a retiring agent-session's task files into its successor's list when the variable was unset is removed, and a handoff-supervisor started without the variable stops at startup, names the launchers, and exits 2.
- **A launch never waits for another agent-binary update** (user-approved in approval-walk complexity-sweep-findings-2026-10-02, item 12; PR [Skip a claude update when another update holds the lock](https://github.com/nedschorus/nedschorus/pull/1033)). A launcher or handoff-supervisor that finds the machine's update lock held prints one line and launches on the installed `claude`.
- **A merged, vacant worktree is removed whatever files it holds** (user-ruled 2026-10-04; PR [clean-worktrees: a merged, vacant worktree is removed whatever files it holds, each file named first](https://github.com/nedschorus/nedschorus/pull/1042)). Keeping a worktree with uncommitted files was a precaution nothing shows ever saved work, and it kept leftover worktrees forever. Instead the files are named: `clean-worktrees.py --remove` prints a line naming them before each removal and another after it succeeds, and the handoff-supervisor's summary puts each worktree in one bucket, confirmed, failed, or started but not confirmed, so a removal stopped partway still names what may be gone (PR [clean-worktrees: discard lines survive a killed run, and the handoff summary names each worktree once](https://github.com/nedschorus/nedschorus/pull/1053)).
- **From noon Pacific, a Mac handoff-supervisor asks a successor for the day's review of both machines' memory stores** (user-ruled 2026-09-30; PR [From noon Pacific, a reincarnated Mac seat is asked for the day's review of both memory stores](https://github.com/nedschorus/nedschorus/pull/823)). The user's reason: memory is useful in the short term and counterproductive unless drained regularly. The review puts each entry to the user in an approval-walk with a recommended outcome, a fix to an instruction file, a task, a GHI or nothing, carries out his ruling, and then deletes the entry with a shell command; an entry is never edited, because the instruction-file guard refuses every Edit or Write into a memory store (user-ruled 2026-10-05; PR [instruction-file-guard: a memory write is refused with its own text, asking the user what to do with it](https://github.com/nedschorus/nedschorus/pull/1087)). The check sits beside the overview check for the same reason, once per reincarnation. Only a Mac handoff-supervisor gives the line, because the user reads on the Mac and only the Mac can read both stores: the Mac reaches ned-box's store over ssh, and nothing gives ned-box a way back. The line names ned-box's store by its path under the Mac's mount of ned-box's home, `/Volumes/nedhome/`, with the scp form for a day the share is not mounted, so the reviewing agent reads each entry with its file tools; the handoff-supervisor and the mark program still read ned-box over ssh, which gives up after ten seconds, where a read from a hung mount has no time limit (PR [The memory review reminder names ned-box's store by the Mac's mount path, with ssh as the fallback](https://github.com/nedschorus/nedschorus/pull/929)). Noon and the marks' dates are read in America/Los_Angeles, never in a machine's own zone. The successor marks the review started before walking the user through the entries, so an agent-seat reincarnated during the approval-walk is not asked for the same review; a successor that dies during the approval-walk leaves the started mark, and the line stays away until the next noon, which is deliberate. The done mark records a digest of both stores, and from the next noon the line returns only once the digest differs. A failed read, ned-box unreachable included, gives no line and writes no mark, so the launch goes on and a later reincarnation checks again.
- **Uncommitted work is copied as a work-snapshot because the worktree cleaner removes it with the worktree after a crash** (user-approved in approval-walk uncommitted-work-snapshots-across-crashes-design-2026-10-05-2; PR [Work-snapshots: uncommitted work outlives a crash and the worktree cleaner](https://github.com/nedschorus/nedschorus/pull/1096)). The cleaner rightly removes a worktree whose branch has no commits beyond main and in which nothing runs, uncommitted files included, so on 2026-10-05 a fork killed before its first commit lost its edits at the next 06:30 run. A work-snapshot is a commit under `refs/work-snapshots/`, which no branch points to and an ordinary `git push` does not send, so it outlives both the crash and the cleanup and stays on its machine. Its owner is the `claude` process, not the agent-session or the fork, because a fork runs inside its parent's process and dies with it; the owner key adds the process's start to its id, so a reused process id is not taken for the owner.
- **A leftover is listed only when its worktree is gone or no longer holds its changes** (user-ruled 2026-10-08). A session-handoff, a quota stop and a logout each end the owner process and leave its files in place, and agent-seat checkouts keep uncommitted files on purpose, so listing every leftover whose owner is gone would list the same files after every session-handoff. Whether the owner process is alive decides only whether the cleaner may ever delete a work-snapshot. A leftover still held by its worktree is kept unlisted, and is listed once that worktree is removed or changed.
- **Nothing judges whether a lost change still exists somewhere else.** A rule that deleted a leftover once its changes appeared in a later work-snapshot or in the worktree's commit was built and then removed during the review of PR [Work-snapshots: uncommitted work outlives a crash and the worktree cleaner](https://github.com/nedschorus/nedschorus/pull/1096): each review round found a new way for that rule to delete the only copy of discarded work, and the user had ruled only on listing. So the cleaner deletes a leftover only more than ten days after its first listing, or when a newer leftover holds the same parent commit and the same tree by git object id. A leftover of work since committed is listed too, an accepted cost: the restore steps' diff shows the agent the work is committed, and the agent deletes the work-snapshot.
- **The handoff-supervisor and the work-snapshot module ask whether a process exists in two different ways, on purpose** (PR [Work-snapshot tests: a claude stand-in macOS can copy and run; process_exists_or_raise](https://github.com/nedschorus/nedschorus/pull/1101)). The handoff-supervisor's `process_exists_by_signal` counts every error except "no such process" as a live process, so a lock is never taken from an owner it cannot identify; the module's `process_exists_or_raise` raises, so a failed check is reported rather than read as a dead owner whose work-snapshot is then listed or deleted. On macOS, signal 0 decides whether an owner is gone and `ps` is read only for a live process's start time, because macOS `ps` fails for a process id no process has.
- **Each launch names the agent-session with `--name` as well as `--remote-control`** (PR [handoff-supervisor: each agent-session is named after its agent-seat, locally and on Remote Control](https://github.com/nedschorus/nedschorus/pull/1118); GHI [Cross-session messages between agent-seats reach stale offline Remote Control entries instead of the live agent-session](https://github.com/nedschorus/nedschorus/issues/1115)). `--remote-control` names only the Remote Control entry; without `--name`, the name another agent-session on the same machine addresses was derived from the working directory plus a code that changes every agent-session, so a message sent to the agent-seat's name missed the live agent-session. `--remote-control-session-name-prefix` keeps the agent-seat's name on an entry that `/remote-control` re-creates with a default name.
- **The launch-time branch sync is stopped by what stops the turn-end freshness hook** (PR [A detached checkout with no work of its own is moved forward to main, at launch and at each turn's end](https://github.com/nedschorus/nedschorus/pull/1110)). An agent-seat's own checkout often sits on a detached HEAD while its work happens in other worktrees, and CLAUDE.md, the skills and the hooks load from that checkout; on 2026-10-08 the MD-skills checkout was 86 commits behind main because three untracked files had stopped the sync. The handoff-supervisor loads its tracked-change count and its in-progress check from `scripts/checkout-freshness-catch-up.py`, so the two programs refuse a move for the same reasons: an uncommitted tracked change, or a merge, rebase, cherry-pick or revert in progress, a paused multi-commit sequence included. Untracked files no longer stop the sync, because git refuses on its own to overwrite one and names it, and the "branch sync" line then reports the checkout left as is with git's error.
