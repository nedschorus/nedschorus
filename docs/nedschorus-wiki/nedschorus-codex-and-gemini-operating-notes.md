# Notes on using the Codex and Gemini (Antigravity) agents from an agent-seat

This page tells an agent-seat how to run Codex and Gemini, and what to expect from them. Facts about an installed program say which machine and date they were checked on, because the programs update often. Measurements the cold-read-research agent-seat made from 2026-09-03 to 2026-09-07 are in their own section near the end, and the campaign's data is in the record `nedlern@ned-box:/home/nedlern/nedschorus-logs/cold-read-records/2026-09-03-cold-read-tier-roster-campaign/`. Claude Code, the program the agent-seats themselves run in, is covered elsewhere; it appears here only where it was measured beside the other two or where it broke their runs.

## Run them through the project's programs

- To give Codex a task, run `scripts/run-codex-task-from-brief.py -C <checkout> --brief <file> -o <report>`. Never type `codex exec` by hand: without that program, Codex waits forever on stdin, nothing stops a run that hangs, and nothing keeps Codex out of credential files. The program's own options cover what a task needs: `--sandbox`, which takes `read-only` (the default) or `workspace-write` to let Codex edit, `-m <model>`, `--effort <effort>`, `--outside-git-checkout` for a folder that is not a git checkout, `--no-network` to keep a run off the network and without web search, which every other run has, and `--deadline-minutes` (default 60). Run it with `--help` for the rest.
- To run one reviewer on a document, use the cold-read-cell launchers: `nc-systems/cold-read/cold-read-claude-cell.py`, `nc-systems/cold-read/cold-read-codex-cell.py` and `nc-systems/cold-read/cold-read-agy-cell.py`. Each takes `--cell`, which names the reviewer prompt under `.claude/skills/cold-read/prompts/` (`defect-hunt`, `fast-clarify` or `terminology`), `--tier`, `--target` and `--report`. The Codex launcher takes `--tier deep` or `--tier second-strongest-model`; the Claude launcher takes those two and also `--tier fast`, the tier the cold-read-fast-read's backup runs when Gemini fails; the Gemini launcher takes only `--tier fast`. To use a prompt of your own, add `--prompt-file <path>`; `--cell` is then a label of your choosing, lowercase letters and digits joined by single hyphens, recorded in the report's provenance stamp.
- To give Gemini a task, run `scripts/run-gemini-task-from-brief.py -C <checkout> --brief <file> -o <report>`. It takes `--sandbox`, `-m <model>` and `--deadline-minutes` as the Codex task program does, `--effort <effort>`, and `--writable-root <folder>`, which only `--sandbox workspace-write` accepts; run it with `--help` for the rest.
- Never give `agy` a prompt outside `scripts/run-gemini-task-from-brief.py`, the Gemini cold-read launcher `nc-systems/cold-read/cold-read-agy-cell.py`, or `nc-systems/general-tools/agy-print-prompt-run-in-empty-home-sandbox.py --model <id> "<prompt>"`, which runs one prompt and prints the answer; `agy update`, `agy --version` and `agy models`, which send no prompt, you run yourself. With `--dangerously-skip-permissions`, which the first two programs pass so that `agy` can write its report, `agy` reads credential files, and its own `--sandbox` switch does not stop it; those two programs run it inside `bwrap` on Linux or `sandbox-exec` on macOS, and refuse to run without one. Without that flag, `agy` still reads files in its working directory and runs the commands its settings allow, as point 3 of "What a new runner must handle" below says; so `agy-print-prompt-run-in-empty-home-sandbox.py` runs it without the flag, in an empty working directory, inside `bwrap` with a home that holds only `~/.gemini` on Linux, and inside the launcher's `sandbox-exec` on macOS.

## What each kind of task may read, reach and write

The program that starts a run decides its access. The reviewing programs are the cold-read-cell launchers for Codex and Gemini, `scripts/code-review-codex-cell.py`, and the Codex sanity-check-cells of `scripts/sanity-check-adversarial-prompts.py`, which the /sanity-check skill runs. The task programs, `scripts/run-codex-task-from-brief.py` and `scripts/run-gemini-task-from-brief.py`, run research and trawls, and run code-writing when given `--sandbox workspace-write`. The table gives each kind of task's defaults; the bullets after it say what changes them.

| Kind of task | Reads | Network | Writes |
|---|---|---|---|
| Reviewing a document or a pull request | everything but credential files, as the first bullet below defines them | the web, web search, and GitHub through a token that can only read | its report. A Codex cold-read-cell and a Codex sanity-check-cell can also write in the checkout they review, and the Gemini cold-read-cell anywhere outside credential files, because it runs agy with the whole file system writable but for them. |
| Research and trawls | the same | the same | its report and, on ned-box, its folder in the shared writable folder, which the bullets below describe |
| Writing code | the same | the same | its topic-worktree, its report, each `--writable-root` folder, and, on ned-box, its folder in the shared writable folder. It never pushes. |

- Credential files are the folders `~/.ssh`, `~/.config/gh` and `~/.config/nedschorus`; Claude's and Codex's login files, `~/.claude/.credentials.json` and `~/.codex/auth.json`, and agy's login files to every program but agy, which needs its own; and files named `*.token` or `.env`. On macOS the sandbox denies a file of those names wherever it is. On Linux it denies only those that exist in the home or the checkout when the run starts, so a file of those names made later, or kept elsewhere, is readable.
- Codex and Gemini runs reach the network and may search the web. Give `scripts/run-codex-task-from-brief.py` the option `--no-network` for a run that must do neither; its `--prefetch-github` commands still reach GitHub, because they run outside the sandbox before Codex starts. `scripts/run-gemini-task-from-brief.py` has no such option: the Codex CLI talks to its model outside the sandbox, but agy runs whole inside it, and no proxy separates agy's model traffic from its tools' traffic.
- None of the reviewing or task programs gives Codex or Gemini the agent-seat's GitHub token, which can push and merge. Each puts in its place, as `GH_TOKEN`, a token that can only read public repositories, kept at `~/.config/nedschorus-sandboxed-models/github-public-repositories-read-only-token`, so that `gh` works inside the sandbox. When that file is missing, empty or unreadable, the run goes ahead without a token: `git fetch` over https still works, `gh` does not, and the run log, or the cell's stderr, says so. A token GitHub refuses, such as an expired one, is not caught before the run: `gh` fails inside it with HTTP 401. The token expires on 2027-10-22.
- On ned-box, a run of either task program may write in `/home/nedlern/nedschorus-logs/codex-and-gemini-sandboxed-task-runs-shared-writable-folder/<agent-seat>/<brief file name without its extension>/`, the shared writable folder, which the program creates and names at the end of the brief. `<agent-seat>` is the agent-seat's name, read from `CLAUDE_CODE_TASK_LIST_ID`, or `no-agent-seat-name` when that variable does not hold one. A brief file named `loose-ends-trawl-2026-10-22.md`, run by prime-intellect, writes in `prime-intellect/loose-ends-trawl-2026-10-22/`. A second run of the same brief file by the same agent-seat gets the same folder, with the first run's files still in it; to keep the runs apart, give each its own brief file name.
- On Linux, Codex's profile keeps `/tmp` itself read-only: a Codex sandbox with `/tmp` writable creates `/tmp/.git`, `/tmp/.codex` and `/tmp/.agents`. A folder under `/tmp` given to Codex as a writable folder, such as the cold-read Codex cell's report staging folder, stays writable.
- Codex and Gemini write code only in a topic-worktree the dispatching agent-seat made, given as `-C` with `--sandbox workspace-write`, and run the nc-test-suites there. They do not commit: the worktree's git folder is not among the folders they may write. The agent-seat reviews their change, commits it, pushes it and opens the pull request. A run that fails or passes its deadline leaves its changes in the worktree, for the agent-seat to keep or discard.

## Codex (`codex`, OpenAI)

**Install and update.** Codex is installed through npm, not Homebrew: on ned-box `/usr/local/bin/codex` is a symlink into `/usr/local/lib/node_modules/@openai/codex`, and on the Mac `/opt/homebrew/bin/codex` is a symlink into npm's `node_modules/@openai/codex`, so `brew upgrade codex` fails. Update with `codex update`, which runs `npm install -g @openai/codex`, and check with `codex --version` (codex-cli 0.159.3 on ned-box on 2026-10-17). Every agent-seat on a machine shares the one binary, so before you update, check with `pgrep -af codex` that no Codex run is in progress; if one is, wait for it to finish. Running Codex tasks side by side is fine; only the update must wait.

**Model ids.** The CLI has no command that lists models. It caches the list it knows in `~/.codex/models_cache.json`, refreshed on each run; the ids are the `slug` fields. A model appears there only once the CLI is new enough for it: the Codex launcher's `gpt-6.1-sol` needs codex-cli 0.159.1 or later. A model id the CLI does not know makes the run hang instead of failing (measured: eight minutes with no output, then killed), so take the id from the cache; `scripts/run-codex-task-from-brief.py` stops such a run at its deadline. The model cannot tell you its own id.

**Effort.** Effort is set per run, with `--effort`, not in the model id.

**At capacity.** When a run on `gpt-6-astra` prints "Selected model is at capacity. Please try a different model.", which means OpenAI has no room on that model at that moment rather than that the user's plan is used up, run the task again with `-m gpt-6.1-sol --effort xhigh`.

**Project rules.** Codex reads the repository's `AGENTS.md`, which tells it to read `CLAUDE.md` and follow it. Measured with a canary on 2026-08-22 and 2026-09-04: Codex reads `CLAUDE.md` when it may read files.

## Gemini via Antigravity (`agy`, Google)

**What it is.** Gemini runs through the Antigravity CLI, `agy`, the agent behind the Antigravity IDE; there is no `gemini` command. On ned-box `agy` is `~/.local/bin/agy` and its configuration is under `~/.gemini/antigravity-cli/` (version 1.4.0 on 2026-10-17). `agy update` updates it and `agy --version` reports it.

**Model ids carry the effort.** `agy models` lists them: `gemini-3.8-flash-high`, `gemini-3.8-flash-medium`, `gemini-3.8-flash-low`, `gemini-4-argon-high`, `gemini-4-argon-medium` and `gemini-4-argon-low` (ned-box, 2026-10-17). The cold-read-fast-read runs on `gemini-3.8-flash-medium`, and on `claude-sonnet-5-5` at low effort when Gemini fails.

**What a new runner must handle.** The Gemini cold-read launcher, `nc-systems/cold-read/cold-read-agy-cell.py`, handles all of these, and `scripts/run-gemini-task-from-brief.py` all but point 4; they matter only to someone changing either or writing a new one.

1. The prompt is the value of `--print`. In `agy --print --model X "prompt"`, agy takes `--model` as the prompt and ignores yours. Put every other option first and `--print` last, with the prompt as its value.
2. Pass the repository with `--add-dir <repo>`, or nothing from the repository loads, `AGENTS.md` included.
3. Without `--dangerously-skip-permissions`, a headless run still reads files in its working directory, and runs the commands an allow-rule under `permissions.allow` in `~/.gemini/antigravity-cli/settings.json` permits: under the rule `command(agy)` it ran `agy --version` and `agy --help`. It was denied every other file read, in the home and in `/etc` included, and every other command it tried; a denied run ends with "no output produced — a tool required the X permission that headless mode cannot prompt for" (agy 1.4.12 on ned-box, 2026-10-31). The launcher passes the flag so that agy can write its report, and that flag is why the launcher runs agy inside the operating system's sandbox.
4. Gemini sometimes writes the whole review as its answer instead of into the report file. The Gemini cold-read launcher then takes the answer as the report when it is at least 120 words; a shorter answer with no report file counts as a failed run.
5. `--print-timeout` defaults to `0s`, no limit, and agy does not always stop at it. The Gemini cold-read launcher sets `30m` and kills agy's process group 60 seconds after that; `scripts/run-gemini-task-from-brief.py` sets it to its own deadline and kills the process group at that deadline.

**Its own documentation.** On ned-box, agy's customization guide is `~/.gemini/antigravity-cli/builtin/skills/agy-customizations/SKILL.md`, with the rule-loading details in `~/.gemini/antigravity-cli/builtin/skills/agy-customizations/docs/rules.md`. Read it before asking agy about itself: asked about itself, agy may spend its whole run on experiments and time out.

## Measured from 2026-09-03 to 2026-09-07

These are the cold-read-research agent-seat's results, on the models and CLI versions of those days; the campaign record above holds the data for all but the result of 2026-09-07.

- A Codex run at `max` effort on a document of 1,500 to 2,300 words took 13 to 32 minutes (`gpt-6-astra` and `gpt-5.6-sol`).
- Codex hit no account limit in the campaign; Claude hit its limit three times in one day.
- `gemini-3.8-flash-low` read a 700 to 1,500-word skill in 21 to 31 seconds, found as many of the known defects as `gpt-5.6-terra` at low effort in a quarter of the time, and found no defect that no other reviewer found. Measured on 2026-09-07, as `nc-systems/cold-read/cold-read-agy-cell.py` records: on one defect list, `gemini-3.8-flash-medium` found 42% and low 19%, which is why the cold-read-fast-read runs on medium.

## Things that went wrong once and will again

- In a scratch directory several agents shared, one agent ran another's script because both used a generic name, `build_clusters.py`. Put the name of the document you are working on and your agent-seat's name in a scratch file's name.
- Give a shared file one writer. Each run writes its own record file, and one program builds any summary from the records; for a log, use one writer process that the others send to, as Python's `logging` documents.
- `/login` in an agent-seat's terminal kills that agent-seat's running subagents and its background `claude -p` runs with an authentication error. A Claude login once expired overnight and left a run hanging for six hours. Give a long batch of runs a deadline per run, and make it able to start again without redoing the runs whose reports are complete.
