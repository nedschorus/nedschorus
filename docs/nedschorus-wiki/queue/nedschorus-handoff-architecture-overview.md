# The handoff-system: nc-architecture-overview

This document has proposed improvements or changes: read every file in this folder whose name starts with `nedschorus-handoff-architecture-overview-proposed-improvements-or-changes-`.

## Purpose

The handoff-system keeps an agent-seat working across many agent-sessions. When an agent-session's context window runs low, it has the agent write a session-handoff and carries out a reincarnate-seat: it replaces the agent-session with a fresh one that continues from the session-handoff and the conversation-tail. When an agent-session or its machine dies, it can bring the agent-seat back, resuming the dead agent-session where it can. It takes an agent-seat's name, the next step the outgoing agent writes and whether the user is to be asked before a relaunch, Claude Code's transcripts, and the token of the GitHub account the agent-seat acts as; it produces a supervised agent-session in the agent-seat's tmux pane, whose initial-agent-instructions say where to pick up.

## Architectural pattern

A supervisor and the process it launches: on each machine, one handoff-supervisor per agent-seat runs in the agent-seat's tmux pane, started by the pane's shell, launches `claude` as its child process, waits for a session-handoff or the child's exit, and, by the rules Components gives, starts the next agent-session, fresh or resumed from the transcript. At each session-handoff that launches a successor without consulting the user, it first restarts itself on main's code. Hooks inside the agent-session ask for the session-handoff and keep work-snapshots, and reach the handoff-supervisor only through files on the machine. The launchers, `launch-claude-mac` and `launch-claude-ubuntu`, start the handoff-supervisor; `recover-crashed-seats.py` and `resupervise-seat.py` start it again when it is gone, and on ned-box the agent-crash-watcher runs `recover-crashed-seats.py` when an agent-session died without a session-handoff. The user-rulings behind the system, and their reasons, are in `nc-systems/handoff/handoff-design.md`; the code is what the system does.

```
person on the Mac ──> launch-claude-mac / launch-claude-ubuntu ──> tmux pane ──> handoff-supervisor.py
login on the Mac, boot on ned-box ──> restart-live-seats-at-login.py ──> recover-crashed-seats.py ──> launcher or tmux pane
agent-crash-watcher (ned-box, every minute) ──> recover-crashed-seats.py ──> launcher or tmux pane
handoff-supervisor.py ──launches, kills, resumes──> claude (agent-session)
threshold hook ──asks──> agent ──/handoff──> handoff-write-and-check-supervisor.py ──> <seat>-handoff.md
handoff-supervisor.py ──at a session-handoff: kills claude, removes finished worktrees, restarts itself on main's code──> handoff-supervisor.py
handoff-supervisor.py ──runs handoff-extract-conversation.py, launches──> successor
```

## Components

**`nc-systems/handoff/handoff-supervisor.py`**, the handoff-supervisor. At startup it sets `GH_TOKEN` to the token of the GitHub account the agent-seat acts as, and refuses to start without it. It holds the agent-seat's lock for its whole life, taking it again after its restart on main's code, heartbeats into its state file, and launches `claude` named after the agent-seat, both in the pane and on Claude Code's Remote Control, where agents on the other machine address the agent-seat by that name. Before each launch it tries to update `claude` and runs the launch-time-git-sync on the agent-home, and launches the agent-session whatever the launch-time-git-sync's result. At a session-handoff that does not ask for the user to be consulted, a handoff-supervisor with no terminal to seat the successor on leaves the agent-session running and the session-handoff unconsumed for a handoff-supervisor that has one, and exits. Otherwise it ends the agent-session. When the session-handoff asks for the user to be consulted, it asks him on its terminal, or, with no terminal, takes the answer as no; on no, it records the exit and exits, and on yes, it launches the successor without restarting itself on main's code. It removes the agent-home's worktrees that `scripts/clean-worktrees.py` judges finished. Then, unless the user was consulted, it restarts itself on main's code: it fast-forwards the checkout it runs from to main and replaces its own process with a fresh start of the program from that checkout, keeping its process ID, which its lock file names, and leaving the session-handoff unconsumed, so that the fresh process carries out the rest of the session-handoff at its startup. When that checkout cannot be brought to main's commit, or the replacement of its process fails, it carries on with its old code, and the successor's initial-agent-instructions say why; `docs/nedschorus-wiki/nedschorus-handoff-supervisor-restart-onto-main-code-by-hand-procedure.md` says how to restart such a handoff-supervisor by hand. The process that launches the successor runs the extractor (`handoff-extract-conversation.py`) as a separate program, then launches the successor with initial-agent-instructions naming the conversation-tail, the next step, the launch-time-git-sync's result, the spawned-subagent-roster, and, on the Mac from noon Pacific when one is due, as the readers in `handoff-user-review-of-agent-memory-stores-mark.py` decide, the day's memory review, an approval-walk on the notes agents saved in Claude Code's memory. If the extraction fails, the successor's initial-agent-instructions start with the next step and a note that there is no conversation-tail and where the outgoing agent-session's transcript is, or that it was not found. For the agent-seat agent-instructions-editor alone, the initial-agent-instructions also carry an overview refresh reminder for each system whose non-Markdown code under `nc-systems/<system>/` has moved past the commit its nc-architecture-overview's last line names, unless an open pull request already changes that nc-architecture-overview or the user was shown its refresh that day. Every launch also lists the agent-seat's lost work-snapshots: work-snapshots, still kept, whose `claude` process has ended and whose worktree no longer holds their changes. When the agent-session dies without a session-handoff, it resumes that agent-session after a signal or an error exit when it has a terminal, resumes it again only if the resumed agent-session did substantive work, and otherwise records the exit and exits. At its first launch, with a session-handoff waiting, it consults the user if the session-handoff asks for that, then runs the extractor and launches the successor; with no session-handoff waiting and no recorded exit, it resumes the agent-seat's last transcript worth resuming, as `scripts/agent-seat-transcript-worth-resuming-common.py` defines it, or else starts fresh; with a recorded exit, it starts fresh. It resumes a transcript its caller names, and starts fresh from the initial-agent-instructions it is given when its caller says those win over a transcript worth resuming.

**`nc-systems/handoff/handoff-write-and-check-supervisor.py`**, the writer script. Apart from the next step and whether the user is to be asked before a relaunch, the writer computes every field of the session-handoff, and writes `<seat>-handoff.md` under the name the handoff-supervisor watches. It refuses a name whose session-handoff was written from a working directory other than the agent's, since writing would destroy a session-handoff that agent-seat may not have read, and a name no handoff-supervisor has watched when another name is already supervised for the agent's working directory; the agent can tell it to take the name over, which waives both refusals. It prints the main-gatekeeper's audit of branch protection, which never stops the session-handoff being written, and reports whether a handoff-supervisor is watching. Before it writes the session-handoff, the writer removes from the agent-seat's task list each completed task whose copy in the log-store has the same bytes as the task's file, unless the task is linked to an open task in either direction or the next step names its id or subject; a failure of that prune prints one line and never stops the session-handoff being written, and a prune that fails before it removes anything keeps every completed task.

**`nc-systems/handoff/handoff-agent-seat-died-without-session-handoff-restart-watcher.py`**, the agent-crash-watcher. On ned-box, every minute, it finds each agent-seat it has seen running since the machine booted whose agent-session has since crashed, as `recover-crashed-seats.py`'s own assessment judges, and restarts it by running `recover-crashed-seats.py`, at most once an hour per agent-seat. It never restarts an agent-seat whose session-handoff waits or whose exit the handoff-supervisor recorded. When it leaves such an agent-seat down, other than after an exit the handoff-supervisor recorded as on purpose, or a restart fails, it shows the user a failed-restart-notice on the Mac.

- `scripts/launch-claude-mac`: run on the Mac, creates a Mac agent-seat's agent-home and seat-branch when missing, updates `claude`, fast-forwards the launcher's own checkout to main, and starts the agent-seat on its own tmux server, whose pane's shell sets the agent-seat's task list and git identity and runs the handoff-supervisor from the launcher's own checkout; or attaches to the agent-seat's tmux session.
- `scripts/launch-claude-ubuntu`: run on the Mac, does the same for a ned-box agent-seat over ssh, fast-forwarding ned-box's reference-checkout, `~/Projects/nedschorus`, and running the handoff-supervisor from it.
- `scripts/handoff-context-threshold-hook.py`, the threshold hook, a `Stop` hook: at a set share of the context window, or when the context used plus the tokens the agent-session's compactions dropped reaches a second, higher share, tells the agent to run the /handoff skill, once until the next compaction, with a handoff-deferral while a subagent or a recent background Bash task still runs, until the context used reaches the ceiling, a third, higher share.
- `.claude/skills/handoff/SKILL.md`: the /handoff skill; the agent writes the next step to a file and runs the writer script on it.
- `docs/agents/seat-session-appended-system-prompt.md`: below its `---` line, the text the handoff-supervisor appends to every agent-session's system prompt.
- `scripts/post-compaction-session-continues-hook.py`, the post-compaction hook, a `SessionStart` hook: after a compaction, gives the agent-session the tail of its own dialog and tells it to continue, and deletes the threshold hook's `<session>-handoff-asked` file so that hook can ask again.
- `scripts/uncommitted-work-snapshot-hook.py`, a `PostToolUse` hook: after each Edit, Write, NotebookEdit and Bash call, keeps a work-snapshot, owned by the calling `claude` process, of the worktree the call worked in and, after a Bash call, of any worktree that process already has one of, and deletes it once nothing there is uncommitted; it never changes a worktree.
- `nc-systems/handoff/uncommitted-work-snapshots.py`: the work-snapshot module that hook, the handoff-supervisor and `scripts/clean-worktrees.py` share; design in `nc-systems/handoff/handoff-uncommitted-work-snapshots-across-crashes-design.md`.
- `nc-systems/handoff/uncommitted-work-snapshot-hook-real-claude-session-weekly-owner-check.py`, the weekly owner check: once a week on each machine, runs the work-snapshot hook under a real `claude` in a scratch clone and records in the log-store whether the work-snapshot names that `claude` process as its owner.
- `scripts/handoff-extract-conversation.py`, the extractor: writes the conversation-tail from the outgoing agent-session's transcript, and, when the conversation-tail leaves turns out or the agent-session dispatched a subagent whose turns the tracker found, the complete dialog beside it, which alone carries what each subagent was asked and reported.
- `scripts/handoff-extract-conversation-subagent-tracker-nbd.py`: nice-but-dirty code the extractor loads to find each subagent's task and report; when it fails, the complete dialog leaves those turns out with a note, and the session-handoff goes ahead.
- `scripts/agent-seat-transcript-worth-resuming-common.py`: the one definition, for the handoff-supervisor, `recover-crashed-seats.py` and the records reader, of a transcript worth resuming, and of the substantive work the handoff-supervisor's resume rule counts.
- `scripts/agent-binary-update-under-lock.py`: updates `claude` for a launcher or the handoff-supervisor, skipping the update when another holds `agent-binary-update.lock`.
- `scripts/checkout-freshness-catch-up.py`, a hook outside this system: both launchers run it to fast-forward the checkout they run the handoff-supervisor from, and the launch-time-git-sync uses its checks for uncommitted tracked changes and a git operation in progress.
- `scripts/architecture-overview-path-template-and-checked-against-commit-reader-common.py`: gives an nc-architecture-overview's path and reads the commit its last line names, for the handoff-supervisor's overview refresh reminder.
- `nc-systems/handoff/handoff-user-review-of-agent-memory-stores-mark.py`: marks the day's memory review started or done, and holds the readers the handoff-supervisor's memory review uses.
- `nc-systems/handoff/handoff-architecture-overview-refresh-user-shown-mark.py`: marks that the user was shown a system's overview refresh, so the handoff-supervisor withholds that system's overview refresh reminder for the rest of the Pacific day.
- `scripts/clean-worktrees.py`: removes each worktree under `.claude/worktrees/` whose branch has nothing main lacks, that no process uses and that nothing has written to in the last hour, discarding its uncommitted files with it after copying its review records to the log-store; deletes merged branches; and deletes each lost work-snapshot some days after it was first listed.
- `scripts/resupervise-seat.py`: puts an agent-seat running without a handoff-supervisor back under one from a waiting session-handoff, killing the unsupervised agent-session's tmux session.
- `scripts/recover-crashed-seats.py`: brings back an agent-seat whose handoff-supervisor is gone, resuming its last transcript worth resuming, or, when there is none, starting fresh, from its newest conversation-tail when it has one, or, when a session-handoff waits, leaving it to a new handoff-supervisor, unless that session-handoff asks for the user to be consulted, when it leaves the agent-seat down. It reports an agent-seat whose handoff-supervisor runs as already running, refuses while another process works in the agent-seat's agent-home, closes a leftover idle shell only when the person running it says yes, and restarts an agent-seat whose exit was recorded only when the person running it says yes, so an invocation without a terminal leaves such an agent-seat down. On ned-box it then asks the Mac to open a window onto each agent-seat it brought up.
- `scripts/restart-live-seats-at-login.py`, the login restart: hands `recover-crashed-seats.py` each agent-seat that was running when the machine last shut down, judged by how close its last heartbeat is to the newest heartbeat from before the boot; on the Mac it also opens a window running `launch-claude-ubuntu` onto each running ned-box agent-seat that has no window attached.
- `scripts/install-restart-live-seats-at-login-launch-agent.py` and `scripts/install-restart-live-seats-at-login-systemd-unit.py`, the install scripts: install what runs the login restart on the Mac and on ned-box.
- `nc-systems/handoff/agent-seat-state-records-reader.py`, the records reader: the rules for reading an agent-seat's records from its files, for the login restart, `recover-crashed-seats.py`, and through it the agent-crash-watcher, and `scripts/seat-task-list-read-nbd.py`; it re-exports the handoff-supervisor's readers, which own the file names.
- `nc-systems/handoff/handoff-agent-seat-remote-control-lost-at-claude-login-reconnect-by-tmux-typing-watcher.py`, the Remote Control reconnect watcher: on ned-box, every minute, turns Remote Control back on in each running agent-seat after a `claude` login turned it off, by typing the command into the agent-seat's tmux pane.

## Invariants

- No program but the handoff-supervisor starts or resumes an agent-seat's agent-session, apart from `scripts/ghi-guide-agent-ask.py`, which starts and resumes the ghi-guide-agent's agent-sessions itself: the launchers, `recover-crashed-seats.py` and `resupervise-seat.py` start a handoff-supervisor, the agent-crash-watcher runs `recover-crashed-seats.py`, and the writer script starts nothing, because an agent cannot end its own agent-session, so the program that starts a successor must be the one that ends the agent-session. A `claude` a person starts by hand runs unsupervised; once it writes a session-handoff, `resupervise-seat.py` can end it and start a supervised successor.
- When a session-handoff arrives during an agent-session, or the agent-session dies, a handoff-supervisor starts the next agent-session only when it has a terminal, since the child inherits its stdio; that is why it runs inside the tmux pane.
- At each session-handoff that launches a successor without consulting the user, the handoff-supervisor restarts itself on main's code before it extracts the conversation-tail, so a change merged to the handoff-supervisor reaches every agent-seat whose handoff-supervisor started from code that has this restart, at its next session-handoff that does not consult the user; a running handoff-supervisor never reads its own code again otherwise. The extractor runs as a separate program, so a change to what it writes needs no restart.
- At most one handoff-supervisor per agent-seat name runs on a machine, because each holds that name's lock in `~/.claude/handoffs/`; nothing stops the name running on the other machine too, although both then register the same Remote Control name.
- A handoff-supervisor is alive when the process its lock file names runs `handoff-supervisor.py` for that agent-seat; the heartbeat never decides liveness, only which agent-seats the login restart brings back and whether the agent-crash-watcher counts a death as already handled.
- Every path that starts a handoff-supervisor sets `CLAUDE_CODE_TASK_LIST_ID`, and the handoff-supervisor refuses to start without it, so every agent-session a handoff-supervisor starts for an agent-seat on one machine opens the same task list.
- Every agent-session a handoff-supervisor starts acts on GitHub as the agent-seat's account, because the handoff-supervisor, which every start path runs, sets the token and refuses to start without it; the launchers set no GitHub account.
- Apart from the next step and the question whether to ask before a relaunch, the writer script computes the session-handoff, and the extractor cuts the conversation-tail by a minimum word count, so the outgoing agent's judgment shapes neither the other fields nor the conversation-tail.
- A handoff-supervisor that outlives its agent-session records the exit before it exits, so `recover-crashed-seats.py` and the agent-crash-watcher can tell an agent-seat its handoff-supervisor left down from one that crashed. A handoff-supervisor restarted on main's code that cannot start, for want of the token or its lock, or one that fails with an error it does not handle, exits without a record, leaving any session-handoff waiting.
- Session-handoffs and work-snapshots stay off every branch; both machines' session-handoffs, transcripts and task lists are also copied to the log-store every minute by `scripts/transcript-mirror-to-log-store.py`.
- The handoff-supervisor of a ned-box agent-seat, and of any agent-seat `recover-crashed-seats.py` brings back, runs from the reference-checkout, unless a person running `recover-crashed-seats.py` names another checkout, because it runs the extractor from its own checkout and a linked worktree can be removed under it; a Mac agent-seat that `launch-claude-mac` starts runs its handoff-supervisor from whichever checkout that launcher was run from.

## Shared state

Unless named otherwise, files are in `~/.claude/handoffs/` on the agent-seat's machine.

- `<seat>-handoff.md`, the session-handoff: written by the writer script; read by the writer script, `handoff-supervisor.py` and `resupervise-seat.py` directly, and by `recover-crashed-seats.py` and the agent-crash-watcher through the records reader. A session-handoff is waiting while it has a restart counter above the one the state file records as consumed, or the state file records none.
- `<working directory name>-next-step-<time>.md`: written by the agent under the /handoff skill; read by the writer script.
- `<seat>-handoff-NNNN.md`: copies of consumed session-handoffs, kept by `handoff-supervisor.py`, which keeps the two newest generations of these and of the dialog files.
- `<seat>-supervisor.lock`: held with flock by `handoff-supervisor.py`, which writes its process ID there; read for liveness by the writer script, `resupervise-seat.py` and `recover-crashed-seats.py`.
- `<seat>-supervisor-state.json`, holding the heartbeat, the exit record and the consumed restart counter: written only by `handoff-supervisor.py`; read by the writer script, `resupervise-seat.py`, `recover-crashed-seats.py`, `restart-live-seats-at-login.py` and the agent-crash-watcher.
- `<seat>-dialog-NNNN.md`, the conversation-tail, and `<seat>-dialog-NNNN-complete.md`, the complete dialog: written by `handoff-extract-conversation.py`; read by the successor, and by `recover-crashed-seats.py` when no transcript is worth resuming.
- The prompt files `recover-crashed-seats.py` writes, such as `<seat>-recovery-ignition-prompt.md`: read by the handoff-supervisor it starts, as that agent-session's initial-agent-instructions.
- `<seat>-appended-system-prompt-agent-part.md`: written by `handoff-supervisor.py` before each launch from `docs/agents/seat-session-appended-system-prompt.md`; read by `claude`.
- `<session>-handoff-asked` and `<session>-handoff-deferred`, keyed by Claude Code session ID: written by `handoff-context-threshold-hook.py`; the first is deleted by `post-compaction-session-continues-hook.py`.
- `<seat>-work-snapshots-first-listed.json`, recording when each lost work-snapshot was first listed: written through `uncommitted-work-snapshots.py` when the handoff-supervisor lists one; read through the same module by `clean-worktrees.py`, which deletes a lost work-snapshot some days after its first listing.
- `refs/work-snapshots/` in the machine's clone: written by `uncommitted-work-snapshot-hook.py`, listed by `handoff-supervisor.py`, deleted by that hook or by `clean-worktrees.py` through `uncommitted-work-snapshots.py`, or by the agent following the restore steps it is given.
- Transcripts under `~/.claude/projects/`: written by Claude Code; read by the extractor, the threshold hook, the post-compaction hook, the writer script, `agent-seat-transcript-worth-resuming-common.py`, the agent-crash-watcher and the Remote Control reconnect watcher.
- The agent-seat's task list under `~/.claude/tasks/`: written by Claude Code; completed tasks removed by the writer script, which compares each with its copy in the log-store, `agent-session-files-by-machine/<machine>/tasks/` on ned-box, written by `transcript-mirror-to-log-store.py`.
- The reference-checkout, `~/Projects/nedschorus`: fast-forwarded to main by `launch-claude-ubuntu`, by `launch-claude-mac` when run from it, and, at each session-handoff that launches a successor without consulting the user, by every handoff-supervisor that runs from it.
- `daily-memory-review-marks/` and `daily-overview-refresh-reminder-marks/` in the log-store on ned-box: written by `handoff-user-review-of-agent-memory-stores-mark.py` and `handoff-architecture-overview-refresh-user-shown-mark.py`, locally on ned-box and over ssh from the Mac, the memory review's done mark only from the Mac, since it records both machines' memory stores; read by `handoff-supervisor.py`, the memory review marks only on the Mac, and the overview refresh reminder marks only for the agent-seat agent-instructions-editor, on either machine.
- `handoff-agent-seat-died-without-session-handoff-restart-watcher/` in the log-store on ned-box: the agent-crash-watcher's decisions and failed-restart-notices, written by the agent-crash-watcher alone; its own state and lock are under `~/.local/state/nedschorus/` on ned-box.
- `agent-binary-update.lock` under `~/.local/state/claude/`: taken through `agent-binary-update-under-lock.py` by the launchers and the handoff-supervisor.
- `~/.config/nedschorus/<account>.token`, the token of the GitHub account an agent-seat acts as, on the agent-seat's machine: written by the user; read by `handoff-supervisor.py` at every start, and by `recover-crashed-seats.py` before it launches an agent-seat.
- `GH_TOKEN`: set by `handoff-supervisor.py` from that token file for every agent-session it starts, replacing any value it inherited.
- `CLAUDE_CODE_TASK_LIST_ID` and `GIT_AUTHOR_NAME`: set by `launch-claude-mac`, `launch-claude-ubuntu`, and `recover-crashed-seats.py` when it starts a ned-box handoff-supervisor itself; the first is required by `handoff-supervisor.py` and names the task list the writer script prunes, the second names the agent-seat in `uncommitted-work-snapshots.py`.
- `NEDSCHORUS_HANDOFF_SUPERVISOR_AGENT_NAME`, `NEDSCHORUS_HANDOFF_SUPERVISOR_WORKING_DIRECTORY` and `NEDSCHORUS_HANDOFF_SUPERVISOR_SESSION_ID`: set by `handoff-supervisor.py` for its agent-session; read by `handoff-write-and-check-supervisor.py`.
- `LAUNCH_CLAUDE_SUPERVISOR_EXTRA_ARGUMENTS`: set by `recover-crashed-seats.py` and `resupervise-seat.py`; passed on to the handoff-supervisor by `launch-claude-mac` and `launch-claude-ubuntu`.
- `NEDSCHORUS_SESSION_REINCARNATION_OWNED_BY_CALLER`: set by `scripts/ghi-guide-agent-ask.py` for the `claude` it starts; silences `handoff-context-threshold-hook.py`; the handoff-supervisor removes it from the environment of every agent-session it starts.

## Entry points

- The launchers: a person on the Mac; also `resupervise-seat.py`, `recover-crashed-seats.py` on the Mac, and, for `launch-claude-ubuntu`, the login restart on the Mac and a request from `recover-crashed-seats.py` on ned-box to open a window on the Mac.
- `handoff-supervisor.py`: a launcher, inside the tmux pane; on ned-box, also `recover-crashed-seats.py` directly; and the handoff-supervisor itself, when it restarts on main's code at a session-handoff.
- The threshold hook, the post-compaction hook and `uncommitted-work-snapshot-hook.py`: the Claude Code `Stop`, `SessionStart` (after a compaction) and `PostToolUse` events.
- The /handoff skill and the writer script: the agent, when the threshold hook asks or the user requests a session-handoff.
- `handoff-user-review-of-agent-memory-stores-mark.py` and `handoff-architecture-overview-refresh-user-shown-mark.py`: an agent-session, as its initial-agent-instructions say.
- `restart-live-seats-at-login.py`: a LaunchAgent at login on the Mac and a systemd user unit at boot on ned-box.
- `recover-crashed-seats.py`: a person, `restart-live-seats-at-login.py`, or, on ned-box, the agent-crash-watcher.
- The agent-crash-watcher and the Remote Control reconnect watcher: their jobs in `nc-systems/general-tools/scheduled-jobs-on-each-machine.json`, every minute on ned-box.
- The weekly owner check: its job in the same file, weekly on both machines.
- `clean-worktrees.py`: the `clean-worktrees` job in the same file and the handoff-supervisor at each session-handoff that launches a successor; the launchers run it only to report.
- `resupervise-seat.py` and the install scripts: a person. The `list` command of `uncommitted-work-snapshots.py`: a person, or an agent its initial-agent-instructions send there.
