# Restarting an agent-seat's handoff-supervisor onto main's code by hand

A running handoff-supervisor keeps the code it started with, because Python reads a program once, when the process starts. At each session-handoff the handoff-supervisor restarts itself on main's code, as the handoff-system's nc-architecture-overview, `docs/nedschorus-wiki/nedschorus-handoff-architecture-overview.md`, says, and then the next session-handoff is enough. These steps are for a handoff-supervisor that does not restart itself: one whose code predates that restart; one that runs from a checkout other than the reference-checkout `~/Projects/nedschorus`, such as a Mac agent-seat launched from its agent-home; or one whose restart failed for a reason other than its checkout. The steps end the old handoff-supervisor and start a new one from the reference-checkout, which starts the successor from the agent-seat's waiting session-handoff. GHI [The handoff-supervisor restarts itself on main's current code at each handoff](https://github.com/nedschorus/nedschorus/issues/2036) plans the program that replaces this page.

When the successor's initial-agent-instructions say the handoff-supervisor did not restart because the reference-checkout cannot be fast-forwarded to main, do not use these steps, since step 0 fails the same way: tell the user, and once that checkout is fixed the next session-handoff restarts the handoff-supervisor.

## Rules

- The user starts this procedure, by asking the agent-seat being restarted for it. The operator is the agent that runs steps 0 and 2 to 7. On ned-box, the operator is another agent-seat, which the user names. On the Mac, the operator is a helper agent-seat, not a subagent, which the agent-seat being restarted launches before step 0, as "On the Mac: the helper agent-seat" says.
- The operator is never the agent-seat being restarted, because ending that agent-seat's agent-session in step 4 would stop the procedure halfway.
- In steps 1 to 3, the operator and the agent-seat being restarted tell each other with SendMessage, addressed by the agent-seat's name, when each step is done; from step 4 until the successor starts, the agent-seat being restarted has no agent-session to answer.
- The operator ends a process only by its process ID, never with `pkill`, `killall` or a `pgrep` pattern, because every agent-seat on a machine runs as the same Unix user and a pattern reaches the others too. It ends a process with `kill -TERM`, and, if the process still runs 20 seconds later, with `kill -KILL`, as the handoff-supervisor ends an agent-session. When the Bash sandbox blocks a signal on ned-box, the operator runs the same command through `ssh nedlern@ned-box '<command>'`.
- Below, `<seat>` is the name of the agent-seat being restarted.
- When a command fails, the operator does what "Getting an agent-seat back after a failure" says for the state the agent-seat is in, and goes no further.
- The operator tells the result, success or failure, to the restarted agent-seat's successor, which tells the user; when no successor answers, the operator tells the user itself.

## The steps, on either machine

0. The operator runs `git -C ~/Projects/nedschorus fetch origin` and `git -C ~/Projects/nedschorus merge --ff-only origin/main`, because the new handoff-supervisor runs from that checkout. Then it checks that `git -C ~/Projects/nedschorus rev-parse HEAD` prints the same commit as `git -C ~/Projects/nedschorus rev-parse origin/main`, and that `git -C ~/Projects/nedschorus status --porcelain --untracked-files=no` prints nothing.
1. The agent-seat being restarted gets ready: no subagent and no test run of its own still running, its work committed, and its walk-minutes written. On the Mac, its next step for the session-handoff also tells its successor to remove the helper agent-seat once the helper agent-seat reports step 7, as step 3 of "On the Mac: the helper agent-seat" says. It tells the operator it is ready, and waits.
2. The operator reads the handoff-supervisor's process ID from `~/.claude/handoffs/<seat>-supervisor.lock`, and checks with `ps -ww -o args= -p <process ID>` that the command runs `handoff-supervisor.py --agent <seat>` followed by a space or the end of the line, so that a longer name such as `<seat>-restart-helper` does not pass. In `ps -ww -eo pid,ppid,lstart,args` it notes the process ID of the `claude` process whose parent is that process ID, and the Claude Code session ID that follows that process's `--session-id` or `--resume`. It lists the processes working in the agent-seat's agent-home with `lsof -a -d cwd +D ~/agents/<seat>`, and keeps the list for step 5. It then freezes the handoff-supervisor, so that it cannot consume the session-handoff and start the successor on its old code, and tells the agent-seat to write its session-handoff. How it freezes the handoff-supervisor depends on that process's parent:
   - **Under a shell, such as `sh`, `bash` or `zsh`**, as the launchers start it: `kill -STOP <process ID>`; on ned-box, then check that `/proc/<process ID>/status` says `T (stopped)`, and on the Mac that `ps -o stat= -p <process ID>` starts with `T`.
   - **Under its tmux server**, as a pane started before its launcher ended the pane's command with `; exit $?` may be: tmux would continue the process at once after `kill -STOP`, so the handoff-supervisor cannot be frozen. The operator stops here and tells the user.
3. The agent-seat writes its session-handoff with the /handoff skill, without `--dont-restart`, because a session-handoff with that flag makes the new handoff-supervisor wait for an answer on the agent-seat's terminal. It tells the operator the session-handoff is written, and stops working.
4. The operator checks that `~/.claude/handoffs/<seat>-handoff.md` was modified after the operator's message in step 2, since an older session-handoff of the agent-seat may already be at that path. The operator then ends the frozen handoff-supervisor with `kill -KILL <process ID>`, since a frozen process does not act on `kill -TERM`, and, if the `claude` process noted in step 2 still runs, ends it as the Rules say. What the successor needs is in the session-handoff, and the agent-seat's changes were committed in step 1. The operator does steps 4 to 6 without pausing between them: on ned-box, while the agent-seat is down with its session-handoff waiting, the agent-crash-watcher does not restart it, but may show the user a failed-restart-notice about it, and the operator's report says such a notice was expected.
5. The operator runs `python3 ~/Projects/nedschorus/scripts/resupervise-seat.py <seat> --prepare-only`, which refuses unless the session-handoff is waiting and no handoff-supervisor is alive, and removes the agent-seat's old tmux session. The operator then lists again the processes working in the agent-home with `lsof -a -d cwd +D ~/agents/<seat>`; an empty list, with exit status 1, means none is left. It ends each process in the new list that was also in step 2's list and is not a tmux server, because step 6 refuses while one runs. For any other process, it stops and tells the user.
6. The operator runs `python3 ~/Projects/nedschorus/scripts/recover-crashed-seats.py <seat>`, adding `--open-iterm-window-per-seat` on the Mac, so that the successor opens in a window, since the agent-seat's old window closed in step 5. The program finds no handoff-supervisor alive for the agent-seat and a session-handoff waiting, and starts a new handoff-supervisor from the reference-checkout in a new tmux session, which starts the successor from the session-handoff. On ned-box, exit status 3 means the agent-seat started but no window opened on the Mac; that is no failure, and the operator's report says so.
7. The operator checks that a new `handoff-supervisor.py --agent <seat>` process runs from `~/Projects/nedschorus/nc-systems/handoff/`, started after step 4; that a new `claude` process runs under it, with a Claude Code session ID other than the one noted in step 2; and that the successor answers a SendMessage within 10 minutes. Without an answer by then, step 7 has failed. The operator reports the result as the Rules say, with what each of the three showed.

## On the Mac: the helper agent-seat

1. Before step 0, the agent-seat being restarted writes a file outside every agent-home, such as `/tmp/<seat>-restart-helper-first-prompt.md`, saying: "You are the operator for restarting the handoff-supervisor of the agent-seat <seat> on this Mac. Read `~/Projects/nedschorus/docs/nedschorus-wiki/nedschorus-handoff-supervisor-restart-onto-main-code-by-hand-procedure.md` and carry out steps 0 and 2 to 7 for <seat>." It launches the helper agent-seat: `LAUNCH_CLAUDE_SUPERVISOR_EXTRA_ARGUMENTS=--first-prompt-file-wins-over-crashed-transcript ~/Projects/nedschorus/scripts/launch-claude-mac <seat>-restart-helper --no-attach --first-prompt-file /tmp/<seat>-restart-helper-first-prompt.md`. The extra argument makes a helper agent-seat whose name was used before read the file, instead of resuming the old helper agent-seat's transcript. If the launcher prints that a tmux session named `<seat>-restart-helper` already exists, a helper agent-seat from an earlier restart is still there: remove it with the commands in step 3 below, then launch again. The agent-seat being restarted tells the user that the helper agent-seat runs detached, and that he can watch it from a Mac Terminal with `launch-claude-mac <seat>-restart-helper`.
2. The helper agent-seat is the operator for steps 0 and 2 to 7. It commits nothing, so its agent-home and seat-branch hold no work.
3. The helper agent-seat sends its step 7 report to the restarted agent-seat's successor. After that report arrives, and not before, the successor, told to in its session-handoff's next step, stops the helper agent-seat with `tmux -L <seat>-restart-helper kill-server`, and removes its agent-home and seat-branch with `git -C ~/Projects/nedschorus worktree remove --force ~/agents/<seat>-restart-helper` and `git -C ~/Projects/nedschorus branch -D <seat>-restart-helper`. If a removal command fails, the agent running it tells the user what it printed.

## Getting an agent-seat back after a failure

- **Before step 2 freezes the handoff-supervisor:** the agent-seat carries on as before; the fast-forward of the reference-checkout in step 0 needs no undo, since that checkout is meant to be at main. The operator tells the agent-seat being restarted, which tells the user and, on the Mac, removes the helper agent-seat with the commands in step 3 of "On the Mac: the helper agent-seat".
- **While the old handoff-supervisor is frozen:** the operator unfreezes it with `kill -CONT <process ID>`. It consumes any session-handoff already written and starts the successor on its old code, which loses nothing. The operator tells the agent-seat, or its successor, which tells the user and, on the Mac, removes the helper agent-seat. Before step 4, the operator may end the attempt this way at any time, and does so when the agent-seat being restarted says it cannot write its session-handoff.
- **After step 4 ended the old handoff-supervisor, while no new one runs:** the session-handoff still waits on disk. The operator removes what made the command fail, such as a process left from the old `claude`, and runs only that command once more; before it signals a process ID again, it checks with `ps -ww -o args= -p <process ID>` that it is still the same process. If the command fails again, or what made it fail is another agent-seat's tmux server, the operator stops and tells the user, giving him, on the Mac, the commands in step 3 of "On the Mac: the helper agent-seat" that remove the helper agent-seat.
- **Once a new handoff-supervisor runs**, whether or not it started the successor: that handoff-supervisor may already have consumed the session-handoff, so the operator changes nothing, and tells the successor, if one answers, or else the user, what `ps` shows for the agent-seat.
