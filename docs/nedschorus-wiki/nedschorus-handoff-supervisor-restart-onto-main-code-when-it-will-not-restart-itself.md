# Restarting a handoff-supervisor onto main's code when it will not restart itself

A running handoff-supervisor keeps the code it started with, because its process reads its Python code once, when it starts. At each session-handoff that launches a successor without consulting the user, the handoff-supervisor restarts itself on main's code, as the handoff-system's nc-architecture-overview, `docs/nedschorus-wiki/nedschorus-handoff-architecture-overview.md`, says, and then the next such session-handoff is enough.

The restart program, `python3 ~/Projects/nedschorus/nc-systems/handoff/handoff-supervisor-restart-onto-main-code-by-relaunch-from-reference-checkout.py <seat>`, is for a handoff-supervisor that is running and will not restart itself: one whose code predates that restart; one that runs from a checkout other than the reference-checkout `~/Projects/nedschorus`, such as a Mac agent-seat launched from its agent-home, since the restart fast-forwards the checkout the handoff-supervisor runs from and fails whenever that checkout cannot be fast-forwarded to main, as when its seat-branch holds commits of its own; or one whose restart failed for a reason other than its checkout. The agent-seat being restarted runs the program itself, on the machine it runs on, and on ned-box through `ssh nedlern@ned-box '<command>'`, because the Bash sandbox cannot signal the handoff-supervisor. The program's docstring says what the agent-seat does before and after running it, what the program does, how each failure leaves the agent-seat, and what it cannot handle.

When neither a handoff-supervisor nor an agent-session of the agent-seat runs, the restart program does not apply: `scripts/recover-crashed-seats.py`, which brings back an agent-seat whose handoff-supervisor is gone, is the tool for that agent-seat.

When an agent-session of the agent-seat runs but no handoff-supervisor watches it, neither the restart program nor `scripts/recover-crashed-seats.py` applies: the agent-session writes its session-handoff at once, by the /handoff skill, and tells the user, who then runs, on the Mac, `python3 ~/Projects/nedschorus/scripts/resupervise-seat.py <seat> --machine <machine>`, with `ubuntu` for an agent-seat on ned-box and `mac` for one on the Mac. That program ends the agent-session, losing anything done after the session-handoff was written, and starts a successor from that session-handoff under a new handoff-supervisor.

When the reference-checkout cannot be fast-forwarded to main at a session-handoff, a handoff-supervisor that runs from the reference-checkout itself runs `nc-systems/handoff/handoff-reference-checkout-back-on-main-after-pushing-leftovers-to-a-branch.py`, which saves anything left in that checkout to a pushed branch and puts the checkout back on main, and then restarts. When that program fails, the successor's initial-agent-instructions say the handoff-supervisor did not restart and quote what the program printed. Do not run the restart program for that notice: it pushes no leftovers, and its first step fails whenever the checkout will not fast-forward. The agent-seat works out the cause from what the program printed, fixes the cause, and runs the program again: on ned-box as `ssh nedlern@ned-box 'python3 ~/Projects/nedschorus/nc-systems/handoff/handoff-reference-checkout-back-on-main-after-pushing-leftovers-to-a-branch.py'`, and on the Mac as `python3 ~/Projects/nedschorus/nc-systems/handoff/handoff-reference-checkout-back-on-main-after-pushing-leftovers-to-a-branch.py`, without ssh; when the cause is not one the agent-seat can fix, it tells the user what the program printed. A failed push still leaves the checkout on main, and the branch the program could not push stays only in that checkout until the program is run again, because the handoff-supervisor runs the program only when the checkout will not fast-forward. Once the checkout is on main, the next session-handoff that launches a successor without consulting the user restarts the handoff-supervisor.
