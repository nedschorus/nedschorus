# nedschorus glossary

A list of the phrases and terms of this project approved by the user, in alphabetical order, skills first. Generic SDLC vocabulary is deliberately absent.

Every project-term should be listed here; a term this page does not list is not a project-term, at least not yet. A term used by one system or subsystem alone is a system-term, not a project-term: it is defined in that system's own glossary, so when this page does not list a term, look in the glossary of the system whose files you are in. Each term has one entry, in the glossary of the widest scope that uses it: a term more than one system uses is defined here and in no system glossary. If a term should be added to this list, ask the user to review it. A word needs a project-term only where this project does something unexpected with it or gives it a meaning that would be hard to guess; otherwise it stays ordinary prose. A project-term takes one of four forms: an abbreviation such as GHI, a skill's slash name such as /handoff, a hyphenated phrase such as agent-seat, or a filename suffix such as -draft. The hyphens mark a phrase as a project-term or a system-term with a meaning this project gives it, so a reader knows to look it up, here or in that system's glossary, and an ordinary word keeps its ordinary meaning.

A term used by one system alone is defined in that system's glossary, not here. The system glossaries are `.claude/skills/skills-glossary.md`, the terms the skills alone use, `docs/design-to-main/design-to-main-glossary.md`, the terms of the design-to-main workflow, `nc-systems/handoff/handoff-system-glossary.md`, the terms of the handoff-system, and `nc-systems/main-gatekeeper/main-gatekeeper-glossary.md`, the terms of the main-gatekeeper. A new system glossary is listed here when it is created; `scripts/system-glossaries-listed-on-the-project-glossary-test.py` fails until it is listed. A system with no glossary of its own has no system-terms: its terms are defined here, or in the skills glossary when a skill runs the system, as with cold-read.

An entry that defines a kind of text, a change to text, or a check on text ends with one or more of the labels #prose, #code and #data, separated by spaces, naming the kinds of text the entry's term covers; the term does not cover a kind its labels leave out. An entry that names a thing, a role or a procedure, such as an agent-seat, merge-lane or the log-store, carries no label: prose, code and data can all refer to it, and each passage that does is checked as its own kind requires. A part of a file that is two kinds at once, such as a Markdown heading that people read and a program reads as data, is covered by a term only when the term's labels name both kinds.

- **/cold-read** — a skill used to improve the readability of prose.
- **/explain** — a skill that re-explains a message the user could not follow, so he can understand the message without the agent-session's context.
- **/find-info** — the skill an agent uses to find a stored file, record, transcript or walk-minutes file, or a past discussion, decision or approval, such as an earlier user-ruling.
- **/find-missing-file** — the skill an agent uses before it reports that a file, record, transcript or backup is missing, to search for copies of it first.
- **/ghi-write** — a skill used before any write to a GitHub issue.
- **/handoff** — a skill that writes the session-handoff a successor agent-session starts from, used when a system message says the agent-session has used the share of its context window set as the reincarnation threshold, or the user asks for a handoff.
- **/overview-write** — the skill used to write, refresh or fix an nc-architecture-overview, and to run the program that checks its claims against the code.
- **/pull-request-review-write** — a skill used before writing or revising a review on a pull request.
- **/sanity-check** — a skill used to improve designs.
- **/start-agent-seat** — the skill used to start a new named agent-seat on ned-box, which covers choosing its name, the seat-brief the user approves, and its launch command.
- **/walk-me-through** — a skill that presents complex material to the user one item or step at a time.
- **-common** — a filename suffix for a module whose functions several programs import; the module is not run on its own.
- **-draft** — the filename suffix of a document still being written, such as `docs/drafts/<subject>-draft.md`; a cold-read-fast-read may read it, but no one has been asked to approve it yet. The section "Filename suffixes" of `docs/nedschorus-wiki/nedschorus-file-naming-and-location-standards.md` defines it and six more suffixes.
- **-nbd** — the end of the name of a file whose whole content is nice-but-dirty, just before any extension, such as `scripts/log-store-session-dialogs-refresh-nbd.py`; no file without the suffix holds nice-but-dirty code.
- **agent-action-block** — a refusal that a program in this repository, such as a hook or a script, hands an agent, stopping the agent's action; the agent-action-block's kind says what, if anything, clears it. Its kinds are hard-block, soft-block, user-block and reminder-block. A tool-message-to-agent that does not stop the agent's action, such as a warning, is not an agent-action-block.
- **agent-arbitrator** — a fresh-agent, used to resolve conflicts between agents.
- **agent-binary** — the installed program a cold-read-cell or a sanity-check-cell runs its model through, `claude`, `codex` or `agy`.
- **agent-crash-watcher** — the program on ned-box that restarts an agent-seat whose agent-session stopped without writing a session-handoff, at most once an hour, and otherwise shows the user a failed-restart-notice. The program is `nc-systems/handoff/handoff-agent-crash-watcher.py`.
- **agent-home** — the directory an agent-seat works in, `~/agents/<seat name>` on the agent-seat's machine: a git worktree that holds no work and rests on a detached HEAD at `origin/main`, marked by the file `agent-home-marker` in its own git directory, so that `scripts/git-client-side-hooks/pre-commit` refuses commits in it; its agent-sessions work on nc-topic-branches in worktrees of their own.
- **agent-instructions** — prompts or Markdown files that instruct agents, wherever an agent reads them, such as CLAUDE.md, a skill, a seat-brief or AGENTS.md.
- **agent-readable** — a text-intended-reader-category: text written for an agent outside the writer's agent-session that can open any file in the repository; its cold read checks that an agent acts on it correctly.
- **agent-seat** — a named, long-lived agent identity with its own agent-home and seat-brief, held by a series of agent-sessions joined by session-handoffs.
- **agent-session** — one running conversation of an agent, usually occupying an agent-seat. Agent-sessions end; while an agent-seat is active, a successor replaces its agent-session, and the agent-seat persists.
- **AO** — the answer to an approval-walk item that approves it and records that the user found it obvious.
- **approval-walk** — presenting material to the user one item at a time, under /walk-me-through, for a decision on each item; its outcomes are recorded in walk-minutes.
- **approved-by-walk** — approved by the user item by item in an approval-walk, not by one yes to a bundle.
- **block-and-inform** — the technique of checking before an agent acts: a program refuses the action, and its tool-message-to-agent teaches the behavior wanted instead, such as `.claude/guard-hooks/ghi-issue-write-hand-typed-gh-command-refusal.py` refusing a hand-typed `gh issue create` and sending the agent to `scripts/ghi-issue-write.py`. Every agent-action-block should carry it out; where the block's check can miss a case, detect-inform-correct is added after the act.
- **build-slice** — one numbered increment of a build plan, built and merged on its own.
- **C-numbers** — the identifiers `C1`, `C2` … of the main-gatekeeper's decisions on the credential that pushes to main, defined in `nc-systems/main-gatekeeper/main-gatekeeper-design.md` § The credential and enforcement.
- **case fix** — a change that fixes only the case in front of the author.
- **code-prompt-code (aka CPC)** — a program whose code does every step that needs no judgment, such as sequencing, saving and reading state, validation and retries, and hands an agent a prompt only for work that needs judgment, then checks the form of what the agent returns, such as its required sections, before its code uses it. Example: `nc-systems/cold-read/cold-read-grid.py`, which runs reviewer prompts through `claude`, `codex` and `agy`.
- **cold-read-record** — the directory holding the reports of one cold-read-full-run, one cold-read-fast-read or one judging of a restater by `nc-systems/cold-read/cold-read-restater-judge-runner.py`, its frozen-copy where it has one, and, once its findings are triaged, `cold-read-triage.md`; kept in the checkout's `cold-read-records/` and shipped to the log-store by `nc-systems/cold-read/cold-read-record-ship.py`.
- **conversation-tail** — the verbatim tail of an agent-session's dialog, `~/.claude/handoffs/<seat>-dialog-NNNN.md`, which the handoff-supervisor writes when it replaces the agent-session, for the successor to read first.
- **cosmetic-change** — a change to prose that alters only its formatting or its place, never what it says, as `docs/nedschorus-wiki/nedschorus-which-changes-need-the-users-approval.md` defines it. #prose
- **create-GHI** — the ghi-write-tool operation that files a new GHI for a GHI-MD that has none, refusing when an open GHI already covers the same ground.
- **deferred-decisions** — the section of a design or GHI-MD, headed `Deferred-decisions` at any heading level, that lists the cases and decisions the document leaves for its build, for later evidence or for the user to settle; a reviewer does not report a case listed there as missing.
- **design-contract** — the file beside a design listing what the component promises its component-consumers, one testable clause per observable effect.
- **design-requirement** — one statement of what a design requires, with a name no other design-requirement in the repository has, such as `cleaner-removes-worktree-after-30-quiet-days`. A design's design-requirements are its list of them.
- **design-to-main** — the workflow that takes an approved design to code, tests and a pull request; its design and its own glossary are in `docs/design-to-main/`. A user-ruling made for today's system, in which an agent-seat opens a pull request and merge-lane-2 reviews and merges it, does not apply to the steps inside a design-to-main run unless the user rules that it does; the pull request a run opens follows the rules of whatever reviews and merges it.
- **detect-inform-correct (aka DIC)** — the technique used where a check before an agent acts, such as a hook's refusal, can miss a case: a program detects, after the act, an action that should not have happened, and then one of two things follows. When the program can undo the action safely, it undoes it and tells the agent, in a tool-message-to-agent, what it undid, why, and how to do it correctly. When only the agent can undo it safely, such as after a shell command changed a guarded-file, the program tells the agent what it detected and how to undo it, and the agent corrects it.
- **edit-GHI** — the ghi-write-tool operation that merges an edit of a filed GHI-MD into main and updates the GHI from main.
- **failed-restart-notice** — the notice the agent-crash-watcher shows on the user's Mac, as a browser page or else in a terminal window, when it cannot restart an agent-seat, with the command to restart it himself.
- **fix-round** — one cycle of a pull request answering review findings, written by a forked subagent that inherits the author's full context, as one commit on top of the frozen-head.
- **fresh-agent** — a minimal-context agent: one that has read only `CLAUDE.md`, every file `CLAUDE.md` names, every glossary (this one and the system glossaries listed at its top), its agent-instructions, and the documents selected for its task with the documents they link. A fresh subagent is a fresh-agent started as a subagent, not as a fork, so it sees none of the conversation of the agent that dispatched it; a forked subagent is its opposite, a copy that inherits that conversation.
- **fresh-reader** — a fresh-agent, or a person, reading a document with no context beyond the document and what it links.
- **frozen-copy** — the copy of a document that a cold read's reviewers read, taken when the run starts.
- **frozen-head** — a pull request's nc-head-commit once pushed, which is never amended or force-pushed; a fix is a new commit on top.
- **GHI** — GitHub issue
- **ghi-guide-agent** — the GHI knowledge agent, which an agent asks, with `scripts/ghi-guide-agent-ask.py`, which issues to read before filing or editing an issue.
- **GHI-MD** — the MD file used to explain a GitHub issue.
- **ghi-write-tool** — `scripts/ghi-issue-write.py`, the program whose operations are create-GHI and edit-GHI.
- **guarded-file** — a file that the instruction-file guard, `.claude/guard-hooks/instruction-file-guard.py`, protects: `CLAUDE.md` and `CLAUDE.local.md`, everything under a `.claude/` directory apart from `worktrees/`, `jobs/` and `handoffs/`, a `-prompt.md` or `-instructions.md` file, and a reviewed document (a `.md` file under `docs/agents/`, `docs/nedschorus-wiki/` or `nc-systems/skills/`, or a `-design.md` file), with the exceptions that guard makes; plus `~/.claude/CLAUDE.md` and `~/.claude/settings.json`.
- **guide-agent** — a long-lived agent that answers other agents' questions about one domain (the GHIs, PRs, the wiki, one system) and keeps that domain's knowledge current. It is not an agent-seat: a script runs it one question at a time, with no seat-brief and no handoffs, and the user does not talk to it. ghi-guide-agent is the first.
- **hand-merge** — a merge of main into a conflicting pull request's branch, with each conflict resolved by hand and nothing else changed, pushed on top of the frozen-head.
- **handoff-supervisor** — the program `nc-systems/handoff/handoff-supervisor.py`, one per agent-seat, that launches an agent-session and replaces it when it writes a session-handoff. When the agent-session ends without one, the handoff-supervisor resumes it if it exited with a non-zero code and its last resume, if any, brought new work; otherwise the handoff-supervisor exits.
- **handoff-system** — the subsystem that replaces an agent-session with a fresh one, which continues from the session-handoff the old agent-session wrote. Overview: `docs/nedschorus-wiki/nedschorus-handoff-architecture-overview.md`.
- **hard-block** — an agent-action-block that nothing clears; the agent does what the agent-action-block says to do instead, such as running `scripts/ghi-issue-write.py` in place of a refused `gh issue create`, and stops and tells the user when that cannot do the work.
- **human-and-agent-readable** — a text-intended-reader-category: text written for the user and for agents; its cold read checks both that the user understands it and that every path, command and flag an agent needs is written out exactly.
- **human-readable** — a text-intended-reader-category: text written for the user, who reads the page, its links, the glossaries and `CLAUDE.md`, but not code; its cold read checks that the user understands it from those alone.
- **ID-type** — the kind of thing an identifier names, and the word written before its name in a citation: `GHI` for a GitHub issue, `PR` for a pull request, agent-seat for an agent-seat, and the ordinary word for a commit, task or session.
- **initial-agent-instructions** — the agent-instructions in the prompt that starts an agent or a subagent.
- **instruction-file guard** — the hook `.claude/guard-hooks/instruction-file-guard.py`, which refuses an edit to an agent-instructions file or a Claude Code settings file until the `.walk-approved` marker file holds the user's approval, for a change `docs/nedschorus-wiki/nedschorus-which-changes-need-the-users-approval.md` lists and does not except, or, for any other change, `#pre_approved_change` and the reason the change needs no approval.
- **launch-time-git-sync** — the fast-forward of an agent-seat's agent-home to `origin/main` that the handoff-supervisor attempts before it starts an agent-session; when a fast-forward is not possible or not safe, the agent-home is left as it is.
- **leftover-shell** — the shell an agent-seat's tmux window drops to after its agent-session stops; `scripts/recover-crashed-seats.py` asks before closing it.
- **link-only-GHI** — a GHI whose body is only links to its GHI-MD and supporting documents; the GHI-MD holds the text.
- **log-store** — the directory on ned-box, `/home/nedlern/nedschorus-logs/`, holding the byproducts of the work that are not the system, cold-read-records first.
- **loose-end** — something asked, offered or left open that nothing routinely processes: no open task on an agent-seat's task list, open GHI or open pull request holds it in that task's, GHI's or pull request's current text; no session-handoff its successor has not yet read lists it as open; and it is not an unanswered item of an approval-walk still open in a running agent-session. It may concern a task, GHI or pull request, such as a question about a pull request. Work handed to another agent-seat is a loose-end unless a task, GHI or pull request holds it on one side or the other, so the agent-seat that hands it over keeps a task for it until the other agent-seat says it has a task for it. A closed approval-walk's minutes, a cold-read triage, a queue directory and `docs/drafts/` do not count as holding one, because nothing routinely processes them. The plural is loose-ends.
- **machine-readable** — a text-intended-reader-category: text written for a program that is not a language model, such as code that Python or a shell runs, a JSON file a script parses, or a GHI-MD heading a script reads; a test that feeds the text to that program checks it. A text written for more than one kind of reader, such as a GHI-MD heading that a script parses and agents read, belongs to each reader's category and gets each category's check.
- **main-gatekeeper** — the program that will be the only way a change reaches main. Until it is live, changes reach main by PR through merge-lane.
- **maintenance-job** — a job that runs on a regular schedule, some of them daily, to catch what an immediate check, such as a hook, missed, or to clear what builds up, such as old worktrees.
- **merge-lane** — the role that manages the review of every PR and merges the PR into main, held by the agent-seat merge-lane-2 on ned-box.
- **NBD** — nice-but-dirty.
- **NC** — this project, NedsChorus.
- **nc-architecture-overview** — a document for someone about to change a system: it says what the system is for, what its components are, and how they fit together. In this project, it is one wiki page per system under `nc-systems/`, `docs/nedschorus-wiki/nedschorus-<system>-architecture-overview.md`, written and checked as `docs/nedschorus-wiki/nedschorus-how-to-write-an-architecture-overview.md` says. #prose
- **nc-head-commit** — the newest commit of a branch; in this project, a pull request's nc-head-commit, once pushed, is the frozen-head that the pull request's review runs against and that the pull request's merge is pinned to.
- **nc-mutation-testing** — putting a small fault into code on purpose and running the tests, to see whether a test fails; in this project, how an author or a reviewer shows that the tests check a line of code: with that line broken, at least one test that runs it fails. `CLAUDE.md` says which code must be shown this way.
- **nc-shared-database** — the project's shared database, on ned-box, which the project's later stores join as tables of their own; one service, `nc-systems/nc-shared-database/nc-shared-database-service.py`, alone reads and writes it, and programs on both machines reach it only through that service.
- **nc-system** — a part of this project with its own job and its own directory under `nc-systems/`, such as `nc-systems/cold-read/`, `nc-systems/main-gatekeeper/` or `nc-systems/skills/`, or whose files are still to move there, such as design-to-main; `nc-systems/general-tools/` is not one, since it holds code shared by several nc-systems or owned by none.
- **nc-test-sandbox** — an environment that limits what a test can see and change on the machine it runs on; in this project, the one the test runner `scripts/run-all-test-suites.py` builds around an nc-test-suite; the runner's docstring says, under "THE SIGNAL SANDBOX IS ALSO EACH SUITE'S NC-TEST-SANDBOX", what a suite can see, and which suites and machines get one.
- **nc-test-suite** — a set of test cases run together as one program; in this project, each file git tracks whose name ends in `-test.py` or `-test.sh` is one nc-test-suite, which the test runner `scripts/run-all-test-suites.py` runs as one unit and judges by its exit code alone, 0 a pass and anything else a fail. The project's tests as a whole are "the nc-test-suites", plural. A test run need not include every nc-test-suite: without options the test runner runs every nc-test-suite, but given `--only-suites-whose-recorded-inputs-changed-since <commit>`, the test runner runs only the nc-test-suites its docstring's selection rules pick, which include every nc-test-suite the change may affect; the scheduled full test run, `scripts/daily-full-test-run-of-main.py`, is set to run every nc-test-suite on main on each machine, at the times `nc-systems/general-tools/scheduled-jobs-on-each-machine.json` gives.
- **nc-topic-branch** — in Git's sense, a branch for one topic, a feature or a bugfix; in this project, the branch whose commits a pull request brings into main. Not a seat-branch.
- **ned-box** — the Ubuntu machine on the user's LAN, reached as `ssh nedlern@ned-box`: the project's hub and server, where most agent-seats run and the log-store lives.
- **nice-but-dirty** — a component, such as a script, a hook or a scheduled job, that mostly works but need not work every time, the way an instruction file or a skill mostly works but sometimes does not. A nice-but-dirty component is held to four limits only: the docstring at the top of its file, or the header comment in a language without docstrings, says what it does, what it does not handle and how it can fail, including any harm it can cause, and it does what that says; it never damages other systems or data, or blocks other work, and whatever goes wrong when it fails can be undone; it reports its own failures where an agent or the user will see them, and never hides them or reports them as success; and deleting it, or reverting the pull request that added it, leaves nothing broken behind. Code that needs nice-but-dirty code in order to work is nice-but-dirty too. A piece of work is only as reliable as its least reliable step, usually an LLM agent, and each guard, retry or fallback is new code that can fail. Beyond what the four limits require, add a guard, retry or fallback to nice-but-dirty code only when the failure it prevents happens about as often as that least reliable step fails. That agent usually recovers on its own from a failure the code reports plainly, so a plain report costs less than a guard and, unlike the agent's quiet recovery, leaves a trace. A review finding on nice-but-dirty code blocks a merge only when it shows the code breaking one of these four limits; a failing test still blocks. Nice-but-dirty code lives only in files whose names end with the -nbd suffix. Closest SDLC-term: best-effort; nice-but-dirty adds the four limits. Abbreviated NBD.
- **obvious-error** — a mistake in prose, never in code or data, whose correct replacement the rest of its document, the repository, the Mac, ned-box or GitHub makes clear; only these count: a spelling, grammar or punctuation mistake; a link, path, file name, script name, flag, or line or section reference that does not exist, or does not work or point where the text says, other than a name the text gives as planned or as an example; a statement of how things are, such as where a file lives or which machine a program runs on, that is false, where a plan, a design's intent or a user-ruling is never a statement of how things are; and a place missed by a change the user approved in the same agent-session that makes the fix. A mistake whose correction would change what an agent or a program is told to do, or what a document decides, other than by making the text true, making a broken name work as the text says, or making a missed place match the approved change, is not an obvious-error, however obvious it looks. #prose
- **obvious-error-fix** — replacing an obvious-error with its correct replacement and changing nothing else; a missed place is fixed exactly as the approved change fixed the other places. When the fix is committed, the commit message says what was fixed and why, and, for a false statement, names the source that shows it false. The fix is not reported to the user; a subagent tells the agent that dispatched it. #prose
- **obvious-fix marker** — a `.walk-approved` marker file that begins 'Obvious fix under CLAUDE.md's standing approval:', which lets an agent make an obvious-error-fix in a guarded-file without asking the user first.
- **one-off-prompt** — a prompt written for one agent, once, such as a brief to a subagent, written in the agent's scratchpad or passed straight to the agent, never kept in a checkout. The user does not review a one-off-prompt; before dispatching a fresh subagent, run `nc-systems/cold-read/cold-read-fast-read.py --target <prompt file>` on its brief.
- **outside-program-term** — a term that an outside program this project runs defines, such as Claude Code's subagent or GitHub's label, used with that program's meaning and spelling and no hyphen of this project's own: pull request, never pull-request.
- **pre-approved-change** — a change that needs no approval: one not on the list of changes that need approval, or one of the list's exceptions.
- **project-term** — a name with a meaning specific to this project and used by more than one of its systems or subsystems, listed in this glossary: an abbreviation such as GHI, a skill's slash name such as /handoff, or a hyphenated phrase such as agent-seat, or a filename suffix such as -draft, whose leading hyphen marks it as a project-term. A word this glossary does not list is not a project-term; a term one system uses alone is a system-term.
- **proposed-improvements-or-changes-file** — a file beside an nc-architecture-overview, or, for ghi-guide-agent's ruling questions about a GHI-MD, in the log-store directory `nedlern@ned-box:/home/nedlern/nedschorus-logs/ghi-guide-agent-proposed-improvements-or-changes/`, named `<document name>-proposed-improvements-or-changes-<source>-<date>.md`, in which one reviewer records changes it proposes to that document or to what the document describes; GHI [Proposed improvements or changes to a GHI are handled by agents first, and reach the user only when they need him](https://github.com/nedschorus/nedschorus/issues/1132) says how its entries are settled.
- **provisional-addition** — a line an agent adds to an issue's Markdown file under "Provisional additions (not yet vetted by the user)", which becomes a ruling only when the user reviews the issue.
- **queue-drain** — the procedure that empties the queue directories and `docs/drafts/`, promoting, archiving or deleting each item; its issue is GHI [Queue drain procedure — the review process that empties the wiki queue, the pair queue, nc-queue, the drafts directory and the queue-drain-candidate-label issue queue](https://github.com/nedschorus/nedschorus/issues/24).
- **ready** — of a task or an approved change: nothing is left for the user to decide before work on it starts. Neither is ready while it waits on a pull request that has not merged or on another agent-seat's work, or while it needs ned-box and ned-box cannot be reached. Nor is long work ready, such as a cold-read-full-run or a pull-request review, while the handoff-deferral of the agent-session that would start it lasts.
- **reference-checkout** — the main worktree of a machine's clone of the repository, `~/Projects/nedschorus` on the Mac and on ned-box, which stays on `main`; the git hooks of every checkout of that clone run from its `scripts/git-client-side-hooks/`, and no agent works in it.
- **reincarnate-seat** — the handoff-supervisor replacing an agent-session with a fresh one that continues from the session-handoff, usually when the agent-session's context runs low.
- **reminder-block** — an agent-action-block that stops an agent once, such as the hook that, once per agent-session, stops an agent that wrote that a file is missing and reminds it to run `scripts/locate-file-copies-across-machines.py`, and lets the next attempt through whether or not the agent acted on it.
- **retire-seat** — to end an agent-seat for good so its name can be freed or reused; distinct from pausing it. The steps are in `docs/nedschorus-wiki/nedschorus-agent-seat-model.md`.
- **reusable-prompt** — a prompt kept for agents to run on again, by later agent-sessions or by several agents at once: a file in a checkout whose name ends in `-prompt.md` or `-instructions.md`, or prompt text in code, such as the successor prompt of `nc-systems/handoff/handoff-supervisor.py`. A change to what a reusable-prompt tells an agent to do needs the user's approval; a change that leaves that the same, such as an obvious-error-fix, does not. `docs/nedschorus-wiki/nedschorus-which-changes-need-the-users-approval.md` lists the exceptions.
- **ruling-agent** — the agent-seat on ned-box that keeps the user's user-rulings and his words in one store, and checks each approval-walk item against them before the item is shown.
- **SDLC-term** — a standard term of software engineering or of another computing field, such as operating systems, networking or databases, used with its standard meaning, as `flock` is; `docs/nedschorus-wiki/nedschorus-sdlc-terms.md` lists those this project relies on.
- **seat-branch** — retired: the long-lived git branch of one agent-seat, named for the agent-seat, that the launchers created for its agent-home. Launchers now make an agent-home detached at `origin/main`, and `scripts/agent-home-seat-branch-commits-save-to-pushed-branch-and-detach-at-origin-main.py` pushes a seat-branch's commits that main lacks to `<seat name>-seat-branch-commits-saved-<YYYY-MM-DD>` and detaches the agent-home.
- **seat-brief** — the `CLAUDE.local.md` at the root of an agent-seat's checkout, which git does not track: the file an agent-seat's occupant reads to learn its job.
- **self-readable** — a text-intended-reader-category: text written for its writer, in the same agent-session, such as scratchpad notes; it gets no check.
- **session-handoff** — the act of transferring the key context and state of one agent-session to the next, and the file that carries it, `~/.claude/handoffs/<seat>-handoff.md`, on the agent-seat's machine only and never committed.
- **shared-log** — the one log that every program on a machine writes to through Python's logging, one JSON line per event, copied to the log-store.
- **soft-block** — an agent-action-block the agent clears without the user's approval, by the act the agent-action-block names, such as writing its own reasoning into a marker file or running the command again with an environment variable the agent-action-block names set in front of it.
- **standing-agent-instructions** — agent-instructions that will be followed again and again: `CLAUDE.md`, `AGENTS.md`, the seat-briefs, every `-instructions.md` and `-prompt.md` file, every skill's `SKILL.md`, and every agent definition in `.claude/agents/`.
- **supporting-document** — a file on main, other than a GHI's GHI-MD, that the GHI's body links to, such as `docs/issues/670-system-overview-refresh-agent-design.md`, a design beside GHI 670's GHI-MD.
- **system-term** — a term used by one system or subsystem alone, defined in that system's own glossary rather than here; a term used by more than one is a project-term, defined here and in no system glossary. The system glossaries are listed at the top of this page.
- **test-design** — the document, written from a design and its design-contract, listing one test-requirement per design-requirement a test must observe, each with the coverage-type of the test that will cover it.
- **test-requirement** — one line of a test-design: one design-requirement, the coverage-type and names of the tests that check it, or `no-tests` with the reason.
- **text-intended-reader-category** — who a text is written for, and so how its cold read checks it: self-readable, agent-readable, human-readable, human-and-agent-readable or machine-readable.
- **tool-message-to-agent** — text that a program in this repository writes for an agent to read and act on, such as a hook's refusal, warning or reminder, or the error a script prints. Its source is in the repository, so every tool-message-to-agent can be found, cold-read, tested and rewritten. Text that the agent-binary, `claude`, `codex` or `agy`, adds on its own, such as Claude Code's "hook error" label, is not part of a tool-message-to-agent. A tool-message-to-agent that never reaches the agent is a defect of the program that writes it.
- **topic-worktree** — a linked worktree made together with its own nc-topic-branch, the branch being cut from `origin/main`, in which an agent does the work of that one nc-topic-branch.
- **user-alert** — a JSON file a program on ned-box writes into `~/.local/state/nedschorus/user-alerts/pending/` when it hits a failure only the user can fix; the next prompt he types in a ned-box agent-session claims it, and the agent turns it into the next item of his approval-walk.
- **user-approved-change** — a specific change the user approved before an agent makes it, approved-by-walk or approved in conversation, as `docs/nedschorus-wiki/nedschorus-which-changes-need-the-users-approval.md` defines it.
- **user-block** — an agent-action-block that only the user's approval clears: the user's words quoted into the marker file the agent-action-block names, or, for an obvious-error-fix, the user's standing approval in `CLAUDE.md`, which the agent cites in that marker file.
- **user-ruling** — a decision by the user, recorded where it applies in the form (user-ruled YYYY-MM-DD), or recorded with his words and its date elsewhere, such as in walk-minutes.
- **walk-minutes** — the file `docs/walk/<name>-minutes.md`, in which the /walk-me-through skill records the outcome of each item of an approval-walk; shipped to the log-store's `walk/` directory by `scripts/walk-files-ship.py`.
- **walk-runner** — the program that will run an approval-walk's bookkeeping: it hands the agent the current item, counts its words, and records each ruling in the walk-minutes.
- **work-snapshot** — a git commit, kept under `refs/work-snapshots/` and never on a branch, that copies one worktree's uncommitted changes so they survive a crash; an agent-seat's leftover work-snapshots that hold lost work are listed in the initial-agent-instructions of its next agent-session, and by `python3 nc-systems/handoff/uncommitted-work-snapshots.py list --agent-seat <name>`.
