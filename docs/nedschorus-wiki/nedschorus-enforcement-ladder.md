# The enforcement ladder

The ways this project makes an agent follow a rule, ordered by when each acts. Read it before you add a rule to CLAUDE.md or another file of standing instructions: a rung nearer rung 1 usually serves the rule better than another line of text. The R-numbers below name the rules of [the fleet git and worktree working model](nedschorus-fleet-git-worktree-working-model.md), whose Index gives the rung of most rules.

A *rule* is a do-or-not-do instruction expressed as text; an *enforcement program* is code that enforces one (user-ruled 2026-08-17). The ladder orders mechanisms by when they act, earliest first — not by resistance to evasion: a block acts before the deed but can be blind to some routes; detection acts after and sees routes a block is blind to.

1. **Impossible** — the bad state cannot arise without a deliberate override. Even rung 1 is "impossible by default": `git worktree add --force` and a second clone both defeat git's one-branch-one-worktree refusal. Example: GitHub's branch protection on main refuses a direct push from every account, and lets a change reach main only as a pull request with one approving review, merged by one of two accounts (R12). That is rung 1 for GitHub accounts only: any process holding either account's credential can merge a reviewed pull request.
2. **Default** — the right thing happens without anyone deciding. Example: `.gitignore` keeps `cold-read-records/` and `docs/walk/` out of every commit, so no agent has to remember to leave them out (R22).
3. **Block** — an enforcement program refuses at the moment of action (Claude Code's PreToolUse hooks). Known blind spot: a block on file-write tools does not see shell writes (R10 carries the user-ruling on that gap). Example: `.claude/hooks/instruction-file-guard.py`, a PreToolUse hook on Edit, Write and NotebookEdit, refuses an edit of CLAUDE.md, a seat-brief, a skill, a wiki page or a design until the agent writes into a `.walk-approved` marker file the user's approval or, for a change `docs/nedschorus-wiki/nedschorus-which-changes-need-the-users-approval.md` does not require his approval for, `#pre_approved_change` and the reason; the guard checks that the marker exists, not that the approval is real (R10).
4. **Remind** — the program surfaces the rule at the moment it matters and lets the agent's action go ahead. Example: `scripts/bare-number-citation-in-markdown-and-agent-reply-warning-hook.py`, registered in `.claude/settings.json`, tells the agent when a Markdown file it just edited, or its last reply, cited a pull request or GHI by a bare number, and lets the work go on.
5. **Detect and reverse** — the unwanted action is noticed after the fact, undone, and the right way taught. Preconditions: an undo must exist, and the damage must not be consumed before detection — both argue for fast detection, not audits. Example: no program on main undoes an agent's act and teaches the right way. The nearest is `scripts/clean-worktrees.py`: at every handoff and once a day it removes each worktree under `.claude/worktrees/` that has no commits beyond main and that no process is using (R21). It clears a leftover, not an act.
6. **Text** — no enforcement; prose only. The waiting room: a do-or-not-do rule lives here only until mechanized (user-ruled 2026-08-17); governing principles, such as R17's and R28's, live here permanently by design. Example: CLAUDE.md's rule that, writing to the user or another agent, an agent writes the noun instead of a pronoun that could point at more than one thing; no program checks it.

Anchoring user-ruling, from the main-gatekeeper design, `nc-systems/main-gatekeeper/main-gatekeeper-design.md`: **CLAUDE.md is documentation, never enforcement** — no program enforces it, and different machines may carry different copies.
