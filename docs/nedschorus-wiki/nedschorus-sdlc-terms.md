# nedschorus SDLC terms

Standard terms of software engineering and of other computing fields, such as operating systems, networking or databases, that this project relies on, each used with its standard meaning; the /cold-read skill's step 8, in `.claude/skills/cold-read/SKILL.md`, also sends here a standard term the user directs in place of a coined one, when he plainly asks for its line. One line per term, in alphabetical order: the term, then what this project uses it for. A term listed here is not a project-term and is never hyphenated; project-terms are listed in the glossary, `docs/nedschorus-wiki/nedschorus-glossary.md`. List an SDLC-term only when other words for the same thing appear in the project, or when the user has plainly asked for its line; an agent unsure whether he asked for it asks him before adding one; an SDLC-term with neither needs no line, and is no less an SDLC-term for having none. A line is removed once its term has neither.

- **canonical location** — the one place where a document or fact is kept and updated; another document that needs that document or fact links to that place instead of copying it.
- **failure** — an event in which a program, component or system does not do what it is required to do, as the [ISTQB glossary](https://glossary.istqb.org/) defines it. Whose failure it is depends on what was examined: a test that fails has observed a failure of the code it tests, while a test, a linter or a review that could not do its own job, such as a linter that could not read a file it was asked to check, has failed itself.
- **finding** — a problem that a review, a linter or an analysis reports in what it examined, such as a defect that a pull request review reports. A finding can describe a failure of the thing examined, and a program can report findings and still fail itself, such as by stopping before it has examined everything.
- **outage** — something agents or the user rely on that does not work.
- **workaround** — code that copes with a cause instead of removing it.
