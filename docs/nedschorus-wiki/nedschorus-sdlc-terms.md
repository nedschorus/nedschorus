# nedschorus SDLC terms

Standard terms of software engineering and of other computing fields, such as operating systems, networking or databases, that this project relies on, each used with its standard meaning; the /cold-read skill's step 8 also sends here a standard term the user directs in place of a coined one. One line per term, in alphabetical order: the term, then what this project uses it for. A term listed here is not a project-term and is never hyphenated; project-terms are listed in the glossary, `docs/nedschorus-wiki/nedschorus-glossary.md`. List a standard term only when this project uses it more narrowly than its standard meaning, or when other words for the same thing appear in the project; a standard term used with its plain meaning and no competing words needs no line.

- **architecture overview** — a document that tells a reader who must change a system what the system is for, what its components are, and how they fit together; in this project, one per system under `nc-systems/`, written and checked as `docs/nedschorus-wiki/nedschorus-how-to-write-an-architecture-overview.md` says.
- **canonical location** — the one place where a document or fact is kept and updated, which every other mention points to.
- **head commit** — the newest commit of a pull request's branch; in this project, once pushed it is the frozen-head that the pull request's review runs against and its merge is pinned to.
- **mutation testing** — putting a small fault into code on purpose and running the tests, to see whether a test fails; in this project, how a reviewer or an author shows that a change's tests check what the change does: with a key line of the change broken, at least one of those tests must fail.
- **test sandbox** — an isolated environment in which a test runs, so that what the test does cannot reach the rest of the machine; in this project, the one the test runner `scripts/run-all-test-suites.py` builds on ned-box for each test suite it does not list as running without one, specified in the runner's docstring under "THE SIGNAL SANDBOX IS ALSO EACH SUITE'S TEST SANDBOX"; on the Mac no suite gets one.
- **test suite** — a set of test cases run together as one program; in this project, each file git tracks whose name ends in `-test.py` or `-test.sh` is one test suite, which the test runner `scripts/run-all-test-suites.py` runs as one unit and judges by its exit code alone, 0 a pass and anything else a fail. The project's tests as a whole are "the test suites", plural. A test run need not include every test suite: before a push, the test runner, given `--only-suites-whose-recorded-inputs-changed-since origin/main`, runs only the test suites the rules in its docstring select, chiefly those the change may affect; the daily full test run, `scripts/daily-full-test-run-of-main.py`, runs every test suite once a day on each machine.
- **topic branch** — in Git's sense, a branch for one topic, a feature or a bugfix; in this project, the branch a pull request merges. Not a seat-branch.
