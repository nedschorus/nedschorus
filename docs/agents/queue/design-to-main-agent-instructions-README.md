# design-to-main agent-instructions — drafts
These files are the standing-agent-instructions the design-to-main state machine (`docs/design-to-main/design-to-main-state-machine-design.md`; "§N" in every file cites it) launches each agent with: one file per state that launches an agent, named `design-to-main-<state>-agent-instructions.md`, drafted 2026-09-08 from the design and its glossary.
They are drafts in `docs/agents/queue/`, awaiting the full cold read and the user's review, and land in `docs/agents/` after both (user-ruled 2026-09-08); nothing launches them yet.
Which state launches which: `design-writing` launches the initiator; `contract-revising`, `implementation-writing`, `test-design-writing` and `test-writing` each launch a fresh writer; `design-acceptance-by-agent`, `contract-acceptance-by-agent`, `implementation-acceptance-by-agent`, `test-design-acceptance-by-agent` and `test-acceptance-by-agent` each launch a fresh reviewer; `test-suite-arbitrating` launches the arbitrator.
Common to all, the state-exit (§2): one state-package in, one state-exit out — `state`, a `verdict` from the state's own list, `package-commit` copied from the state-package, no destination, and the field the verdict needs: `input-named` (`design`, `component-contract`, `test-design`), `investigation-focus` (`design`, `test-design`), or `coverage-type` (`script`, `prompt`, `script-and-prompt`); the two agents that talk to the user, the initiator and the arbitrator, also carry his rulings in `rulings`, and the machine appends them to the user-rulings file.
Common to all, the notes: one file at `<component's directory>/design-to-main-record/evidence/<state>-<n>/notes.md` (§9), a reviewer's own tests beside it; findings carry a failure scenario, nits sit under a `Nits` heading and are never routed as work (§6.1).
Common to all, the state-package (§2): the standard-package — the design, the component-contract and the user-rulings file `<component's directory>/design-to-main-record/user-rulings.md`, whose latest ruling on a point governs and which nobody re-raises — plus what §3.1's Package column names for the state, repeated in its file.
Common to all: no agent commits or pushes — the machine commits every state-exit to the topic branch (§9); no agent below the design edits the design; a reviewer edits nothing at all.
Every example is built on the `create-topic-branch` component and its refusal-clause-pair 7a/7b: no `origin/main` after the fetch, exit status 1, two stderr lines, stdout empty.
Where the design did not say enough — the state-exit's file form, the evidence directory's count, the arbitrator's two rejects in one state-exit — the drafts say what the machine's code reads today, and the gaps are reported with the drafts.
