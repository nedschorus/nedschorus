# Project vocabulary (PROPOSED wiki page — draft for review)

Every term of art this project's agents and documents use as if established, one line each, so a new agent or a zero-context reviewer can resolve them instead of flagging them as unexplained coinages. Each entry: the plain meaning, then the defining home as a repo path (or "no defining document — usage only"). Generic SDLC vocabulary a professional already knows is deliberately absent.

- **accepted residual** — a named block recording that the boss overrode a review objection: the objection in one line, why it is not a concern here, and the reopening trigger; re-flagged only with new evidence matching that trigger. Home: `docs/cross-project/nedschorus-ai-native-software-development.md` § Accepted residuals.
- **anchor** — the document a walk marks its dispositions in (the subject document, the issue's pair document, or a tmp-file ledger), and the recovery contract a resumed walk reads instead of conversation memory. Home: `.claude/skills/walk-me-through/SKILL.md`.
- **artifact-lifecycle rule** — every artifact is either final at its home or sitting in a named queue that states its destination, and every queue has a drain; no stateless piles, ever. Home: `docs/cross-project/nedschorus-ai-native-software-development.md` § Project organization.
- **attack prompt** — one of the sanity-checker instrument's three stance audits (cut, mechanization, fresh-eyes), each run in its own fresh context by the runner. Home: `docs/agents/sanity-checker-instructions.md`; prompts at `docs/agents/sanity-checker-{cut,mechanization,fresh-eyes}-attack-prompt.md`.
- **boss** — the user: the project's one human operator; "the boss" and "the user" are the same person throughout the documents. Home: `docs/cross-project/git-gatekeeper-design.md` (stated there); also `docs/cross-project/fleet-git-worktree-working-model.md` § Reader's key.
- **brief** — `docs/agents/<seat>-instructions.md`: what a seat's occupant reads to learn its job. Home: `docs/agents/agent-seat-model.md`.
- **C-numbers (C1…C8)** — identifiers of the git-gatekeeper's credential rulings, meaningful only inside that design. Home: `docs/cross-project/git-gatekeeper-design.md` § The credential and enforcement.
- **cell** — one reviewer run of the cold-read grid: a {pass} × {tier} × {runtime} combination that writes one report file. Home: `scripts/cold-read-grid.py` (module docstring).
- **check-in** — the operation of getting a change onto main through the git-gatekeeper (`git-gatekeeper.py check-in`); replaces the retired "land"/"landing" vocabulary. Home: `docs/cross-project/git-gatekeeper-design.md`; terminology ruling in the retired founding plan (`git show 615a230:docs/cross-project/nedschorus-founding-plan.md`) § Standing decisions.
- **cold read** — the eight-cell zero-context review a document of lasting value gets before it lands on main: reviewers with no history restate what each sentence made them think it meant and report defects. Home: `.claude/skills/cold-read/SKILL.md`.
- **defect-hunt** — the cold-read pass whose reviewers flag contradictions, ambiguous readings, un-executable text, and unfindable names, without proposing fixes. Home: `.claude/skills/cold-read/prompts/defect-hunt.md`.
- **deputization** — the interim lane's ruled exception: the user instructs a specific seat, in that seat's own session, to merge a specific PR; relayed words are hearsay and are refused. Home: `CLAUDE.md`; `docs/cross-project/fleet-git-worktree-working-model.md` R13.
- **digest** — the gatekeeper's SHA-256 over base commit + declared paths + their new bytes + the import triple: the duplicate-detection key that makes resubmitting a check-in always safe. Home: `docs/cross-project/git-gatekeeper-design.md`.
- **dormant** — the git-gatekeeper's current state: built and tested, but not yet the live path to main until its credential work lands and the gate can review what passes through it. Home: `docs/cross-project/git-gatekeeper-design.md`; stated in `CLAUDE.md`.
- **draft (label)** — the GitHub label that is the issue world's queue membership: the boss's review queue is issues labeled `draft`. Home: the retired founding plan (`git show 615a230:docs/cross-project/nedschorus-founding-plan.md`) § Standing decisions. (Distinct from the `docs/drafts/` directory of in-progress documents — see CONFLICTS.)
- **drain** — the one process by which the boss empties any queue: he walks it when he chooses, and each item gets exactly one of four outcomes — promote, edit, demote, or drop. Home: `docs/cross-project/nedschorus-ai-native-software-development.md` § Project organization (procedure tracked on nedschorus#24).
- **enforcement ladder** — the ordering of enforcement mechanisms by when they act: impossible, default, block, detect-and-reverse, remind, text; a *rule* is text, an *enforcement program* is code that enforces one. Home: `docs/cross-project/fleet-git-worktree-working-model.md` § The enforcement ladder.
- **entry checkpoint** — the recorded crossing every import from the legacy system makes: the `Gatekeeper-import` trailer written in the importing commit itself, so the record cannot lag the system. Home: the retired founding plan (`git show 615a230:docs/cross-project/nedschorus-founding-plan.md`) § Standing decisions; mechanism in `docs/cross-project/git-gatekeeper-design.md`.
- **fix ladder** — the escalation sequence for failed work: retry, then a stronger model, then the boss. Home: `docs/cross-project/git-gatekeeper-design.md` (named in passing in the founding plan; `docs/agents/doctrine-instructions.md` points here as the definition).
- **fix round** — one commissioned round of fixes on a reviewed PR before merge (state S4/S5 of the PR-to-main process). No defining document on main — the design of record, `docs/drafts/pr-main-process-design.md`, sits only on the unmerged `merge-lane` branch.
- **GHI** — this project's shorthand for a GitHub issue; the GHI carries state, the MD carries substance, the queue holds the not-yet-decided. Home: `docs/agents/ghi-instructions.md` (the expansion); routing in `.claude/skills/ghi-write/SKILL.md`.
- **ghi-info** — the designed (not yet built) issue-knowledge agent that answers, for an issue write about to happen, which existing issues the author should have read; it reads the local `ghi-mirror/` only. Home: `docs/issues/46-ghi-info-agent-design.md`.
- **git-gatekeeper** — `scripts/git-gatekeeper.py`: the one program holding the project's one main-capable credential, the permanent single door to main; agents invoke it and never push to main themselves. Home: `docs/cross-project/git-gatekeeper-design.md`. (On the bare word "gatekeeper", see CONFLICTS.)
- **grid** — one cold-read invocation: eight cells ({restate, defect-hunt} × {good, floor} × {claude, codex}) launched in parallel over one target, reports saved to `cold-read-records/`. Home: `scripts/cold-read-grid.py`.
- **handoff** — the machine-local file a session writes for its successor (`~/.claude/handoffs/<seat>-handoff.md`), never committed; the one artifact that makes a paused seat resumable. Home: `docs/agents/agent-seat-model.md`; system design in `docs/cross-project/fast-handoff-design.md`; skill at `.claude/skills/handoff/SKILL.md`.
- **hearsay** — the user's words relayed through another session; refused as authorization (deputization must be given in the acting seat's own session). Home: `CLAUDE.md`.
- **ignition prompt** — the launch prompt the supervisor hands a successor session: the handoff path plus the elapsed-time line, the task count, and the queue-status line. Home: `docs/cross-project/fast-handoff-design.md`.
- **instruction-class** — files that tell agents how to behave (`CLAUDE.md`, per-seat `CLAUDE.local.md`, anything under `.claude/`); they change only with walked approval, enforced by `.claude/hooks/instruction-file-guard.py`. Home: `docs/agents/agent-seat-model.md`.
- **interim lane** — how work reaches main until the gate activates: commit on the seat's own branch, cherry-pick one topic onto a fresh branch from main, PR that branch; the merge-lane seat reviews and merges every PR. Home: `CLAUDE.md`; `docs/cross-project/fleet-git-worktree-working-model.md` § Reader's key.
- **legacy** — the old system (`~/Projects/nedlern`): read-only reference, every import crossing the entry checkpoint; never called "quarry". Home: `docs/cross-project/nedschorus-ai-native-software-development.md` § Standing decisions.
- **marker (override marker)** — a gitignored file at the checkout root (`.walk-approved`, `.location-write-approved`) holding the user's quoted approval words, consumed by the one guarded call it approves. Home: `docs/cross-project/fleet-git-worktree-working-model.md` § Reader's key and § Marker honesty.
- **MD-GHI pair / pair document** — a substantial issue's companion document `docs/issues/<n>-<slug>.md`: the issue carries the walkable state, the MD carries the greppable substance. Home: `docs/cross-project/nedschorus-ai-native-software-development.md` § Project organization.
- **merge-lane** — the seat on the user's Mac whose agent reviews and merges every PR until the gatekeeper activates; its GitHub identity is `ned-review-merge`. Home: `CLAUDE.md`; account detail in `docs/cross-project/git-gatekeeper-design.md` § The credential and enforcement.
- **pile** — the body of related work a seat owns: a subject area with shared context, not an ordered queue. Home: `docs/agents/agent-seat-model.md`.
- **pin** — the resolver every pointer carries so a successor or reader can find exactly what was meant: path + commit SHA, or repository + issue number. Home: `docs/cross-project/fast-handoff-design.md` § Rulings.
- **queue** — a named holding place with a stated destination and a drain: `docs/wiki/queue/`, `docs/issues/queue/`, `nc-queue/`, `legacy-feature-queue/`, and the `draft` issue label; the same `queue` token everywhere so one grep finds them all. Home: `docs/cross-project/nedschorus-ai-native-software-development.md` § Project organization.
- **recycle** — the supervisor replacing a session with a fresh one, carrying the handoff forward; triggered when the agent hands off, usually at the context threshold the Stop hook watches. Home: `docs/agents/agent-seat-model.md`; mechanism in `docs/cross-project/fast-handoff-design.md`.
- **reference checkout** — the machine's checkout that supervisors and launchers run from and other agents read expecting main; a reference, never a bench — agent writes into it are refused. Home: `docs/cross-project/fleet-git-worktree-working-model.md` § Reader's key and R6+R7.
- **restate** — the cold-read pass whose reviewers say in their own words what each sentence means; a confident misreading is a defect in the file, not in the reader. Home: `.claude/skills/cold-read/prompts/restate.md`.
- **revision convention** — a clarification or correction edits the artifact's body (issue body, pair document); comments are only for genuinely new events, an instance outcome or a ruling challenge. Home: `docs/cross-project/nedschorus-ai-native-software-development.md` § Project organization; enforced by `.claude/skills/ghi-write/SKILL.md`.
- **rewrite policy** — every legacy cherry-pick classifies exactly the features it touches as preserve-feature, update-feature, remove-feature, or consider-feature; unexamined is never preserved. Home: `docs/cross-project/nedschorus-ai-native-software-development.md` § Standing decisions.
- **ruling** — a written, reasoned disposition — the question, the answer, and why — dated and attributed with the stamp carried throughout the documents ("user-ruled / boss-ruled <date>"). Home: `docs/agents/doctrine-instructions.md` (authoring); the stamp form itself has no defining document — usage only.
- **sanity-checker** — the project's second review instrument: three attack prompts plus their runner `scripts/sanity-check-attacks.py`; also the name of the seat that owns it, and the brief keeps the two apart. Home: `docs/agents/sanity-checker-instructions.md`.
- **scrub** — the handoff-time report of every queue's depth and oldest item, so starvation is visible, not just volume; the duty now rides the ignition prompt's queue-status line (see CONFLICTS for the term's stale/live split). Home: the retired founding plan (`git show 615a230:docs/cross-project/nedschorus-founding-plan.md`) § Standing decisions.
- **seat** — a named, long-lived agent identity: a name, a home directory (`~/agents/<seat>`), its own git branch, and a brief; occupied by sessions and outliving any one of them. Home: `docs/agents/agent-seat-model.md`.
- **session** — one running conversation occupying a seat; sessions end and are replaced, the seat persists. Home: `docs/agents/agent-seat-model.md`.
- **slice** — one numbered increment of a build plan, built and landed on its own. Home: `docs/agents/agent-seat-model.md`.
- **stumble** — a place a zero-context reader misreads or cannot resolve in proposed instruction text; fixed before the user sees the text, or brought to him with the item. Home: `.claude/skills/walk-me-through/SKILL.md`.
- **supervisor** — `scripts/handoff-supervisor.py`: the per-seat process that launches a session, replaces it when it hands off, and exits when its agent stops without handing off; one per seat, lock-guarded. Home: `docs/agents/agent-seat-model.md`; design in `docs/cross-project/fast-handoff-design.md`.
- **tier** — in the cold-read grid, the model-quality axis of a cell: `good` or `floor`. Home: `scripts/cold-read-grid.py`. (The word also carries three other senses — see CONFLICTS.)
- **trailer** — the `Gatekeeper-*` lines the gatekeeper writes into every check-in commit: the whole machine-readable record (origin, agent, digest, import, issue); git history is the record, `git log --grep` the view. Home: `docs/cross-project/git-gatekeeper-design.md` § The trailer.
- **walk** — delivering complex material one item at a time, advancing only on the user's word; a deciding walk is a working review whose decisions are captured in their durable homes before advancing. Home: `.claude/skills/walk-me-through/SKILL.md`.
- **walk ledger** — the machine-local, gitignored disposition file in `walk-ledgers/` used when a walk has no durable anchor; its one reader is the interrupted walk resuming, and decisions survive only in their durable homes. Home: `.claude/skills/walk-me-through/SKILL.md` (as the "tmp-file ledger").
- **walked approval** — the user's approval given item by item through a walk, never one yes to a bundle; recorded by quoting his words into `.walk-approved`. Home: `docs/agents/agent-seat-model.md`.
- **zero-context reader / zero-context read** — the standard reader durable artifacts are written for (a fresh agent whose context floor is CLAUDE.md + prompt), and the single fresh-subagent check run on proposed instruction text before the user sees it. Home: `docs/cross-project/nedschorus-ai-native-software-development.md` § Standing decisions (the standard); `.claude/skills/walk-me-through/SKILL.md` (the check). (Distinct from the eight-cell cold read — see CONFLICTS.)

# Review appendix (for the user — not part of the eventual page)

## (a) CONFLICTS — one term, two meanings

1. **gatekeeper (bare)** — the seat vs the program. `docs/agents/agent-seat-model.md` rules the double duty deliberate ("`gatekeeper` naming the seat that works on the git-gatekeeper is therefore deliberate, not a collision to fix", user-ruled 2026-08-13), yet the user himself later misread the bare word as the seat and corrected an agent: "the project's name is `git-gatekeeper` … the bare word collides with the merge-lane seat's informal gatekeeping role" (`walk-ledgers/2026-08-25-md-pipeline-consolidated-walk.md`, 2026-08-28 entry). The page should instruct: full name for the program, bare name only as a seat address.
2. **tier** — four live senses: the grid's model-quality tier `good`/`floor` (`scripts/cold-read-grid.py`); the reasoning-effort tier `xhigh`/`max` ("the effort tier — xhigh vs max, per runtime", `docs/agents/sanity-checker-instructions.md`); the cooperative hook tier C6 ("the cooperative tier (C6)", `docs/cross-project/git-gatekeeper-design.md`); and, in the merge-lane verify pass, a closable class a claim ranges over ("exhaustion needs a closable tier", `~/.claude/handoffs/merge-lane-dialog-0019-complete.md` — same file as sense one).
3. **ladder** — three ladders share the word: the fix ladder (retry → stronger model → the boss, `docs/cross-project/git-gatekeeper-design.md`); the enforcement ladder (impossible → … → text, `docs/cross-project/fleet-git-worktree-working-model.md`); and the automation ladder ("manual → script-you-run → automation, each step earned by evidence", `docs/cross-project/nedschorus-ai-native-software-development.md` § Standing decisions and `docs/cross-project/comms-bridge-spec.md` "EARNED automation per the ladder" — the bare phrase "the ladder" there resolves only by context).
4. **cold read vs zero-context read** — two different instruments one phrase apart: the eight-cell grid (`.claude/skills/cold-read/SKILL.md`) and the single fresh-reader pre-user gate (`.claude/skills/walk-me-through/SKILL.md` line 38); `docs/drafts/cold-read-tooling-design.md` § 4 distinguishes them explicitly ("a separate surface for a separate moment, not a reduction of the eight-cell grid"), but casual usage blurs them.
5. **scrub** — stale/live split: the retired founding plan (`git show 615a230:docs/cross-project/nedschorus-founding-plan.md`) still assigns the "handoff scrub" its queue-depth reporting duty, while `docs/cross-project/git-gatekeeper-design.md` records the "handoff scrub" anchor as retired ("replacing the retired 'handoff scrub' anchor", ruled 2026-08-12) and `docs/cross-project/fast-handoff-design.md` moved the queue-status line onto the ignition prompt.
6. **draft** — the `draft` issue label (queue membership, the boss's review queue) vs `docs/drafts/` (in-progress working documents) vs "draft for review" in commit messages; three related but distinct mechanisms sharing one word, defined only for the label.
7. **seat (loose use)** — defined strictly in the seat model, which itself flags one deliberate loose use (the Mac-side agent "is not one of the seats defined here"); and `docs/agents/ghi-instructions.md` records a live contradiction: `docs/issues/46-ghi-info-agent-design.md` calls ghi-info a seat while the seat model defines exactly seven and does not list it ("Both cannot be right … report it").
8. **audit** — the gatekeeper's built `audit` subcommand (branch-protection check) vs the deleted trailer-absence audit; `docs/agents/gatekeeper-instructions.md` has to disambiguate in-line ("Unrelated to the `audit` subcommand"), a sign readers hit the collision.
9. **arm** — (a) an experimental condition ("the item-by-item arm is the unmeasured one", `~/.claude/handoffs/MD-skills-dialog-0007-complete.md`, 54 transcript uses); (b) activating a standing watcher ("re-arm three watchers from `walk-ledgers/merge-lane-watchers.md`", `~/.claude/handoffs/merge-lane-dialog-0019-complete.md`).
10. **anchor** — (a) the walk's disposition document (defined, `.claude/skills/walk-me-through/SKILL.md`); (b) textual alignment ("two cells' quoted phrases anchor within 3 lines", MD-skills transcript); (c) an edit's match target ("Assert your anchors when editing", git-infra transcript).
11. **lane** — (a) the merge pipeline ("if the review requirement ever wedged the lane", git-infra transcript); (b) the merging seat as an actor ("hand it to merge-lane for the approve", MD-skills transcript); (c) any standard route ("through the normal lane", same file); plus spelling drift across "merge lane", "merge-lane", and "merge seat".
12. **brief** — (a) a seat's instruction file (`docs/agents/agent-seat-model.md`); (b) a dispatched agent's build spec ("The builder's spec is `…/BRIEF.md`", MD-skills transcript); (c) a reviewer's fixed commissioning document ("a fixed brief the commissioning seat doesn't get to tailor", merge-lane transcript).
13. **floor** — (a) the cheap model tier (`scripts/cold-read-grid.py`); (b) a minimum bar ("must pass the two-question floor", MD-skills transcript; the extractor's "word-floor tail", `docs/cross-project/fast-handoff-design.md`).
14. **cell** — (a) one grid coordinate ("a separate instrument, never a grid cell", merge-lane transcript); (b) a named prompt script outside any grid ("`scripts/cold-read-codex-cell.py --cell fast-clarify`", MD-skills transcript).
15. **capture** — (a) recording a decision in its durable home (`.claude/skills/walk-me-through/SKILL.md`); (b) losing tool output ("an intermittent capture loss", git-infra transcript).
16. **drain** — (a) the boss emptying a queue (`docs/cross-project/nedschorus-ai-native-software-development.md`); (b) concurrent jobs finishing ("once the fan-out drains", MD-skills transcript).
17. **marker** — (a) the approval file `.walk-approved` (merge-lane transcript, matching the defined sense); (b) harness format strings ("record types, field names, marker strings", mac-ubuntu-bridge transcript).
18. **queue** — (a) a project queue with a drain (defined); (b) the harness's internal message queue ("it exists in the JSONL only as a `queue-operation`", mac-ubuntu-bridge transcript).
