# Build the cold-read-fast-read refusals and reads the user ordered for all lasting agent-facing prose

## Why

On 2026-10-11 the user said: "Almost every prose info or instruction file (not log) should be at least fast cold read." On 2026-10-12 he ordered the refusals that enforce this built at once, with the cold-read-fast-read as it ran then and no lighter mode. A month later none of them is on main, and twelve texts on main still say the opposite of a user-ruling in force. The reason the read must come before the push is the user's, from M item 3: pull request reviewers do not review Markdown, so merge-lane-2 does not catch unread prose ("the merge agent/process assuming that MDs are fully vetted, and so they skip reviewing them!").

1. **The pre-push read refusal.** M items 1, 2 and 7 (M:7, M:11, M:119); GN item 19 (GN:58). `scripts/git-client-side-hooks/pre-push` gains a refusal, a soft-block: a push is refused until one file holding all its commit messages and changed program messages has a cold-read-fast-read record of that exact text, the hook assembling that file itself so that the text read is the text pushed (`nc-systems/general-tools/python-source-tool-message-to-agent-string-collector-common.py` already finds the changed program messages for `scripts/pull-request-review-plan.py`), or until a one-push marker file gives the reason no read is needed. A later user-ruling settles that after a cold-read-full-run, a cold-read-fast-read of the rewrite is enough (item 1 of approval-walk cold-read-skill-rebuild-so-programs-do-the-mechanical-steps-2026-10-23, approved 2026-10-26, its walk-minutes lines 8 and 12). 10. **Three rounds of reads after fixes.** M item 9 (M:155); GN item 20 (GN:60). A fixed text is read again after each fix, until a read has no finding the agent must act on or three reads have run. The push refusal accepts only a read of the exact text pushed. When the third read still finds a misreading that would make an agent act wrongly, the text goes to the user; a subagent sends it to the agent that dispatched it, which tells the user. A user rewrite after the third read gets one cold-read-fast-read, which clears the refusal; a misreading that read finds goes to the user, not into his words. Two texts on main allow one read: the instruction-file guard's sentence "revise the text from the findings once, then put the change to him" (`.claude/guard-hooks/instruction-file-guard.py:77-84`), and /cold-read steps 2 and 8, which give a rewrite after a cold-read-full-run one cold-read-fast-read. **Both need the user's approval of the new text.**

12. **How a writer acts on a read's findings.** M item 15 (M:95, M:102, M:117). The user's own text replaces /cold-read step 4's sentence "Fix what it misread, revise the text to resolve its findings, add what is missing." His text, as approved at M:102: "Simplify to clarify. Be careful about adding statements: every word subtracts attention and adds complexity. Narrow statements to minimize the need for exceptions. To reduce objections, use shorter, simpler statements. To minimize or remove ambiguities use this project's glossaries and naming conventions or reword with more direct and specific expressions. Before you fix a passage, ask whether the passage is needed at all; is it vital; does it make the prose easier or harder to understand and act on. Where a reader misread a passage, change the words so the meaning is clear. Push toward ease of understanding and clarity of action. Act on a finding about something the text leaves out only when it is important and the missing info is both known and clear to you, yet unknown and unclear to other agents. If something is still an unknown, an open question, do not invent an answer. You need not act on every finding - only the ones that push to clarity from what you know. The agents reading the revised text will not have your context." Step 7's "rewrite the document to fix the findings they raised" becomes "revise the document as step 4 says" (M:117). `nc-systems/cold-read/cold-read-fast-read.py` prints the user's text after every report; GHI [Rebuild the /cold-read skill so its programs do the mechanical steps and print each instruction when the agent needs it](https://github.com/nedschorus/nedschorus/issues/2158) already plans for that program to print its next step (its table, step 4), so build the printing there, with this text, rather than twice.
