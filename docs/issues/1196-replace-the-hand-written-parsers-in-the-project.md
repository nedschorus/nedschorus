# Replace the hand-written parsers in the project's hooks and scripts with real parsers

Many of the project's hooks and scripts read structured text, such as shell commands, Markdown, Python source and the output of `git` and `gh`, with regular expressions and string splitting instead of a real parser, and they get ordinary input wrong. This GHI replaces those hand-written parsers with real parsers, built as shared modules so that every program reads a language the same way, and fixes the other hook defects the same audit found.

## Why

An audit of origin/main at commit ca26365208c2, 116 code files, found 169 hand-written parsers: 12 HIGH (wrong answers seen or likely in real use), 51 MEDIUM, 106 LOW. Most were confirmed by running the code on the failing input. The report is the supporting document `nedlern@ned-box:/home/nedlern/nedschorus-logs/seats/reboot-test/detection-and-correction-techniques-research-2026-10-10/hand-written-parsers-audit.md`. The worst:

- **The Bash guards' shared shell reader**, `tokenize_command_list` in `scripts/synthetic-keystroke-guard-hook.py`, used by all four PreToolUse Bash guards, lets a `cd` inside `$(...)` or `( ... )` change the directory later commands are checked in. For `(cd /tmp/other && make); git push --force-with-lease origin feature`, the force-push guard asked GitHub about the wrong repository's pull requests.
- **The force-push guard**, `scripts/force-push-with-open-pull-request-guard-hook.py`, allowed `if git push -f …; then`, `timeout 60 git push --force-with-lease …`, `{ git push -f …; }`, `bash -c 'git push --force …'` and `git push --mirror`.
- **The keystroke guard** does not see `tmux send-keys` sent through `ssh ned-box <<'EOF'`, the ordinary form from the Mac, nor after a tmux `\;` command separator.
- **The GHI redirect guard**, `.claude/hooks/ghi-issue-write-redirect.py`, matches `gh issue` words anywhere in the command, even inside quotes, so it refuses a command that only pipes JSON containing those words.
- **`scripts/ghi-issue-write.py`** treats any GHI body containing the text `ghipair` as its own, and replaced a prose body with links.
- **The backup write guard**, `.claude/hooks/backup-and-snapshot-write-guard.py`, matches paths by prefix, and a Write under Timeshift's mount `/run/timeshift/<pid>/backup/…` was allowed.
- **Markdown readers**: the coverage-type scan in `scripts/design-to-main/design-to-main-state-machine.py` misses the project's own worked example and then passes silently; `parse_judge_report` in `nc-systems/cold-read/cold-read-restater-judge-runner.py` drops list and bold items; `scripts/md-drift-lint.py` reports wrong findings on main today; `scripts/bare-number-citation-in-markdown-and-agent-reply-warning-hook.py` and `scripts/style-guide-word-checker-markdown-edit-hook.py` scan only the edited text, so an Edit that closes a code fence hides the prose after it.

Earlier GHIs record the same failure one case at a time: GHI [The Bash guards' shared shell reader does not read inside a double-quoted command substitution](https://github.com/nedschorus/nedschorus/issues/710), GHI [The style-guide-word-checker misses prose and flags code in six Markdown shapes](https://github.com/nedschorus/nedschorus/issues/1043) and GHI [Sort the 60 standing md-drift-lint findings into forward references and stale citations, then fix the stale ones](https://github.com/nedschorus/nedschorus/issues/572). The root cause is the same in each: the project has no shared, real parser, so each program writes its own.

## The work, in order

Each step is a build-slice on its own topic branch, tested, and merged before the next starts.

1. **git output.** Done: PR [Shared git-output module: 21 programs read git's -z output instead of splitting it by hand](https://github.com/nedschorus/nedschorus/pull/1210) merged on 2026-10-12. A shared module, `nc-systems/general-tools/git-machine-readable-output-runner-and-parser-common.py`, that runs `git` in its machine-readable forms (`-z`, `--porcelain=v2`, `--format` with NUL separators, `git push --porcelain`) and returns structured values. The programs the audit lists as splitting `git` path lists or reading `git`'s English error text move onto it in the same pull request. That pull request also carries `scripts/obsolete-file-edit-warning-hook.py`, whose rebase advice led an agent to rebase a pushed head commit in fleet-restart-at-login's audit of messages whose instructions fail when followed (`nedlern@ned-box:/home/nedlern/nedschorus-logs/analysis/hook-messages-instructions-that-fail-when-followed-audit-2026-10-11/synthesis.md`, section 5); fleet-restart-at-login rewrites that hook's messages once it merges.
2. **Shell commands.** Install `tree-sitter` and `tree-sitter-bash`, which need compiled code, per user on both machines into the `python3` the hooks run, from a requirements file that pins their versions, which this step adds to the repository under a name chosen by the naming page: `python3 -m pip install --user --break-system-packages -r <that file>`. A plain `--user` install is refused on ned-box (`externally-managed-environment`, PEP 668); the install into the user's site directory leaves the system's own packages untouched. The daily maintenance of GHI [Daily maintenance in one daily step, starting with a daily check of every wiki page](https://github.com/nedschorus/nedschorus/issues/1058) reports a library that is not installed. The shell module, on tree-sitter-bash; then `scripts/synthetic-keystroke-guard-hook.py`, `scripts/force-push-with-open-pull-request-guard-hook.py`, `.claude/hooks/ghi-issue-write-redirect.py`, `scripts/search-file-argument-read-as-option-guard-hook.py`, the cron matcher in `nc-systems/general-tools/install-scheduled-jobs-on-this-machine.py` and the command reading in `scripts/unvalidated-negative-result-check.py` (`split_on_top_level`, `pipelines_of`, and the `shlex.split` calls in `search_pattern_and_rest`, `control_refusal` and `run_control`) move onto it, and `tokenize_command_list` is deleted; that check's imitation of ugrep's ignore rules is replaced in step 5. The checks about git move into the pre-push hook and GitHub branch protection, as item 13 decided; a pre-push check that refuses a non-fast-forward update to a branch with an open pull request also covers agent-sessions running in Codex, which run git hooks. The Codex CLI's command readers ([codex-rs/shell-command/src/bash.rs](https://github.com/openai/codex/blob/a9b0815167c27ab13719dd12d13b63e02b70d221/codex-rs/shell-command/src/bash.rs), Apache-2.0) are a model: one reader proves a command holds only literal words; the other collects what it can, and must never be used to prove safety. Their test cases, heredocs included, join the 80,630 real commands and the required test case above. The tmux kill guard of PR [tmux kill guard: refuse kill-server and kill-session that name no server](https://github.com/nedschorus/nedschorus/pull/1191), merged on 2026-10-12, `nc-systems/general-tools/claude-code-tmux-kill-server-and-kill-session-missing-server-selection-refusal-hook.py`, moves onto the module too.
3. **Markdown.** The Markdown module, on markdown-it-py, a library written only in Python. markdown-it-py and its dependency `mdurl` are listed at pinned versions in the same pinned requirements file as tree-sitter, and install themselves the same way: a program that imports markdown-it-py and finds it missing installs the pinned file, and tells the agent to tell the user only when that install fails. The coverage-type scan, `scripts/md-drift-lint.py`, `scripts/style-guide-word-checker.py` and its edit hook, and the bare-number citation hook move onto it. The two PostToolUse hooks parse the file on disk and keep only the lines the edit wrote, from `tool_response.structuredPatch`, as `scripts/markdown-edit-hard-wrapped-paragraph-reminder-hook.py` already does. The bare-number citation hook also checks the agent's reply in the same turn, through a Stop hook (chore 7 of GHI [Move mechanical agent chores into programs and hooks](https://github.com/nedschorus/nedschorus/issues/1036)). The cold-read judge answers in JSON instead of Markdown, so `parse_judge_report` reads JSON; its owner, agent-seat mac-claude, is told first.
4. **Python source.** The collector, which branch `python-edit-changed-agent-facing-message-check-reminder-hook-topic-branch` of agent-seat reboot-test moves to `nc-systems/general-tools/python-source-agent-facing-string-collector-common.py`, is widened to the message patterns the audit lists: returned messages, `sys.exit("…")`, `parser.error`; this step starts after that branch merges to main. The number lookups by regular expression over source move to `ast` or `tokenize`.
5. **Fixes that need no module**, each its own pull request: `ghipair` matched by `re.fullmatch` of the placeholder's whole pattern; the backup guard compares `os.stat().st_dev` with the backup disk's; the empty-search check runs the real `ugrep`; `scripts/recover-crashed-seats.py` returns its recovery verdict as a structured value instead of English that a second program reads back; transcript records classified by their JSON fields.
6. **Hook defects that are not about parsing**, from the audit's section "Hook improvements that are not about parsing", one pull request per hook: a hook that fails silently or exits 0 on a crash reports the failure to the agent, as CLAUDE.md's rule on reporting failures requires; hooks without timeouts get them; dead code goes.
7. **The main-gatekeeper**, `nc-systems/main-gatekeeper/main-gatekeeper.py`, last: it is dormant, so its findings harm no agent until it is switched on.

## What is not decided

1. **A missing parser.** Settled by the user on 2026-10-12: when a Bash guard cannot import `tree-sitter-bash`, it installs the pinned requirements file with step 2's install command, then checks the command as usual. If the install fails, the guard lets the command through and tells the agent to tell the user that the parser is missing, with what the install printed.
2. **The `MultiEdit` matcher.** The three Edit and Write guards do not match `MultiEdit`; whether Claude Code still offers `MultiEdit` is for the user to settle before step 6 touches it.
3. **Linters.** Neither machine has ruff or ShellCheck. A ruff setup pinned to 0.16.1 was ratified on 2026-07-31 but never built. The trawl (`nedlern@ned-box:/home/nedlern/nedschorus-logs/seats/reboot-test/detection-and-correction-techniques-research-2026-10-10/linters-trawl.md`) found no bugs that fail at run time and five minor real problems, and recommends ruff 0.17.0 with rules `F,E9,B,PLE,EXE001,BLE001,S110` and ShellCheck, as a PostToolUse hook that reports without fixing and as a test suite, and no `ruff format`. Codex's research on ruff with AI agents (`nedlern@ned-box:/home/nedlern/nedschorus-logs/seats/reboot-test/detection-and-correction-techniques-research-2026-10-10/ruff-with-ai-agents-codex-research.md`) gives the command that reports without fixing.
4. **Codex.** Codex has lifecycle hooks, read from its own `hooks.json`, and this project has configured none. Whether this GHI's guards also run under Codex, through an adapter, is a decision of its own; the facts are in `nedlern@ned-box:/home/nedlern/nedschorus-logs/seats/reboot-test/detection-and-correction-techniques-research-2026-10-10/codex-open-source-components-for-nedschorus-review.md`. The Codex patch tool passes the whole patch as `{"command": <patch>}`, with no `file_path`, so a guard keyed on `file_path` would miss Codex's writes.
5. **The shell that runs a command on the Mac.** On the Mac, Claude Code's Bash tool runs agent commands in zsh, through `eval`, not in bash, so every guard reads Mac commands with a bash grammar. The evidence: the Mac transcripts mirrored on ned-box under `nedlern@ned-box:/home/nedlern/nedschorus-logs/transcripts/mac/projects` hold 2,399 tool results reading `(eval):N: no matches found`, which is zsh's message for code run through `eval`. The two shells differ on some words: `$'\cA'` is the byte 0x01 in bash and the text `cA` in zsh, and globbing and word splitting differ more widely. No recorded command changes a guard's verdict today. Should the reader follow the shell that runs the command, and if so, how?
