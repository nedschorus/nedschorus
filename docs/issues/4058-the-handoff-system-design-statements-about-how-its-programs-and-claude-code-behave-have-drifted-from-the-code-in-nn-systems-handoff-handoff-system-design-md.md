# The handoff-system design's statements about how its programs and Claude Code behave have drifted from the code, in `nn-systems/handoff/handoff.system.design.md`

## What is wrong

`nn-systems/handoff/handoff.system.design.md` says it carries only what code cannot: the user-rulings and their reasons, the verified facts about Claude Code, the known holes, and the session-handoff file format, because "mechanism prose drifts". It still describes how its programs work in many places, and those descriptions have drifted from the code and from each other. By section:

- **"What a reincarnate-seat kills, and how work survives it".** It names the option `--background-task-wait-minutes` as current twice, after saying the wait-limit table replaced it; `grep -c background-task-wait-minutes scripts/handoff-context-threshold-hook.py` printed 0 on main at 55626cb48. It says "The threshold hook holds the reincarnate-seat while any subagent started with the Agent tool is in flight", while the User-rulings entry "A reincarnate-seat waits for the agent-session's running subagents, up to a ceiling" says both that and that the handoff-deferral waits only for the work in flight when it began. It says the hook judges a background Bash task by completion notifications, while the next paragraphs say the hook reads Claude Code's `background_tasks` list. It states a rule for a subagent waiting on its own background work (user-ruled 2026-10-30), says neither the threshold-hook nor the writer applies it, and names no program that does. It says a subagent still working when its agent-session is replaced keeps its uncommitted edits as a work-snapshot, though edits from a tool call killed before it returns may have none. It tells the agent to name a detached headless job "and these costs" in the next step, which can mean restating four fixed facts in every such next step, or naming only what they mean for this job.
- **User-rulings and Known holes about crash recovery.** "the agent-crash-watcher does check every ned-box agent-seat each minute", though Known holes says it restarts only an agent-seat it has seen running since boot and not restarted in the last hour. "a launcher, not the writer script, starts each handoff-supervisor", though `scripts/recover-crashed-seats.py`, `scripts/resupervise-seat.py` and the handoff-supervisor's own restart on main's code start one too. "Every path on which the handoff-supervisor chooses to stop after its agent-session has exited writes the exit record", though the reports find two handled stops in `nn-systems/handoff/handoff-supervisor.py` that write none: an unreadable transcript before a resume, and a session-handoff with no terminal. "the user is shown a notice instead when the agent-seat left down is fleet-restart-at-login itself" can mean instead of both tasks or instead of the second only; the agent-crash-watcher still writes the first. A sentence whose condition is that the agent-session died without a session-handoff then branches on a session-handoff waiting. "(unaffected by a dialog box Claude Code shows at startup)" sits against Known holes' trust dialog that stops a resume. And "sending itself SIGTERM trips the safety classifier (exit 143)" does not say what exits with code 143.
- **The reference-checkout entry (user-ruled 2026-11-05 and 2026-11-08).** "Only when the program fails does the successor get the not-restarted notice", though a failed `os.execv` or a handoff-supervisor not running from the reference-checkout also gives it; and nothing says what later finds the branch that `nn-systems/handoff/handoff-reference-checkout-back-on-main-after-pushing-leftovers-to-a-branch.py` pushed the leftovers to, since "neither the successor nor the user is told".
- **The first-prompt list and the task prune.** The design does not say what `nn-systems/handoff/agent-seat-worktrees-and-branches-with-no-pull-request-first-prompt-list.py` lists when the task list or a task's metadata cannot be read: every entry, none, or a failure. Its sentence on the writer's task prune lists copy, remove and keep, then "first raises `.highwatermark`", so the order cannot be read from it; the writer's docstring says the mark is raised before anything is removed.
- **Verified facts about Claude Code.** "Every assistant transcript record carries `message.usage`" and "can therefore be computed ... in any agent-session", though the hook skips records without usage; "ONE TO THREE times, never four" from three transcripts; a monitor's `taskId` and `persistent`, while the hook tells a monitor by `timeoutMs` and a background Bash task by `backgroundTaskId`; a multi-id specimen said to come from a previous agent-session that came from the same one; and the unknown-model default of 200K called "the safe direction", which it is not for a model with a smaller window.

The findings come from the cold-read-full-run `nedlern@ned-box:/home/nedlern/nedsnodes-logs/cold-read-records/handoff.system.design-2026-11-20-6`, which read the design for a one-entry edit and deferred every finding on text that edit did not change. Its `cold-read-triage.md`, in that directory beside the reports named here, gives each of these findings the link of the GHI filed from this file: `agy-hunt-gemini-4-argon-high.md` 2, 3, 5, 6, 14, 16, 18, 20, 21, 22 and 23; `claude-hunt-deep.md` 1, 7, 8, 9, 12, 13, 21, 22, 25, 29, 34, 37, 38, 39 and 41; `claude-hunt-second-strongest-model.md` 1, 6 to 9, 13 to 20, 28, 31, 32, 38, 39, 43, 44 and 46; `codex-hunt-deep.md` 7, 8, 19, 21, 22, 23 and 24; `codex-hunt-second-strongest-model.md` 1, 2, 4, 10, 11 and 12; `claude-terminology-deep.md` 14. Each report quotes the design and names the code it checked.

## Why it matters

An agent that follows the design to change a wait passes an option the hook rejects, and the hook runs at every Stop. An agent that dispatches a subagent during a handoff-deferral cannot tell whether it holds the session-handoff or dies at it. A reader writing transcript code from the Verified facts table, or expecting a crashed agent-seat back within a minute, is misled. The design calls itself the record of what code cannot say, so a reader does not expect to have to check it against the code.

## Next action

The agent-seat agent-instructions-editor, which edits the files the instruction-file guard protects, first asks the user whether the design keeps these descriptions of mechanism at all, or keeps only the user-rulings, facts and holes and points to the code for the rest, since the design's own opening paragraph records his ruling that "mechanism prose drifts". Whatever he answers, each statement above is corrected or removed against the code on main; for the Verified facts, against the transcripts in the log-store, counted by a script, not by reading. Where the code and a user-ruling disagree, it brings him a recommendation: that the threshold-hook apply the 2026-10-30 rule for waiting subagents, since it already reads the subagents in flight; whether the unknown-model default should stay 200K; and that the reference-checkout program write a task or a user-alert naming the branch it pushed, or that the first-prompt list show such a branch. It proposes with them a test that fails when an option, constant, field or path the design names in backticks is gone from the program it is attached to, which would have caught `--background-task-wait-minutes`. Then one pull request on the design carries every correction and every ruling, and gets the cold-read-full-run the /cold-read skill gives a design; a ruling that changes code goes in its own pull request with its test.
