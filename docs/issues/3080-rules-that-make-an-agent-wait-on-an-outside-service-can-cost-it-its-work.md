# Rules that make an agent wait on an outside service can cost it its work

## What this is

Eight rules in this repository tell an agent to stop, or to wait, until something outside its control comes back: Gemini, GitHub, ned-box, a running subagent, or the user; a ninth case, case 4, was a defect in this project's worktree cleanup that removed records still waiting to ship. While an agent waits, its work can be lost: a handoff can come at the context ceiling, a worktree can be removed, or a restart can leave an agent-seat down. Each case below gives the rule as it reads on main today, the exception first proposed for it, and the user's later rulings on its subject.

The nine cases come from one search made on 2026-10-15 by a Claude subagent and a Codex run, both from one brief on origin/main at 15c73e52. Their comparison is `nedlern@ned-box:/home/nedlern/nedschorus-logs/seats/ned-box-helper/rules-that-make-an-agent-wait-on-an-outside-service-claude-and-codex-compared-2026-10-15.md`. The user asked for that search when he approved item 21 of the approval-walk glossary-naming-rule-reader-categories-and-open-questions-2026-10-13: "this problem may exist in other forms please have codex and a Claude check". Item 21 approved one exception: when Gemini's quota is out, an agent-session that must hand off does so with a next-step file that has had no fast read, says so in that file, and its successor gives the file its fast read once the quota is back.

## Why

An exception that lets the agent carry on, and record what it still owes, keeps the work. Waiting loses it whenever the outside service stays down longer than the agent-session can wait.

## The nine cases

### Exceptions that let an agent do without an outside part

1. **A failed cold read stops the agent.** `.claude/skills/cold-read/SKILL.md`, step 3: "If it prints a line opening FAILED, tell the user and stop." Proposed: write item 21's exception into the skills; no text on main records it (search: `quota`, `unread` and `fast.read` in `.claude/skills/handoff/` and `nc-systems/handoff/handoff-write-and-check-supervisor.py`, no match for item 21's exception). Since 2026-10-25, FAILED comes only when Gemini and Sonnet have both failed.
2. **A name cannot be used until a fetch of main succeeds.** `docs/nedschorus-wiki/nedschorus-how-to-choose-a-name-for-files-code-and-glossary-terms.md`, line 89: "Run `git fetch`. If it fails, stop this check, tell the user that main could not be checked and why, and do not use the name until the check has run." This depends on GitHub and the network. Proposed: use the name, record "name not checked against main" in the commit message and the next-step file, and the successor runs the check before the pull request opens. No later ruling found.
5. **The fast-read reminder hook asks again while the fast read keeps failing.** `scripts/cold-read-fast-read-due-for-linked-document-reminder-hook.py` asks for a fast read of each document the last reply linked that has none on record, and "a read that failed after freezing its target leaves no report and does not count", so every turn that links the document asks for another read that fails. Proposed: after one failed read, remind once and put "fast read owed" on the task list. Since 2026-10-25 this happens only when Gemini and Sonnet both fail. No later ruling found.
6. **An approval-walk cannot start without its fast read, and a GHI cannot be filed without its /cold-read.** `.claude/skills/walk-me-through/SKILL.md` runs `nc-systems/cold-read/cold-read-fast-read.py` on the draft before the walk-document is written; `.claude/skills/ghi-write/SKILL.md`, step 4: "Give the GHI-MD its /cold-read before running create-GHI or edit-GHI on it." Proposed: go ahead, mark the text "not cold-read: <FAILED line>", and read it once the fast read works again. Since 2026-10-25 this happens only when Gemini and Sonnet both fail. No later ruling found.
7. **Saving scratch worktrees before a reboot depends on ned-box.** `scripts/save-uncommitted-scratch-worktrees-before-reboot.py`: "When ned-box cannot be reached, every save from the Mac fails this way." It accepts `--destination` with a local path, but the restart steps in its docstring do not say to use it. Proposed: when ned-box cannot be reached before a restart that cannot wait, save to the Mac's own disk and ship later. This is the case that `CLAUDE.md` rules against today: "Do not find another way to do a step that needs ned-box: leave that step until ned-box is fixed or the user says otherwise". No later ruling found.

### Changes to this project's own code

3. **A running subagent holds the handoff until the context ceiling.** `scripts/handoff-context-threshold-hook.py` counts a background task as finished 75 minutes after its launch, "though not a subagent". Proposed on 2026-10-15: subagents get the same limit, and the successor restarts the subagents the session-handoff names. Later rulings, recorded in `nc-systems/handoff/handoff-design.md`: a session-handoff waits for running subagents up to the ceiling (user-ruled 2026-08-27); on 2026-10-30 he narrowed it, so a subagent waiting on its own background work counts as running only while its transcript was written in the last 5 minutes or its background task started less than 75 minutes ago; the session-handoff now names each subagent still working, and the successor decides whether to start it again. What is left is the proposal to cap every subagent, which would change his 2026-08-27 ruling.
4. **An unshipped cold-read-record was deleted with its worktree.** Fixed: since commit ae9750751 (2026-10-19), `scripts/clean-worktrees.py` ships each record under a worktree's `cold-read-records/` before removing the worktree, and keeps the worktree when the shipping fails; `.claude/guard-hooks/git-worktree-remove-cold-read-record-and-sanity-check-record-ship-to-log-store-first-guard-hook.py` does the same for a hand-typed `git worktree remove`. On 2026-11-01 a worktree with uncommitted work was still removed, by a handoff-supervisor's cleanup, and restored from a work-snapshot (minutes of ned-box-helper-handoff-wait-limits-by-task-kind-2026-10-31); GHI [Restore and discard commands in `nc-systems/handoff/uncommitted-work-snapshots.py` replace the restore steps an agent runs by hand](https://github.com/nedschorus/nedschorus/issues/2539) covers restoring such work.
8. **The reboot-save procedure waits for busy agents and for the user.** `scripts/save-uncommitted-scratch-worktrees-before-reboot.py`, step 1: "If anything is busy, wait for it to finish or let the user decide; do not stop another agent's work yourself. Wait for the user's go-ahead before going on." Proposed: when shutdown is about to happen, save what is there without stopping other agents. No later ruling found.
9. **Unattended crash recovery leaves an agent-seat down after any recorded exit.** `scripts/recover-crashed-seats.py`, rule 2a: "With no leftover session, nobody to ask or a no leaves the seat down". Proposed: when no one is there to ask, resume an agent-seat whose recorded exit was a failure, not a stop on purpose. Since then, the handoff-supervisor resumes an agent-session that exits with a non-zero code when its last resume brought new work, and `nc-systems/handoff/handoff-agent-crash-watcher.py` tells the user about an exit its supervisor recorded without resuming, other than a stop on purpose (both per the project glossary). GHI [recover-crashed-seats.py: the six changes ruled 2026-09-02 — exit record, process-identity liveness, parking marker, verified restart, by-hand resume, window](https://github.com/nedschorus/nedschorus/issues/242) holds the user's earlier rulings on this script.

Both searches also named three cases they were unsure of, left out here. Two are no longer on main: `scripts/ghi-info-ask.py`, which said "Do not file or edit the issue until he answers", is gone, and no file under `scripts/`, `nc-systems/` or `.claude/` names the flag `--dont-restart` (searched with grep, 2026-11-10). The third is a session-handoff the user asks for and then leaves the agent-session waiting on him while he is away.
