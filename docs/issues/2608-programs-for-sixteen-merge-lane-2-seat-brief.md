# Programs for sixteen merge-lane-2 seat-brief steps that need no judgment

## What is wanted

merge-lane-2 reviews and merges every pull request. Its seat-brief, `nedlern@ned-box:/home/nedlern/agents/merge-lane-2/CLAUDE.local.md`, a file git does not track, asks it to do by hand sixteen steps that need no judgment: each is a count, a lookup, a check of a text or a fixed sentence to write. Each is listed below with the sentence of the seat-brief it would replace and what the program would do. CLAUDE.md's bullet that begins "Build code-prompt-code" says such a step goes in code, because code runs the same way each time and a step merge-lane-2 must remember is skipped when it forgets.

Each idea is its own piece of work: it can be built, and its seat-brief sentence removed, without the others. Line numbers are those of the seat-brief on 2026-11-04; the seat-brief is being rewritten, so find a sentence by its words when the number has moved.

## The review program and the program that posts the review

1. **The fixed closing sentences of a review.** Seat-brief line 98: "A review that carries findings ends with this sentence, word for word: …"; and lines 94 to 96: "Also state plainly in the review whether an independent reviewer was used or whether this seat reviewed it alone". Item 2 of the approval-walk rewrites the second as "State plainly in the review which reviewers ran, which the review tier called for but did not run, or that the review tier called for none." Today merge-lane-2 posts its review by hand with `gh pr review`. A program that posts the review appends the fixed sentence whenever the review carries findings, and writes the sentence on reviewers from the review tier `scripts/pull-request-review-plan.py` prints and from which reviewers' reports exist.
2. **A finding that does not say whether the pull request makes the defect happen.** Seat-brief line 338: "The reviewer says, in its finding, whether this pull request makes the defect happen … When a finding does not say, ask the Claude reviewer". Item 16 of the approval-walk changes how the reviewer is asked: by resuming its session. The program that posts the Claude reviewer's review, `scripts/merge-lane-pull-request-claude-reviewer-headless-run-and-review-post.py`, refuses a finding on lines the pull request's diff does not add or change that does not say, and asks the reviewer again, so merge-lane-2 does not have to notice the gap.
3. **The brief specifications file.** Seat-brief line 45: "Then write the pull request's brief specifications file, a JSON list of one entry". Most of its fields are facts: `tag`, number, title, author, `claude_reviewer`, and for a fix-round `reviewed_before`, `previous_reviews` and `new_commits`. The run-without-merge program, `scripts/merge-lane-pull-request-worktrees-reviewer-brief-codex-review-and-head-tests-run-without-merge.py`, checks only that `claude_reviewer` is true or false, not that it matches the review tier. A program fills the factual fields from `scripts/pull-request-review-plan.py --json` and `gh`, and leaves merge-lane-2 only `tests`, `hazards` and `answer`. `scripts/pull-request-review-plan.py --brief-skeleton` already writes a Markdown skeleton of the reviewer's brief from the same facts, but not this JSON file. Build it on GHI 2505's records when they exist.
4. **The cold-read-fast-read commands for a pull request's messages.** Seat-brief line 41: "merge-lane-2 runs each cold-read-fast-read command that `scripts/pull-request-review-plan.py` prints for the pull request's messages, runs one itself on any new or changed message the script does not list, such as one in a shell script". The run-without-merge program runs the printed commands itself, and the plan's message collector also covers shell scripts.
5. **The Bash-guard verdict check.** Seat-brief lines 21 and 22: "run `python3 nc-systems/general-tools/bash-guards-verdict-changes-between-git-refs-on-recorded-commands-check.py` … Put both lists in the brief specifications file. In its posted review, the reviewer quotes each listed command and says whether its new verdict is right. The merge waits until every entry the check lists for the head being merged has that answer." The plan already detects a Bash-guard change, so the run-without-merge program runs the check and writes both lists into the brief, and `scripts/merge-gate.sh` refuses while a listed command has no quoted verdict in the review of the head being merged.
6. **The Codex review on every code pull request.** Seat-brief line 284: "this lane runs the project's own reviewer, `scripts/code-review-codex-cell.py`, on EVERY code pull request"; item 9 of the approval-walk rewrites it as "Run `scripts/code-review-codex-cell.py` on every code pull request, prose-only pull requests excepted". A pull request is a code pull request when any file it changes is not Markdown, so the review program starts the Codex review from the diff, or `scripts/merge-gate.sh` refuses a code pull request with no Codex review of its head commit. The gate checks for neither today. GHI [Deferred: pr-merge-decision-codex — machine merge-decision review; revisit after code-review-codex-cell accrues lane experience](https://github.com/nedschorus/nedschorus/issues/105), closed as not planned, was about a Codex review that decides the merge, not about making sure the Codex review runs.

## The merge gate and the merge

7. **The merge notice for open `#follow_up` issues.** Seat-brief line 31: "When `scripts/merge-gate.sh`'s pass output lists open `#follow_up` issues, add each to the merge notice with: …", a fixed sentence. The gate already has the list, so it, or the program that merges, prints the finished notice with the fixed sentence for each issue.
8. **Who approved the pull request.** Seat-brief line 149: "The merge seat may approve only work it neither wrote nor reviewed", and line 189: work merge-lane-2 wrote is approved by "a fresh reviewer posting as `mac-claude`, after the user approves in his own words". `scripts/merge-gate.sh` checks that the approving account is not the pull request's author, and, for a pull request merge-lane-2 wrote, that the approver is `mac-claude` and that `scripts/search-user-messages-in-transcripts.py` finds, in the transcript and at the time the pull request's description cites, the user's approving words that the description quotes.
9. **main passes its tests after each merge.** Seat-brief lines 278 and 279: "Verify main green on a clean checkout after every merge." The run-without-merge program tests the pull request merged with main before the merge; nothing tests the new `origin/main` after it. The program that merges runs the test suites on a clean checkout of the new `origin/main` and exits nonzero, naming each suite that failed and the merge commit, when one fails; what to do about a broken main, such as reverting the merge or asking its author for a fix, stays merge-lane-2's judgment.

## Grading a finding

10. **Whether a finding blocks the merge.** Seat-brief line 38: "5. Block when the cost cannot be undone and the condition is ordinary or rare, or when the cost can be undone, the condition is ordinary and no simple workaround exists."; item 5 of the approval-walk rewrites it as "5. Block a permanent harm that is ordinary or rare. Block a repairable harm that is ordinary when no simple workaround exists." The reviewer, or merge-lane-2, makes only bounded choices: the harm, one of permanent, repairable or negligible; how likely the failure is, one of ordinary, rare or hypothetical; and whether a simple workaround exists, yes or no. These are the ratings of questions 3 and 4 of item 5's rewrite. A table in code turns the three answers into block or not, and the program that posts the review asks the reviewer again when a finding lacks one of the three or gives a value not on the list. Point 3 of GHI 2505 gives the whole decision whether a finding blocks to a model; this idea keeps the three ratings with the model and moves only the table into code, so the design of GHI 2505 settles both together.

## merge-lane-2's own bookkeeping

11. **The task list.** Seat-brief line 351: "Keep one task on merge-lane-2's task list for each open item … the next agent-session compares its list with those ids, recreates any missing task from the handoff, and tells the user." A ledger in the log-store lists each GHI filed, each pull request commissioned, each non-blocking finding sent and each question to the user. The programs that act write its entries as they act, such as `scripts/ghi-issue-write.py` when it files a GHI and the run-without-merge program when it commissions a review, so merge-lane-2 does not write them by hand; a program that runs when an agent-session starts compares it with the task list and prints what is missing. Build it on GHI 2505's records when they exist.
12. **Which agent-seat owns a line of code.** Seat-brief line 342: "find that pull request with `git log` on the code's lines, and the agent-seat from the session link in its description or the worktree of its branch". A program runs that chain, from `git log -L` to the merge commit, the pull request, its session link and the agent-seat, and prints the agent-seat or says it found none; when it finds none, merge-lane-2 tells the user, as the seat-brief already says.
13. **A ruling a pull request cites.** Seat-brief line 377: "Check a cited ruling in the Mac transcript mirror … open a task to check it after the next mirror copy. Go to the user only if that check finds a mismatch." A program runs `scripts/search-user-messages-in-transcripts.py` on each `(user-ruled …)` quote a pull request cites, keeps each quote the mirror does not hold yet, and checks the kept quotes again after the next copy from the Mac finishes, which `nedlern@ned-box:/home/nedlern/nedschorus-logs/agent-session-files-by-machine/mac/last-complete-mirror-pass-utc.txt` records, run by the program that writes that file or by a scheduled job; it reports any mismatch to merge-lane-2. GHI [ruling-agent keeps user-rulings, checks approval-walk items against them](https://github.com/nedschorus/nedschorus/issues/2118) keeps a store of the user's rulings that such a check could read.
14. **The GitHub token's expiry.** Seat-brief line 210: "If a command fails with "Resource not accessible by personal access token", check the token's expiry first". `scripts/merge-lane-pull-request-helpers-common-options-paths-and-token.py` already reads the token. It reads the expiry GitHub returns with each reply, in the `github-authentication-token-expiration` header, prints it, and warns when the expiry is near.
15. **The watcher of open pull requests is running.** Seat-brief line 47: "Keep `…/watch-open-pull-requests-nbd.py --exit-after-first-poll-with-events` running in the background, and start it again each time it exits." A hook that runs when an agent-session starts, or when merge-lane-2's turn ends, after merge-lane-2 has read the events the watcher exited on, starts the watcher again when its process is not running, and reports only when that start fails.
16. **Fetching a pull request's head into a branch.** Seat-brief lines 302 and 303: "`git fetch origin pull/N/head:<name>` writes a PERMANENT local branch ref that nothing in this project ever reaps." A Bash guard refuses a `git fetch` command that holds `pull/`, a pull request number, and `/head:`. This idea is listed because the approval-walk listed it, but the harm is only a stray branch, so the guard meets CLAUDE.md's two conditions for a guard weakly at best: build it only when evidence shows both conditions hold.
