# Loose-ends skill: each agent-seat finds the asks between itself and the user that were forgotten, and does its own critical upkeep

## Why

The user runs many agent-seats at once and reads each one only now and then. Things that one side asked of the other get lost: an agent waits on a question the user never saw, could not follow, or did not need to be asked; the user asks for something that is acknowledged and never done; a task that says to bring something to the user sits for days. Parts of this are caught today, each in one place only: /walk-me-through's "Closing" section makes the agent check one approval-walk for its own unanswered questions and open commitments before the approval-walk closes; /handoff step 1 asks the agent to list open items for its successor. Nothing reads an agent-seat's conversations for what was lost between them. Agents have twice gathered such items by hand, as one-off approval-walks: merge-lane's `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/2026-08-31-session-loose-ends.md` and MD-skills' `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/seat-loose-ends-and-stale-tasks-2026-09-18.md`.

On 2026-10-15 the user replaced a planned skill to gather an agent-seat's unfinished approval-walks with a loose-ends skill drawn from the one in his old project, nedlern. On 2026-10-16 he approved its design in reboot-test's approval-walk `loose-ends-skill-design-2026-10-15`: walk-document `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/loose-ends-skill-design-2026-10-15.md`, walk-minutes `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/loose-ends-skill-design-2026-10-15-minutes.md`. His words on walk item 1: "it's a kind of mini maintence, but focused on making sure what agents wanted me to do or look at, or what I wanted agents to do or look at didn't simply get forgotten."

On 2026-10-21 reboot-test handed the work to prime-intellect, because the user has paused reboot-test's other work, and the user asked prime-intellect, at 21:19:09Z in its agent-session on ned-box, to get the skill "ready to start buiding".

## What the user decided

All six items of the approval-walk were approved on 2026-10-16. They are numbered here as in the walk-document; the walk-minutes hold his words.

- **Walk item 1: what the skill does.** Each agent-seat audits its own agent-sessions, not those of other agent-seats, in two parts.
  - The audit of asks finds asks in both directions, from an agent to the user and from the user to an agent, that were forgotten. It ports the old skill's eight kinds of loose end (listed under "What exists"; D2 asks about three of them) and adds three the user named: his suggestion ignored, or recorded in a way that changes what he meant; an approval-walk item that turned into several questions at once; a user-ruling the agent asked for that he never gave. Each ask found is either closed, with what closed it (the artifact that did it; the GHI, GHI edit or task it became; the message or event that made it obsolete), or still open.
  - Critical upkeep of this agent-seat only, admitted by the test "doing it now is clearly better than in 1 to 24 hours". Upkeep of the whole project, such as checking wiki pages, belongs to the maintenance-jobs of GHI [Regular maintenance: the list of maintenance jobs, how often each runs, and how each reaches the user](https://github.com/nedschorus/nedschorus/issues/1058), not to this skill.
- **Walk item 2: when the skill runs.** When the user types `/loose-ends`; before /handoff writes its next-step file, with the findings carried into the session-handoff; and after each approval-walk closes. At a session-handoff the skill only finds and records: it does none of the items and asks the user nothing; the walk-document adds "at a handoff, the successor does it". The user's words for the successor: "continue on the first task handed to the reincarnated agent and to present that and the leftover or loose ends from the previous session in a walk", in place of the unordered list successors show today. Also under walk item 2, he asked for research before the build, in two stages: stage 1, a fast trawl of a few conversations to learn what loose ends look like, now done; stage 2, the drafted detectors run over many more conversations to learn what can be automated, as a code-prompt-code (aka CPC), "nice-but-dirty": code first, a small model only where code cannot tell. The skill's text and the handoff texts are agent-instructions and each gets its /cold-read before its pull request.
- **Walk item 3: what happens to each open loose end**, sorted by who acts next: the agent itself does it and lists it as done; another agent-seat gets a message with the evidence, and the item is listed in one line; the user gets it in one approval-walk, ordered with items that block work first, then items that change direction, then the rest. When the agent is unsure whether something is a loose end, it lists the item for the user rather than drop it. With nothing found, it says so in one line.
- **Walk item 4: who builds it.** reboot-test, after asking ned-box-helper, which had not started; reboot-test has since handed the work to prime-intellect.
- **Walk item 5: names.** The skill is `loose-ends`. "Loose end" becomes a project-term: "an ask between the user and an agent, in either direction, that needed an answer, an action or a ruling and did not get one; an ask the user could not follow, and one a standing rule already decided, are loose ends too."
- **Walk item 6: summary.** He approved the upkeep list: open pull requests with review findings or conflicts; merged worktrees and branches to remove; leftover work-snapshots; new work cut from current main; each step done by an existing program. Three of these steps have no such program for one agent-seat (What exists; D9).

## Decisions for the user

The approval-walk did not decide these. Each comes with a recommendation; the build waits for his answers.

- **D1. The term's written form.** The glossary writes a project-term as an abbreviation, a slash name, a hyphenated phrase or a filename suffix, so that a reader can tell it from ordinary words; "loose end" is none of these. Recommendation: the project-term is written "loose-end", plural "loose-ends", with the approved definition.
- **D2. What the definition covers.** The approved definition covers asks between the user and an agent. Three of the old skill's kinds fall outside it: other agents' messages never acted on, which are between agent-seats; failed research never retried, which is not an ask; questions the agent should have asked, which were never asked, and for which stage 1 found no possible detector. Recommendation: keep the definition; the skill also finds messages from other agent-seats never acted on and failed research never retried, as upkeep of this agent-seat, not as loose ends; drop questions never asked.
- **D3. When a task is a loose end.** Walk item 1 closes an ask once it becomes a task, but stage 1's second group of loose ends was "Bring the user ..." tasks left pending for days. Recommendation: a task is itself a loose end when it says to bring something to the user, or to ask him, and has had no update for 2 days, recognised by the wording stage 2's task detector settles.
- **D4. Inputs.** The walk-document proposed reading the agent-session dialogs only, to keep each audit small. Recommendation: the detector programs read the raw transcripts, which hold everything the dialogs leave out, are current to the moment, and are on the machine where the agent-seat runs; only code reads a transcript, and a model is shown only the excerpt around each candidate.
- **D5. The audit record.** The next audit must know where the last one stopped. Printing a hashtag line in the agent's reply, as the walk-minutes propose with `#loose_ends_audited`, is matched by any later quote of that line, as the old skill's Step 0 found. Recommendation: after the user's items are recorded in his approval-walk's draft and the other items are done, sent or made tasks, a program appends, to the agent-seat's audit record `nedlern@ned-box:/home/nedlern/nedschorus-logs/seats/<agent-seat>/loose-ends-audit-record.md`, one line per transcript the detectors read: `#loose_ends_audited_through`, the transcript's path, and the time of the newest entry read in it (one line per transcript, because an agent-seat writes several transcripts at once, in its agent-home and its topic-worktrees; the name check of 2026-10-21, by the project's new-name-propose-and-check-fresh-agent subagent, found that a fresh-reader took `#loose_ends_audited` for "these items were reviewed"); a failed or unfinished audit appends nothing, so the next one reads from the last good line. At a session-handoff the predecessor appends its lines once the next-step file holds the findings.
- **D6. /handoff does not depend on the skill.** The skill is nice-but-dirty, and deleting it must leave nothing broken. Recommendation: /handoff runs `/loose-ends` only if the skill exists, with a time limit, and when the audit fails or runs out of time it writes the next-step file anyway, with one line saying the audit did not finish and why.
- **D7. The successor's first message.** Recommendation: the successor's first message says which first action it continues and then opens one approval-walk, by /walk-me-through's steps, of the loose ends the session-handoff found for the user, in walk item 3's order; it does the agent's own items and sends the other agent-seats' messages itself, and, between the approval-walk's items while it waits for his answers, carries on with its first action wherever that needs no answer from him. With no loose ends for the user it only continues; with no first action it only opens the approval-walk. Both successor-prompt paths, `build_ignition_prompt` and `BootRecoveryIgnitionPlan.compose`, change.
- **D8. After an approval-walk.** Recommendation: keep /walk-me-through's Closing check of the approval-walk itself, and add one line after it that runs `/loose-ends`, except after the approval-walk that `/loose-ends` or a successor's first message opened. When that run finds loose ends for the user, it opens one approval-walk of them, as walk item 3 says.
- **D9. Upkeep.** Each session-handoff already removes worktrees under `.claude/worktrees/` and gives the successor the work-snapshot, branch-sync and pull-request steps, so the skill runs no upkeep at a session-handoff. On `/loose-ends` and after an approval-walk, three steps of the list have no program that serves one agent-seat. Recommendation: the build adds one nice-but-dirty program that lists this agent-seat's open pull requests with review findings or conflicts, lists its topic-worktrees whose branches have merged, and says whether its current branch, if never pushed, is behind origin/main; the agent then acts as `CLAUDE.md` says (a forked subagent for each fix-round, the hand-merge `scripts/branch-conflict-check.py` describes, the cold-read-records shipped before a worktree is removed).
- **D10. Stage 2's sample.** Recommendation: a Claude subagent labels every loose end in 30 agent-sessions from at least five agent-seats on both machines, chosen when stage 2 starts from those since 2026-10-01; the user checks 20 excerpts picked at random from the sample, some labelled as loose ends and some not, and if he overturns more than 2, the labelling prompt is revised and the sample labelled again before any detector is scored.
