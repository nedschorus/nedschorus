# Loose-ends skill: each agent-seat finds the asks between itself and the user that never got an answer, an action or a ruling, and does its own critical upkeep

## Why

The user runs many agent-seats at once and reads each one only now and then. Things that one side asked of the other get lost: an agent waits on a question the user never saw, could not follow, or did not need to be asked; the user asks for something that is acknowledged and never done; a task that says to bring something to the user sits for days. Parts of this are caught today, each in one place only: /walk-me-through's "Closing" section makes the agent check one approval-walk for its own unanswered questions and open commitments before the approval-walk closes; /handoff step 1 asks the agent to list open items for its successor. Nothing reads an agent-seat's conversations for what was lost between them. Agents have twice gathered such items by hand, as one-off approval-walks: merge-lane's `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/2026-08-31-session-loose-ends.md` and MD-skills' `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/seat-loose-ends-and-stale-tasks-2026-09-18.md`.

On 2026-10-15 the user replaced a planned skill to gather an agent-seat's unfinished approval-walks with a loose-ends skill drawn from the one in his old project, nedlern. On 2026-10-16 he approved its design in reboot-test's approval-walk `loose-ends-skill-design-2026-10-15`: walk-document `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/loose-ends-skill-design-2026-10-15.md`, walk-minutes `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/loose-ends-skill-design-2026-10-15-minutes.md`. His words on walk item 1: "it's a kind of mini maintence, but focused on making sure what agents wanted me to do or look at, or what I wanted agents to do or look at didn't simply get forgotten."

On 2026-10-21 reboot-test handed the work to prime-intellect, because the user has paused reboot-test's other work, and the user asked prime-intellect, at 21:19:09Z in its agent-session on ned-box, to get the skill "ready to start buiding".

## What the user decided

Two approval-walks decided the design. Reboot-test's `loose-ends-skill-design-2026-10-15`, approved on 2026-10-16, set what the skill does. prime-intellect's `loose-ends-skill-finds-forgotten-asks-between-the-user-and-agents-design-2026-10-21`, walk-minutes `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/loose-ends-skill-finds-forgotten-asks-between-the-user-and-agents-design-2026-10-21-minutes.md`, ruled on this GHI-MD's first version on 2026-10-21 and 2026-10-22, and replaced several of the 2026-10-16 approvals; where the two differ, the later ruling stands, as each bullet below says.

- **What a loose end is** (2026-10-22, replacing the 2026-10-16 definition). In the user's words: "Loose ends are things which are not recorded in tasks or GHIs or PRs or other sort of tracking mechanisms. They might be information relating to tasks or GHIs or PRs, like, hey, did you do this or do that to that PR or GHI or whatever?" Items on the task list are not loose ends.
- **What the skill does** (2026-10-16, walk item 1). Each agent-seat looks over its own agent-sessions, not those of other agent-seats, in two parts. The audit finds loose ends in both directions, from an agent to the user and from the user to an agent, starting from the old skill's eight kinds of loose end (listed under "What exists"; D2 asks about three of them) and three the user added: his suggestion ignored, or recorded in a way that changes what he meant; an approval-walk item that turned into several questions at once; a user-ruling the agent asked for that he never gave. Each loose end found is either closed, with what closed it, or still open. The second part is critical upkeep of this agent-seat only, admitted by the test "doing it now is clearly better than in 1 to 24 hours"; upkeep of the whole project belongs to GHI [Regular maintenance: the list of maintenance jobs, how often each runs, and how each reaches the user](https://github.com/nedschorus/nedschorus/issues/1058). The approved upkeep list: open pull requests with review findings or conflicts; merged worktrees and branches to remove; leftover work-snapshots; new work cut from current main.
- **Agents find loose ends; code only helps** (2026-10-22, replacing the 2026-10-16 approval of a code-prompt-code, "code first, a small model only where code cannot tell"). The user: "we'll need a agent to trawl for loose ends and not a Python script. The Python script might help". The skill has the project's ordinary Claude and Codex agents read the agent-seat's recent conversations and list its loose ends: each reads the session dialogs and searches the raw transcripts with its tools for what the dialogs leave out. There are no detector programs to build or measure.
- **Guidance from a trawl by strong agents** (2026-10-22, replacing the 2026-10-16 plan for a stage 2 that measured detectors). Before the skill's text is final, three strong agents each trawl about 40 agent-sessions and write guidance for the ordinary subagents: Claude Opus 5.5 at max effort, Codex `gpt-6-astra` at max effort, and Gemini `gemini-4-argon-high`, the highest Gemini 4 model that `agy models` lists. prime-intellect compiles the three and goes over the result with the user before the skill is final. The user, on reading files: an agent is told the path of a large file and reads it with its tools; the file is not sent to it.
- **When the skill runs** (2026-10-16, walk item 2, confirmed 2026-10-22). When the user types `/loose-ends`; at each session-handoff; and after each approval-walk closes (D8 holds the details of the last).
- **The session-handoff never waits on the skill** (2026-10-22, D6). /handoff runs `/loose-ends` only if the skill exists, with a time limit, in a mode that only finds and records. It writes what it found into the next-step file, the file /handoff step 1 writes to tell the successor its first action; the successor puts the user's items into the one approval-walk it opens and does the rest. If the audit fails or runs out of time, /handoff writes the next-step file anyway, with one line such as "Loose-ends audit did not finish: timed out after 5 minutes." The limit's value is set when the handoff change is built.
- **The successor's first message** (2026-10-21, D7, approved as revised). The successor keeps working on its predecessor's work. One approval-walk, by /walk-me-through's steps, carries everything that needs the user: the unanswered items of any approval-walk in progress, open questions, concerns, suggestions, and the loose ends the session-handoff's audit found. An approval-walk in progress is closed with a line in its walk-minutes naming the new approval-walk that carries its remaining items, each item keeping a link to its original walk-document. The successor itself does its own items and sends other agent-seats theirs, without asking the user. With nothing for the user, it only keeps working. The user's items are ordered as walk item 3 says, below. Both places in `nc-systems/handoff/handoff-supervisor.py` that build a successor's prompt change: `build_ignition_prompt`, and `BootRecoveryIgnitionPlan.compose`, used when the previous conversation cannot be read.
- **What happens to each open loose end** (2026-10-16, walk item 3), sorted by who acts next: the agent itself does it and lists it as done; another agent-seat gets a message with the evidence, and the item is listed in one line; the user gets it in one approval-walk, ordered with items that block work first, then items that change direction, then the rest. When the agent is unsure whether something is a loose end, it lists the item for the user rather than drop it. With nothing found, it says so in one line.
- **The audit record** (2026-10-22, D5). After the audit's items are safely recorded (the user's in the approval-walk's draft, the rest done, sent or made tasks), a program appends lines to `nedlern@ned-box:/home/nedlern/nedschorus-logs/seats/<agent-seat>/loose-ends-audit-record.md`, one per transcript read: `#loose_ends_audited_through`, the transcript's path, and the time of its newest entry read. One line per transcript, because an agent-seat writes several transcripts at once, in its agent-home and its topic-worktrees. A failed audit appends nothing, so the next one reads from the last good line. At a session-handoff the predecessor appends its lines once the next-step file holds the findings. The old skill printed its audit line in the conversation, and its own Step 0 warns that a search for that line also matched agent-sessions that had only loaded the skill.
- **Names** (2026-10-16, walk item 5). The skill is `loose-ends`. "Loose end" becomes a project-term, with the 2026-10-22 definition; D1 asks how it is written.
- **Who builds it.** prime-intellect, to which reboot-test handed the work on 2026-10-21; the user asked prime-intellect that day to get the skill "ready to start buiding".

## Decisions for the user

The approval-walks did not decide these. Each comes with a recommendation; the skill's text waits for the user's answers. The labels D1, D2, D8 and D9 are those of this GHI-MD's first version; D10 and D11 are new. The first version's D5, D6 and D7 are ruled, under "What the user decided"; its D3, D4 and its stage 2 sample, D10, were dropped by the 2026-10-22 rulings.

- **D1. The term's written form.** The glossary writes a project-term as an abbreviation, a slash name, a hyphenated phrase or a filename suffix, so that a reader can tell it from ordinary words; "loose end" is none of these. Recommendation: the project-term is written "loose-end", plural "loose-ends", with the 2026-10-22 definition.
- **D2. Three of the old skill's kinds.** Other agents' messages never acted on: nothing tracks them, so under the 2026-10-22 definition they are loose ends, though they lie between agent-seats rather than between the user and an agent. Failed research never retried: a loose end when someone said it would be retried or asked for its result, and nothing tracks it. Questions the agent should have asked and did not: never asked, so nothing records them, and stage 1 found no way to see them in the files. Recommendation: the audit covers other agent-seats' messages never acted on, and failed research never retried that someone said would be retried or asked for, as loose ends; it drops questions never asked.
- **D8. After an approval-walk.** Recommendation: keep /walk-me-through's Closing check of the approval-walk itself, and add one line after it that runs `/loose-ends`, except after the approval-walk that `/loose-ends` or a successor's first message opened. When that run finds loose ends for the user, it opens one approval-walk of them, as walk item 3 says.
- **D9. Upkeep.** Each session-handoff already removes worktrees under `.claude/worktrees/` and gives the successor the steps for work-snapshots, branch sync and pull requests, so the skill runs no upkeep at a session-handoff. On `/loose-ends` and after an approval-walk, three steps of the list have no program that serves one agent-seat. Recommendation: the build adds one nice-but-dirty program that lists this agent-seat's open pull requests with review findings or conflicts, lists its topic-worktrees whose branches have merged, and says whether its current branch, if never pushed, is behind origin/main; the agent then acts as `CLAUDE.md` says (a forked subagent for each fix-round, the hand-merge `scripts/branch-conflict-check.py` describes, the cold-read-records shipped before a worktree is removed). `nc-systems/handoff/uncommitted-work-snapshots.py` already serves the fourth step.
- **D10. Tasks that say to bring the user something.** Stage 1's second-largest group of lost asks was tasks such as "Bring the user the label question" left pending for days. Under the 2026-10-22 definition a task is not a loose end, so the audit would not list them. Recommendation: the successor's approval-walk (D7) and the approval-walk after an audit also carry each open task whose subject says to bring the user something or ask him, as a task, not as a loose end, so that it reaches him.
- **D11. The Gemini run's launcher.** The project hands `agy` only cold-read reviewer prompts, through `nc-systems/cold-read/cold-read-agy-cell.py`, so the Gemini trawl cannot start today. prime-intellect has asked a Claude subagent and Codex, on 2026-10-22, for existing wrappers that make Codex and Gemini callable as tools from Claude. Recommendation: compile the guidance from the Claude and Codex runs without waiting, and add the Gemini run's guidance when a launcher lands, built as its own pull request once that research reports, so that the launcher can follow a wrapper it finds.
