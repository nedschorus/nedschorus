# Loose-ends skill: each agent-seat finds the asks between the user and its agents that were forgotten, and does its own critical upkeep

## Why

The user runs many agent-seats at once and reads each one only now and then. Things that one side asked of the other get lost: an agent waits on a question the user never saw, could not follow, or did not need to be asked; the user asks for something that is acknowledged and never done; a task that says to bring something to the user sits for days. Nothing finds these today. Agents have twice gathered them by hand, as one-off approval-walks: merge-lane's `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/2026-08-31-session-loose-ends.md` and MD-skills' `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/seat-loose-ends-and-stale-tasks-2026-09-18.md`.

On 2026-10-15 the user replaced a planned meta-walk skill (one skill to gather an agent-seat's unfinished approval-walks) with a loose-ends skill drawn from the one in his old project, nedlern. On 2026-10-16 he approved its design in reboot-test's approval-walk `loose-ends-skill-design-2026-10-15`: walk-document `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/loose-ends-skill-design-2026-10-15.md`, walk-minutes `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/loose-ends-skill-design-2026-10-15-minutes.md`. His words on item 1: "it's a kind of mini maintence, but focused on making sure what agents wanted me to do or look at, or what I wanted agents to do or look at didn't simply get forgotten."

On 2026-10-21 reboot-test handed the work to prime-intellect, because the user has paused reboot-test's other work, and the user asked prime-intellect, at 21:19:09Z in its agent-session on ned-box, to get the skill "ready to start buiding".

## What the user decided

All six items of the approval-walk were approved on 2026-10-16; the walk-minutes hold his words.

1. **What the skill does.** Each agent-seat audits its own conversations, not those of every agent-seat, in two parts.
   - The audit of asks finds asks in both directions, agent to user and user to agent, that were forgotten. It covers the eight kinds the old skill listed (below, under "What exists") and three the user added: his suggestion ignored, or recorded in a way that changes what he meant; an approval-walk item that turned into several questions at once; a user-ruling the agent asked for that he never gave. Each ask found is either closed, with the artifact that closed it (done; turned into a GHI, a GHI edit or a task; made obsolete), or still open.
   - Critical upkeep of this agent-seat only, admitted by the test "doing it now is clearly better than in 1 to 24 hours". The list, approved at item 6: open pull requests with review findings or conflicts; merged worktrees and branches to remove; leftover work-snapshots; new work cut from current main. Each step runs the program that already does it, where one exists, and the skill rebuilds none of them. Upkeep of the whole project, such as checking wiki pages, belongs to the maintenance jobs of GHI [Regular maintenance: the list of maintenance jobs, how often each runs, and how each reaches the user](https://github.com/nedschorus/nedschorus/issues/1058), not to this skill.
2. **When the skill runs.** When the user types `/loose-ends`; before the handoff skill writes its next-step file, with the findings carried into the session-handoff; and after each approval-walk closes. At a handoff the skill only finds and records: it changes nothing, does none of the items and asks the user nothing. The user's words for the successor: "continue on the first task handed to the reincarnated agent and to present that and the leftover or loose ends from the previous session in a walk", in place of the unordered list successors show today.
3. **What happens to each open loose end**, sorted by who acts next: the agent itself does it and lists it as done; another agent-seat gets a message with the evidence, and the item is listed in one line; the user gets it in one approval-walk, ordered with items that block work first, then items that change direction, then the rest. When the agent is unsure whether something is a loose end, it lists the item for the user rather than drop it. With nothing found, it says so in one line.
4. **How it is built.** As a code-prompt-code (aka CPC) that is nice-but-dirty: code detectors first, a small model (Haiku, or a fast Gemini model) only where code cannot tell, a large model only where nothing cheaper works. Research comes first, in two stages: stage 1, a fast trawl of a few conversations to learn what loose ends look like, is done; stage 2 runs stage 1's detectors over many more conversations to learn what can be automated.
5. **Names.** The skill is `loose-ends`. "Loose end" becomes a project-term: "an ask between the user and an agent, in either direction, that needed an answer, an action or a ruling and did not get one; an ask the user could not follow, and one a standing rule already decided, are loose ends too."
6. **The skill's own text and the two handoff texts are agent-instructions**, so each gets its /cold-read before its pull request.

## What exists

Its eight kinds of loose end: the user's questions left unanswered or half-answered; his requests acknowledged and never acted on; decisions discussed and never concluded; "later" promises never kept; failed research never retried; other agents' messages never acted on; questions the agent should have asked and did not; a paused approval-walk. It sorts them by who acts next, and writes a "LOOSE-ENDS-AUDIT:" line into the transcript so the next audit reads only newer conversations.
- Stage 1's research, all in the directory `nedlern@ned-box:/home/nedlern/nedschorus-logs/seats/reboot-test/loose-ends-research-2026-10-16/`: two trawls of reboot-test's ten agent-sessions of 2026-10-07 to 2026-10-16 and two of agent-instructions-editor's, one by a Claude subagent, `trawl-claude-report.md` in that directory, and one by Codex, `trawl-codex-report.md`; two searches for published practice, `best-practices-claude-report.md` and `best-practices-codex-report.md`; and the Claude trawl's 19 detector programs with their outputs, in its subdirectory `scripts-claude/`.
- What stage 1 found, on that sample only:
  - Most loose ends were agent-to-user asks that failed: the same ask repeated 3 to 21 times, often across a session-handoff; asks the user could not follow ("repeat", "not enough context"); asks a standing rule already decided ("Why did you ask? Is there a rule for this"). User-to-agent asks were nearly always closed in the same turn.
  - The second large group is stale tasks: 37 of 79 tasks were never marked completed, and the ones that matter are "Bring the user ..." tasks left pending for days.
  - Four code detectors found most of them with few false candidates: an ask repeated three or more times with no user message between (13 of 13 runs true once a plain "y" reply is excluded); a regex for "why did you ask" and "is there a rule" (5 of 5 true); stale "Bring the user" tasks read from the task list Claude Code writes into each transcript (4 of 4 true); and an item named in three or more successive session-handoffs, read from the first user message of each agent-session, which holds the successor prompt. A regex for "I'll do it later" promises, and a detector for unanswered messages from other agent-seats, found nothing true on this sample.
  - Both searches for published practice agree on three points: keep a ledger of open items, changed only by status; close an item only with evidence; measure detectors on labelled real conversations before trusting them.

## Decisions for the user

The approval-walk did not decide these. Each comes with a recommendation; the build waits for his answers.

1. **Dialogs and transcripts.** Item 2 of the walk-document proposed reading the agent-session dialogs only, to keep each audit small; stage 1 then found that the dialogs leave out tasks, other agent-seats' messages and mid-turn user messages. Recommendation: the detector programs read both, the dialog for the conversation and the transcript for those three things; only code reads the transcript, and no model reads it whole, so the cost stays small.
2. **The audit's hashtag.** The walk-minutes propose `#loose_ends_audited`; the name check proposes `#loose_ends_audited_through`, because a fresh-reader took the first for "these items were reviewed" rather than "the audit covered everything up to this time". The skill prints the hashtag and the time in its reply, so the line reaches both the transcript and the dialog, and the next audit starts after the newest such line in the agent-seat's transcripts. Recommendation: `#loose_ends_audited_through`.
3. **Upkeep at a handoff.** Decision 2 above says the skill changes nothing at a handoff. Recommendation: at a handoff the skill runs no upkeep and lists the merged worktrees and branches in the next-step file for the successor to remove; the successor prompt already covers work-snapshots, branch sync and open pull requests. On `/loose-ends` and after an approval-walk closes, it runs the whole list.
4. **The successor's first message.** The user asked the successor both to continue its first action and to present that action with the loose ends as an approval-walk. Recommendation: the successor's first message opens one approval-walk whose first item is the first action handed to it, followed by the loose ends in decision 3's order; while the user has not answered, the successor carries on with the first action wherever that needs no answer from him.
5. **After an approval-walk.** walk-me-through's Closing already checks the approval-walk itself. Recommendation: keep that check, which covers one approval-walk while its context is fresh, and add one line to Closing that runs `/loose-ends` after it, for the rest of the agent-session; the approval-walk that `/loose-ends` itself opens does not start another audit when it closes.
6. **Who labels stage 2's sample.** Stage 2's detectors are scored against conversations labelled by hand. Recommendation: a Claude subagent labels them, and the user checks 20 of the labels before the scores are trusted.

## The work

1. **Stage 2.** Run stage 1's code detectors over every agent-seat's agent-session dialogs and transcripts on both machines from 2026-10-01, and score each against a hand-labelled sample. The sample includes the four loose ends ned-box-helper named on 2026-10-16, which the walk-minutes list under item 4. Record each detector's counts of true and false candidates in the log-store, and bring them to the user in an approval-walk, with a recommendation per detector: keep it, and whether code alone decides or a small model judges the candidates code found; or drop it.
2. **The detectors.** Build the detectors the user keeps as nice-but-dirty programs with tests, under `nc-systems/skills/loose-ends/`, each reading one agent-seat's agent-sessions since its newest audit line and printing the candidates with their citations. A detector that cannot read its input says so and exits nonzero; the skill then lists that detector as not run.
3. **The skill.** Write `.claude/skills/loose-ends/SKILL.md`: run the detectors, judge their candidates, sort each open loose end by who acts next, run the upkeep list, print the audit line, and present the user's items as one approval-walk. An item the agent tries itself and cannot finish goes to the user's approval-walk, with what failed. /cold-read before its pull request.
4. **The handoff part.** Change the handoff skill so that it runs `/loose-ends` before step 1 and puts the findings in the next-step file; change `build_ignition_prompt` so that the successor's first message is the approval-walk decision 4 describes; add decision 5's line to walk-me-through's Closing. /cold-read of the three texts before their pull request. reboot-test held the handoff change as its own task and has passed it to this GHI-MD.
5. **The glossary.** Add "loose end", with the definition in item 5 above, to `docs/nedschorus-wiki/nedschorus-glossary.md` in its own small pull request.
