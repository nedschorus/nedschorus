# Loose-ends skill: each agent-seat finds the asks between itself and the user that never got an answer, an action or a ruling, and does its own critical upkeep

## Why

The user runs many agent-seats at once and reads each one only now and then. Things that one side asked of the other get lost: an agent waits on a question the user never saw, could not follow, or did not need to be asked; the user asks for something that is acknowledged and never done; a task that says to bring something to the user sits for days. Parts of this are caught today, each in one place only: /walk-me-through's "Closing" section makes the agent check one approval-walk for its own unanswered questions and open commitments before the approval-walk closes; /handoff step 1 asks the agent to list open items for its successor. Nothing reads an agent-seat's conversations for what was lost between them. Agents have twice gathered such items by hand, as one-off approval-walks: merge-lane's `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/2026-08-31-session-loose-ends.md` and MD-skills' `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/seat-loose-ends-and-stale-tasks-2026-09-18.md`.

On 2026-10-15 the user replaced a planned skill to gather an agent-seat's unfinished approval-walks with a loose-ends skill drawn from the one in his old project, nedlern. On 2026-10-16 he approved its design in reboot-test's approval-walk `loose-ends-skill-design-2026-10-15`: walk-document `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/loose-ends-skill-design-2026-10-15.md`, walk-minutes `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/loose-ends-skill-design-2026-10-15-minutes.md`. His words on walk item 1: "it's a kind of mini maintence, but focused on making sure what agents wanted me to do or look at, or what I wanted agents to do or look at didn't simply get forgotten."

On 2026-10-21 reboot-test handed the work to prime-intellect, because the user has paused reboot-test's other work, and the user asked prime-intellect, at 21:19:09Z in its agent-session on ned-box, to get the skill "ready to start buiding".

- **What a loose-end is** (2026-10-25, item 14 of `prime-intellect-open-decisions-for-the-user-2026-10-22-2`, D12, refining the entry approved on 2026-10-23 in its item 4, which replaced the 2026-10-22 and 2026-10-16 definitions). The approved glossary entry: "**loose-end** — something asked, offered or left open that nothing routinely processes: no open task on an agent-seat's task list, open GHI or open pull request holds it in its current text; no session-handoff its successor has not yet read lists it as open; and it is not an unanswered item of an approval-walk still open in a running agent-session. It may concern a task, GHI or pull request, such as a question about a pull request. Work handed to another agent-seat is a loose-end unless a task, GHI or pull request holds it on one side or the other, so the agent-seat that hands it over keeps its task until the other agent-seat says it has one. A closed approval-walk's minutes, a cold-read triage, a queue directory and `docs/drafts/` do not hold one, because nothing routinely processes them. The plural is loose-ends." The user's reason: "Walks minutes are not operative. There's nothing that is assigned to process them except for perhaps maintenance. Tasks are checked by agents very routinely. I check GHIs. So it needs to be, it's not enough to simply record tasks or items ... They have to be put in some sort of queue that is then looked at to process." A successor agent-session reads its session-handoff once, at its start, so an item there that the successor neither did nor made a task is a loose-end. The queue-drain that would process the queue directories is GHI [Queue drain procedure — the review process that empties the wiki queue, the pair queue, nc-queue, the drafts directory and the queue-drain-candidate-label issue queue](https://github.com/nedschorus/nedschorus/issues/24), open and not built. The user, approving it: "I think that is a good definition ... in that process, you might need to update your loose ends definition again." D12, below, says what the 2026-10-25 refinements changed.
- **A subagent's final report is read as fully as a message from the user** (2026-10-22, side ruling on item 10 of `prime-intellect-open-decisions-for-the-user-2026-10-22-2`). The user: "loose ends just has to treat subagent responses more, just as responses, not as like secondary responses that are less important." Each finding in a subagent's report that the agent neither acted on nor passed on, and that no task, GHI or pull request holds, is a loose-end. The guidance trawl found 58 of its 222 loose-ends lost in subagent reports, the second-largest place after "never written anywhere".
- **What the skill does** (2026-10-16, walk item 1). Each agent-seat looks over its own agent-sessions, not those of other agent-seats, in two parts. The audit finds loose ends in both directions, from an agent to the user and from the user to an agent, starting from the old skill's eight kinds of loose end (listed under "What exists"; D2, below, settles three of them) and three the user added: his suggestion ignored, or recorded in a way that changes what he meant; an approval-walk item that turned into several questions at once; a user-ruling the agent asked for that he never gave. Each loose end found is either closed, with what closed it, or still open. The second part is critical upkeep of this agent-seat only, admitted by the test "doing it now is clearly better than in 1 to 24 hours"; upkeep of the whole project belongs to GHI [Regular maintenance: the list of maintenance jobs, how often each runs, and how each reaches the user](https://github.com/nedschorus/nedschorus/issues/1058). The approved upkeep list: open pull requests with review findings or conflicts; merged worktrees and branches to remove; leftover work-snapshots; new work cut from current main.
- **Agents find loose ends; code only helps** (2026-10-22, replacing the 2026-10-16 approval of a code-prompt-code, "code first, a small model only where code cannot tell"). The user: "we'll need a agent to trawl for loose ends and not a Python script. The Python script might help". The skill has the project's ordinary Claude and Codex agents read the agent-seat's recent conversations and list its loose ends: each reads the session dialogs and searches the raw transcripts with its tools for what the dialogs leave out. There are no detector programs to build or measure.
- **Guidance from a trawl by strong agents** (2026-10-22, replacing the 2026-10-16 plan for a stage 2 that measured detectors). Before the skill's text is final, three strong agents each trawl about 40 agent-sessions and write guidance for the ordinary subagents: Claude Opus 5.5 at max effort, Codex `gpt-6-astra` at max effort, and Gemini `gemini-4-argon-high`, the highest Gemini 4 model that `agy models` lists. prime-intellect compiles the guidance from the Claude and Codex runs, after a check of 20 of Claude's loose-ends, and adds Gemini's findings when its run finishes (2026-10-23, item 1 of `prime-intellect-open-decisions-for-the-user-2026-10-22-2`, D11), then goes over the result with the user before the skill is final; this is the user's process of 2026-10-22, "have our normal codex and claude subagents look for loose ends. However maybe we strengthen that by having a Opus 5.5 at Max, and a Codex Astra and a Gemini 4 at Max trawl say 40 transcripts and then compile guidance for our normal agents, which you can then go over with me, before we finalize." The user, on reading files: an agent is told the path of a large file and reads it with its tools; the file is not sent to it.
- **When the skill runs** (2026-10-16, walk item 2, confirmed 2026-10-22; the third time replaced 2026-10-24 by D8 below). When the user types `/loose-ends`, and at each session-handoff.
- **The session-handoff never waits on the skill** (2026-10-22, D6). /handoff runs `/loose-ends` only if the skill exists, with a time limit; the old agent-session does at once what it can, as D9 below says, and writes what is left into the next-step file, the file /handoff step 1 writes to tell the successor its first action; the successor puts the user's items into the one approval-walk it opens and does the rest. If the audit fails or runs out of time, /handoff writes the next-step file anyway, with one line such as "Loose-ends audit did not finish: timed out after 5 minutes." The limit's value is set when the handoff change is built.
- **The successor's first message** (2026-10-21, D7, approved as revised). The successor keeps working on its predecessor's work. One approval-walk, by /walk-me-through's steps, carries everything that needs the user: the unanswered items of any approval-walk in progress, open questions, concerns, suggestions, and the loose ends the session-handoff's audit found. An approval-walk in progress is closed with a line in its walk-minutes naming the new approval-walk that carries its remaining items, each item keeping a link to its original walk-document. The successor itself does its own items and sends other agent-seats theirs, without asking the user. With nothing for the user, it only keeps working. The user's items are ordered with the next step's own item first, when it needs the user, then as walk item 3 says, below; the user, on 2026-10-24, described the successor's approval-walk as starting "with the priority item, but including all the loose ends, and then whatever else". He approved the prompt's exact words on 2026-10-24 (item 6.3 of `prime-intellect-open-decisions-for-the-user-2026-10-22-2`), and PR [handoff-supervisor: successor prompts bring the user's items in one approval-walk (D7)](https://github.com/nedschorus/nedschorus/pull/1915) put them in both places in `nc-systems/handoff/handoff-supervisor.py` that build a successor's prompt: `build_ignition_prompt`, and `BootRecoveryIgnitionPlan.compose`, used when the previous conversation cannot be read.
- **What happens to each open loose end** (2026-10-16, walk item 3), sorted by who acts next: the agent itself does it and lists it as done; another agent-seat gets a message with the evidence, and the item is listed in one line; the user gets it in one approval-walk, ordered with items that block work first, then items that change direction, then the rest. When the agent is unsure whether something is a loose end, it lists the item for the user rather than drop it. With nothing found, it says so in one line.
- **The audit record** (2026-10-22, D5). After the audit's items are safely recorded (the user's in the approval-walk's draft, the rest done, sent or made tasks), a program appends lines to `nedlern@ned-box:/home/nedlern/nedschorus-logs/seats/<agent-seat>/loose-ends-audit-record.md`, one per transcript read: `#loose_ends_audited_through`, the transcript's path, and the time of its newest entry read. One line per transcript, because an agent-seat writes several transcripts at once, in its agent-home and its topic-worktrees. A failed audit appends nothing, so the next one reads from the last good line. At a session-handoff the predecessor appends its lines once the next-step file holds the findings; D5 below keeps this rule. The old skill printed its audit line in the conversation, and its own Step 0 warns that a search for that line also matched agent-sessions that had only loaded the skill.
- **D2. Three of the old skill's kinds** (2026-10-23, item 5 of `prime-intellect-open-decisions-for-the-user-2026-10-22-2`). The audit lists another agent-seat's message that was never answered or acted on as a loose-end, and leaves out failed research that was never retried. Each time it runs, it also asks the agent "What should you have asked the user, and did not?", and lists each answer as a loose-end; nothing in the files shows these. The user: "research - don't care, not a problem. Should have asked but did not, sure, why not. If loose ends gets triggered auto or manually, why not ask that question." Session-dialogs leave out messages from other agent-seats, so the audit finds them in the raw transcripts; the Claude trawl counted 15 of its 222 loose-ends there.
- **D10. Tasks that say to bring the user something stay on the task list** (2026-10-24, item 6 of `prime-intellect-open-decisions-for-the-user-2026-10-22-2`). The audit does not list them. The agent brings one to the user when it becomes relevant, such as when the work it concerns comes up, or when it blocks something from reaching production. The user: "as long as it's in a task list, at least I'll get to it eventually. And not everything can be now or in a walk even", and "I think it's fine that tasks stay on task lists." A task or a GHI is the way to defer; the work to concentrate on is getting things into production.
- **D8. No separate audit after an approval-walk closes** (2026-10-24, item 7 of `prime-intellect-open-decisions-for-the-user-2026-10-22-2`, replacing the 2026-10-16 trigger). Nothing is added to /walk-me-through. The user approved, in fleet-restart-at-login's approval-walk, that an approval-walk's close starts a session-handoff, whose audit (D6) covers it; an approval-walk that closes below the minimum context for a session-handoff, 20% (current context plus the tokens compactions dropped), starts none, and the next session-handoff's audit reads everything since the last audit.
- **D5. The old agent-session writes the audit record at a session-handoff** (2026-10-24, item 8 of `prime-intellect-open-decisions-for-the-user-2026-10-22-2`, keeping the 2026-10-22 rule). A successor that crashes is started again by the handoff-supervisor from the same next-step file, so nothing is lost. A daily job in GHI [Regular maintenance: the list of maintenance jobs, how often each runs, and how each reaches the user](https://github.com/nedschorus/nedschorus/issues/1058), built with the audit, finds a next-step file holding loose-ends whose successor never started, and starts that successor. The user prefers building it before a first case: "I really don't like loose ends, I guess is what I'm really saying. So I'm happy to do a little extra work to make sure".
- **D9. What can be done now is done now, helped by one upkeep program** (2026-10-24, item 9 of `prime-intellect-open-decisions-for-the-user-2026-10-22-2` and a side ruling with it). Only what needs the user, or more work than it has room for, goes to the successor's approval-walk or task list. "Done now" covers work that needs no new ruling from the user, done by the agent itself, by a subagent, or by a message to the agent-seat that owns it. The user: "the stuff that can be done now probably should be done now, and the stuff that needs to tell other agents to do you should tell other agents to do now ... because the context is there for now and not necessarily there for later", and "Worst case, it'll ask me to approve again, but at least it won't be a loose end".

The audit reads the agent-seat's own conversations, not its subagents' conversations.
