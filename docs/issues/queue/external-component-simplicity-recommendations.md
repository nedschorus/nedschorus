# External components that could simplify NedsChorus

**The most useful borrowings are small components and clear boundaries. The inspected system does not need a replacement graph framework to make its next improvements.** Its existing cell runners already handle much of the work that a framework would supply.

This is a recommendation map, with exact source locations in the linked notes. It proposes work for the existing issues; it does not activate deferred work, change the reviewer rules, or install dependencies. The source-specific notes are independent reading units so an agent working on one task need not read the whole survey.

Several inventory corrections affect these choices. The current [scripts/cold-read-grid.py](https://github.com/nedschorus/nedschorus/blob/b9655170cebbbaa78e361b7b4aeef6f3e3a31089/scripts/cold-read-grid.py) runs six cells: four defect-hunt cells and two terminology cells. Restate remains available as a single cell but is absent from the default roster. [#166](https://github.com/nedschorus/nedschorus/issues/166) still describes the earlier eight-cell configuration. Implement its report-consolidation goal against the current roster and actual report contracts, without restoring retired cells.

Similarly, [#41](https://github.com/nedschorus/nedschorus/issues/41) describes an earlier point when the Claude headless path had not been measured. Current [scripts/cold-read-claude-cell.py](https://github.com/nedschorus/nedschorus/blob/b9655170cebbbaa78e361b7b4aeef6f3e3a31089/scripts/cold-read-claude-cell.py) and [scripts/cold-read-codex-cell.py](https://github.com/nedschorus/nedschorus/blob/b9655170cebbbaa78e361b7b4aeef6f3e3a31089/scripts/cold-read-codex-cell.py) share [scripts/cold-read-cell-common.py](https://github.com/nedschorus/nedschorus/blob/b9655170cebbbaa78e361b7b4aeef6f3e3a31089/scripts/cold-read-cell-common.py). The generic CLI remains missing in the inspected tree, but its implementation should start from those working adapters.

The strongest immediate simplification is in [#166](https://github.com/nedschorus/nedschorus/issues/166): code gathers the evidence once, groups it by the passage it concerns, and lets the human and commissioning agent judge it in one place. The issue records comparisons costing 10–20 minutes and 130,000–230,000 tokens; those are historical issue-reported measurements, not measurements from this research pass.

**Scope and evidence.** The repository snapshot inspected was b9655170cebbbaa78e361b7b4aeef6f3e3a31089. The open-issue survey returned 70 issues; detailed reads focused on the runners, Cold Read, evaluation, reference checking, recovery, and diagnosis and their linked queue documents. The current architecture was also read. Local source checks and one synthetic upstream-aggregator probe support the findings. No live agent evaluations or production recovery were run. Source links are pinned where code was inspected; documentation-page links are dated by this note.

The research papers on [Decomposed Prompting](https://arxiv.org/abs/2210.02406) and [separate-context question decomposition](https://arxiv.org/abs/2307.11768) remain relevant conceptual precedents. They did not expose an additional ready-made component that is simpler than the inspected NC code for these gaps. Larger orchestration services should be reconsidered only when a concrete execution requirement exceeds the current controller's practical simplicity.
