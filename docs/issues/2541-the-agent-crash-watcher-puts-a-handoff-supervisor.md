# The agent-crash-watcher puts a handoff-supervisor back on an unsupervised agent-seat whose session-handoff is waiting

## What is wrong

A `claude` that a person starts by hand in an agent-home, rather than through a launcher, runs with no handoff-supervisor. When it writes its session-handoff, nothing acts on it: no handoff-supervisor stops the agent-session or starts the successor. Today a person recovers this state with `scripts/resupervise-seat.py <seat>`, run on the Mac: it refuses unless the session-handoff is waiting (its `restart-counter` not yet consumed) and no handoff-supervisor is alive, retires the agent-seat's tmux session, and runs the launcher, whose handoff-supervisor starts the successor from the waiting session-handoff. For an agent-seat on ned-box, `--machine ubuntu` runs steps 1 to 4 on ned-box over ssh, as `resupervise-seat.py <seat> --prepare-only`, and then `scripts/launch-claude-ubuntu` on the Mac, because that launcher is a Mac-side program. Only a person runs it, and only once he has noticed the state.

The agent-crash-watcher, `nc-systems/handoff/handoff-agent-crash-watcher.py`, runs every minute on ned-box and assesses every agent-seat with `assess_seat()` from `scripts/recover-crashed-seats.py`, but never runs `resupervise-seat.py` (no line of it names that program, on main at 78716fd58). For this state `assess_seat()` returns the verdict `refuse` before it reads the session-handoff: the tmux session is alive and no handoff-supervisor is confirmed by `ps`, or, outside tmux, a process works in the agent-home. The watcher at most shows the user a refusal notice, and only for an agent-seat it saw running earlier in the boot.

## Why it matters

The agent-session has done its part, a session-handoff, and the successor that would carry the work on never starts until a person notices. The project builds code-prompt-code: detecting a waiting session-handoff, no live handoff-supervisor lock and a running `claude`, then running one program, needs no judgment. The session-handoff writer, `nc-systems/handoff/handoff-write-and-check-supervisor.py`, cannot do it: the handoff-system's nc-architecture-overview, `docs/nedschorus-wiki/nedschorus-handoff-architecture-overview.md`, says under its invariants that the writer starts nothing, because the program that starts a successor must be the one that ends the agent-session. `resupervise-seat.py` keeps to that invariant, since it starts a handoff-supervisor, which ends the agent-session and starts the successor, as `recover-crashed-seats.py` does when the watcher runs it today.

## What to build

In the agent-crash-watcher on ned-box, a check of each agent-seat for three facts read by code: a waiting session-handoff that does not carry `dont-restart`; no live handoff-supervisor; and a running `claude` working in the agent-home. Each fact is read by a function that a program already uses, so that the watcher and the programs it runs cannot disagree: `handoff_is_waiting()` of `scripts/resupervise-seat.py`, or `waiting_handoff_verdict()` of the records reader the watcher already uses, whichever the builder shows agrees with `resupervise-seat.py`'s refusal; and `seat_supervisor_confirmed_by_ps()` of `scripts/recover-crashed-seats.py`, which confirms with `ps` the process the supervisor lock names. When all three hold on two runs at least `CRASH_CONFIRMATION_SECONDS` apart, the watcher does on ned-box what the restart program `nc-systems/handoff/handoff-supervisor-restart-onto-main-code-by-relaunch-from-reference-checkout.py` does in its steps 5 and 6: it runs `scripts/resupervise-seat.py <seat> --prepare-only`, which retires the agent-seat's tmux session and with it the unsupervised `claude` in that session, then `scripts/recover-crashed-seats.py <seat>`, which starts the handoff-supervisor on ned-box under the user's systemd manager and opens the agent-seat's window on the Mac; the handoff-supervisor then starts the successor from the session-handoff. It records the decision in `decisions.jsonl`, as it records a restart, and counts it against `RESTART_LIMIT_SECONDS` as a restart. A `claude` running outside a tmux session is not ended by `--prepare-only`, so `recover-crashed-seats.py` refuses while it runs; the watcher then shows the user a notice naming the process. Every failure becomes a notice with its own text, since the existing notices say the agent-session stopped without a session-handoff. Tests go in `nc-systems/handoff/tests/handoff-agent-crash-watcher-test.py`.

## Open questions

- The watcher's docstring calls an agent-seat down with a waiting session-handoff "a state only he should restart from", and `WAITING_HANDOFF_NOTICE_TEMPLATE` says the watcher does not start a successor from a waiting session-handoff because it is the agent's own request. That case differs from this one, where the `claude` is still running and wrote the session-handoff itself, but the builder brings the user the change, with that recorded line, before building.
- Where the check sits in the watcher: the watcher acts today only on an agent-seat it saw running earlier in the boot, and an unsupervised agent-seat is never seen running, because `assess_seat()` returns `seat-already-running` only when a handoff-supervisor is confirmed. The builder decides whether this check runs for every agent-seat, and says why.
