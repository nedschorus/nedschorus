# The user-alerts UserPromptSubmit hook claims the user's pending alerts in headless claude -p sessions, where no user is present

## Reproduction

## Why the hook took the prompt as typed

The hook is `nc-systems/skills/walk-me-through/walk-me-through-pending-user-alerts-claim-and-insert-as-approval-walk-items-user-prompt-submit-hook.py`. Its docstring says "ONLY A PROMPT THE USER TYPED claims". Its function `typed_by_user` reads the transcript from the newest record back, and lets the newest record that carries `turnOrigin` decide, `human` meaning typed, when that record's text is the payload's prompt. When it finds no record carrying `turnOrigin`, it falls back to the prompt's opening: a prompt that does not open as the hook's constant `NOT_TYPED_PROMPT_OPENINGS` lists, such as `<task-notification>`, counts as typed.

In the transcript above, the commission prompt's record, the fourth, carries `"turnOrigin": "sdk"`, `"promptSource": "sdk"` and `"entrypoint": "sdk-cli"`. Had the hook read that record, `typed_by_user` would have returned false, since `sdk` is not `human`. The three records before it, a `session-owner` record and two `queue-operation` records, carry no `turnOrigin`. So the hook most likely ran before Claude Code had written the prompt's record, found no record carrying `turnOrigin`, and by the fallback took the reviewer's commission prompt, which opens "You are the independent reviewer for the nedschorus project", as typed. The docstring names the case of a prompt whose record is not yet written, but only for a later prompt, where the newest record is the previous turn's; on a session's first prompt there is no earlier record carrying `turnOrigin`, and the fallback decides. That order is inferred from the transcript, not observed (unverified).

## Harm

The claimed alerts sit in `claimed/`, where the user does not see them. `user_alerts_claimed_delete_if_recorded_in_approval_walk_minutes_else_release_to_pending_after_30_minutes`, in `nc-systems/general-tools/user-alerts-pending-and-claimed-files-write-claim-release-and-delete-common.py`, moves them back to `pending/` only when a prompt arrives 30 minutes or more after the claim. The hook runs that function and then claims every pending alert in the same run, so when the prompt that releases them is a headless session's, that session claims them again at once. merge-lane-2 runs headless reviewers many times a day, and other programs start headless sessions too, so an alert, such as one saying the idle sweep failed, can be kept from the user again and again. Nothing is lost: the files survive, and a prompt the user types while they are in `pending/` delivers them.

## What to do

The hook's owner, the agent-seat fleet-restart-at-login, which wrote `typed_by_user` (`git log` on the hook's lines), fixes the root cause: the hook must count a prompt as typed only on evidence that the user typed it, so that a headless session's first prompt never counts as typed, whether or not Claude Code has written the prompt's record when the hook runs. The fix must still let a user's first prompt in an interactive session claim, though its record may not be written yet either; one signal to examine is the environment variable `CLAUDE_CODE_ENTRYPOINT`, which reads `cli` in an interactive session on ned-box, but whether Claude Code passes it to hooks, and what it reads in a `claude -p` session, was not checked (unverified). Tests run the hook on a headless session's first prompt both before its record is written and after a record with `"turnOrigin": "sdk"` is written, and show that it claims nothing; and run it on an interactive session's first prompt and show that it claims.

## Outcome

Fixed by pull request [2931 User-alerts hook claims no alert in a headless claude -p agent-session](https://github.com/nedschorus/nedschorus/pull/2931), merged at 2026-11-09T05:25:17Z as 69fcee29a; the after-merge test run passed. The hook now claims and releases nothing when `CLAUDE_CODE_SESSION_ATTENDED` is `"0"`, which Claude Code sets for every `claude -p` agent-session, or when `NEDSCHORUS_SESSION_REINCARNATION_OWNED_BY_CALLER` is set; `typed_by_user` still decides for an attended agent-session. Alerts a headless agent-session had already claimed go back to `pending/` on the user's first typed prompt 30 minutes or more after their last claim, by the existing release, so nothing was built for them.
