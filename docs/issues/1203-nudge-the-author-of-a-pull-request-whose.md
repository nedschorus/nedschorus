# Nudge the author of a pull request whose review findings have gone unanswered for hours

A pull request whose review asked for changes waits until its author agent-seat pushes a fix, and no program tells that agent-seat, or the user, when the agent-seat has stopped working on the fix; since 2026-10-12 merge-lane-2's seat-brief tells it to do so by hand, but it has sent no such reminder, as "What exists today" shows. This GHI builds a nudge: when a pull request has had changes requested and no new commit for about an hour, a program nudges its author agent-seat, naming the pull request and asking the agent-seat to continue; "How the nudge works" says how. A nudge to an author that is in fact still working costs one message. Whether the nudge also brings the user a question the author is waiting on is an open point below.

This was part (b) of GHI [Wake idle agent-seats that have unfinished work, after a usage limit resets and after a change request goes unanswered](https://github.com/nedschorus/nedschorus/issues/1152), which the user approved filing on 2026-10-09 (about 17:20Z, "y") as item 7 of merge-lane-2's approval-walk merge-lane-2-waiting-on-user-walk-2026-10-07 (minutes `nedlern@ned-box:/home/nedlern/agents/merge-lane-2/docs/walk/merge-lane-2-waiting-on-user-walk-2026-10-07-minutes.md`, an untracked file in merge-lane-2's checkout). On 2026-10-12 the user narrowed that GHI to the 5-hour session limit, under the new title "Wake an agent-seat when its 5-hour session limit resets", and asked for this part to be its own GHI ("5 - separate issue"), in prime-intellect's agent-session bafa2657-92ad-439d-ac19-89fdad69d71e.

## Why

Most pull requests merge fast: of the 306 merged from 2026-09-29 to 2026-10-07, 184 were open for under half an hour, and the median was 20 minutes (`gh pr list --state merged --search "merged:2026-09-29..2026-10-07"`, measured 2026-10-09). A pull request whose author has stopped after a change request waits as long as the author stays stopped, and the user does not watch pull requests, so nobody notices.

## What exists today

- **Watching pull requests.** `scripts/watch-open-pull-requests-nbd.py` polls open pull requests and prints an event when one opens or gets a new head commit. It does not report how long a change request has gone without a commit.
- **A watch that does not expire.** On 2026-10-09 merge-lane-2 stopped watching open pull requests with Claude Code's Monitor tool, whose watch expired after 30 minutes, and started waiting in the background with no time limit, until an event arrives. An agent-seat or subagent that waits this way cannot lose a result to an expired watch, the cause of the 24.5-hour stall above; the nudge still catches an author that stops for any other reason.
- **merge-lane-2 already sends the nudge by hand, after one hour.** The section "When a pull request's author stops answering" of merge-lane-2's seat-brief, `nedlern@ned-box:/home/nedlern/agents/merge-lane-2/CLAUDE.local.md` (machine-local, not in the repository), applies when a pull request has requested changes and its author has pushed nothing and said nothing for an hour. merge-lane-2 first reads the findings, and when the findings question the pull request's design, it asks the user whether to close the pull request instead. Otherwise merge-lane-2 checks the author's agent-seat with `scripts/recover-crashed-seats.py --dry-run <agent-seat>`, brings a dead agent-seat back with the same script, sends a live agent-seat a reminder with SendMessage, Claude Code's cross-session messaging tool, and tells the user when the agent-seat cannot be reached or runs on the Mac. When the author has still pushed nothing and said nothing an hour after the reminder, or an hour after merge-lane-2 told the user, merge-lane-2 hands the pull request to an idle agent-seat on ned-box, which pushes the fix and tells the author. The user approved the section on 2026-10-12, about 04:00Z ("Y - if they have been fast cold-read"), as item 10 of merge-lane-2's approval-walk merge-lane-2-open-items-walk-2026-10-05 (minutes `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/merge-lane-2-open-items-walk-2026-10-05-minutes.md`). ## How the nudge works

The user decided these on 2026-10-14 and 2026-10-15, in prime-intellect's approval-walk prime-intellect-open-decisions-for-the-user-2026-10-13, item 20 (minutes `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/prime-intellect-open-decisions-for-the-user-2026-10-13-minutes.md`), after the evidence above showed the manual reminder had not been sent.

- **The program replaces merge-lane-2's manual reminder.** The section "When a pull request's author stops answering" of merge-lane-2's seat-brief changes with the program: merge-lane-2 stops reminding authors by hand. merge-lane-2 keeps the two parts that need judgment: asking the user whether to close a pull request whose findings question its design, and handing a pull request whose author still has not answered to an idle agent-seat.
- **When.** The program nudges once a pull request has had changes requested and no new commit for about an hour, the wait merge-lane-2's manual procedure used.
- **How the nudge reaches the author.** An author agent-seat that is busy is nudged by a hook in its own session, for example a Stop hook that raises the nudge at the end of a turn, as `scripts/agent-seat-due-task-raise-hook.py` raises an agent-seat's due tasks. An idle author agent-seat, which no hook in its session reaches, is woken by a cross-session message, and the program checks that a live agent-session received it. Nothing types into an agent-seat's tmux window: the user ruled that out ("tmux is dangerous because it steps in the middle of other typing"). An author agent-seat that is not running is brought back first with `scripts/recover-crashed-seats.py`, as the manual procedure did. When the author agent-seat cannot be found or reached, or runs on the Mac, the program tells the user.
- **One nudge per stall.** An hour after a nudge with no commit and no reply from the author, merge-lane-2 hands the pull request to an idle agent-seat, as before; it learns that the nudge went out from the log.
- **A log.** The program records each nudge in the log-store, and whether a commit or a reply from the author followed within an hour, so that whether nudges work can be read from the log.

## Deferred-decisions

1. **Which agent-seat is the author.** Every agent-seat pushes as the same GitHub account, so the pull request's author field does not name the agent-seat; the commits' author name (prime-intellect's commits carry `prime-intellect`) or the branch's checkout may. When no running agent-seat matches, the nudge goes to the user instead.
2. **What counts as changes requested**; proposed: a review in the state `CHANGES_REQUESTED`, not dismissed, with no later commit on the pull request. Open with it: whether a reply from the author without a commit also stops the nudge, and which review's time starts the hour when a pull request has several.
3. **An author waiting on the user**: whether the nudge also brings the user a question the author is waiting on, how the program would tell that the author is waiting, and how the question would reach the user.
4. **How the program hands a nudge to a busy author's hook, and how it tells a busy author agent-seat from an idle one.** The user ruled that a hook nudges a busy agent-seat and a message wakes an idle one; the mechanism between the program and the hook, and the check that a message reached a live agent-session rather than a stale entry (GHI 1115 above), are the build's.

## Next action

Put points 1 to 3 under "Deferred-decisions" to the user; point 4 is the build's. Then build the nudge with a test that feeds it a pull request with a change request older than the threshold and no later commit, and checks that it sends one nudge naming that pull request to its author agent-seat, and none for a pull request that has a newer commit.
