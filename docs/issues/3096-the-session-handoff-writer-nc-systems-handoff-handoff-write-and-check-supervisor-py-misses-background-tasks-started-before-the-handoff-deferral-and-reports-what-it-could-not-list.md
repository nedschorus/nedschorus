# The session-handoff writer nn-systems/handoff/handoff-write-and-check-supervisor.py misses background tasks started before the handoff-deferral and reports what it could not list only after writing

## What is wrong

When an agent-session hands off, `nn-systems/handoff/handoff-write-and-check-supervisor.py` writes the session-handoff and records in it the work still running, so the successor knows what to start again. The successor needs that record because the session-handoff stops every background Bash task of the agent-session. Of the three gaps this issue named, part 2 is open, checked here against main at 91543284b. Part 1, in the same script, is fixed in the writer, but an instruction that still describes the old behaviour remains; part 3, in a script that reads the same transcripts, is fixed.

### 1. Only background tasks started during the handoff-deferral were listed: fixed in the writer

The writer kept a background Bash task only when it was launched at or after the moment the handoff-deferral began, so a task started earlier and still running was stopped at the session-handoff without being listed, and a session-handoff that was not deferred listed no background task at all. Pull request [#3689](https://github.com/nedsnodes/nedsnodes/pull/3689), merged on 2026-11-15, fixed it: `background_task_fields_for_this_session` in `nn-systems/handoff/handoff-write-and-check-supervisor.py` now lists every background Bash task still running, whatever its launch time, as the field `background-task-N`, and `nn-systems/handoff/session-handoff-field-names-common.py` names the old field `background-task-started-during-handoff-deferral-<n>` as retired. The user approved the change on 2026-11-13 05:10Z as item 37 of approval-walk md-skills-questions-waiting-2026-11-05 (walk-minutes `nedlern@ned-box:/home/nedlern/agents/MD-skills/docs/walk/md-skills-questions-waiting-2026-11-05-minutes.md`); the commit, 02908cdd3, calls the change that item's Part 1.

One piece of this part's proposal is not done: it also proposed removing the instruction that tells the agent to name earlier tasks by hand. That instruction is `NEW_WORK_DURING_HANDOFF_DEFERRAL_INSTRUCTION` in `scripts/handoff-context-threshold-hook.py`, whose current wording pull request [#3095](https://github.com/nedsnodes/nedsnodes/pull/3095) set on 2026-11-20, after #3689 merged. On main at 91543284b it still says the writer names "each background Bash task that started since this handoff-deferral began and is still running", and then says "A background Bash task started before the deferral and still running is named, with its command, in the next-step file when the successor must run it again; otherwise it is stopped at the session-handoff." Both sentences describe the writer as it was before #3689.

### 2. The writer reports what it could not list only after the session-handoff is written

In main at 91543284b, `write_handoff_and_report_supervisor` calls four functions first, `spawned_subagent_roster_for_this_session`, `background_task_fields_for_this_session`, `handoff_deferral_fields_for_this_session` and `background_task_past_wait_limit_fields_for_this_session`, then `write_handoff_file`, and prints their reports only after that. When one could not read what it needs, its report says what was left out and asks the agent to supply it: the roster's report ends "Name any subagents in the next step by hand."; the background-task report ends "Name in the next step, with its command, any background task still running that your successor must restart."; the handoff-deferral's report, which now covers only the cold-read-full-run commands refused during the handoff-deferral, ends "Find them in this session's dialog, and run this script again with a next step that names them."; and the report on background tasks past their wait-limit says "The session-handoff is already written." and tells the agent to run the script again with a next step that names each such task. When the writer finds a handoff-supervisor watching, the same output then says "Stop working now and wait — it takes over within seconds." The next step is already written by then, so the agent can add the missing work only by rerunning the script, and the watching handoff-supervisor may end the agent-session first. The work left out then never reaches the successor, and the script has exited 0. When the writer cannot tell whether a handoff-supervisor is watching, it exits 2 and prints "Do not rerun this program: the handoff is already written, and a second one would replace it.", which contradicts the handoff-deferral report and the report on background tasks past their wait-limit, the two that tell the agent to run the script again.

Proposed: when any of these reports names work it could not list, the writer prints the report and exits nonzero before `write_handoff_file`, so the agent names the work in the next step and reruns before anything takes over; the exit code follows #2476. This reverses the current design: `nn-systems/handoff/handoff.system.design.md` says, for the spawned-subagent-roster, the background-task fields and the handoff-deferral fields, that when the writer script cannot read what it needs it writes no such field and tells the agent to name the missing entries in the next step; and the docstrings of the four functions say they report failures without blocking a session-handoff, or never raise. It also needs a way to write the session-handoff anyway once the next step names the work by hand, because a failure that a rerun does not cure, such as `CLAUDE_CODE_SESSION_ID` being unset, would otherwise block every session-handoff. The writer can tell those failures apart itself: it could refuse only on a failure a rerun might cure, such as a transcript line still being written, and write the session-handoff on the rest.

A simpler alternative needs no refusal and keeps the design: the writer writes each failed report into the session-handoff as a field of its own, which the handoff-supervisor puts in the successor's initial-agent-instructions, so the successor learns what was not listed whatever the agent does. Both ways change the design, so this part waits on the user's ruling too.

### 3. The idle sweep missed Workflow-tool agents' transcripts: fixed

`scripts/agent-seat-idle-sweep-verdicts-print.py` left the transcripts of the agents that Claude Code's Workflow tool starts, under `subagents/workflows/<workflow run>/agent-*.jsonl`, out of the verdict's `last_activity`, so an agent-seat whose only work was a running workflow could be judged idle. Pull request [#3538](https://github.com/nedsnodes/nedsnodes/pull/3538), merged on 2026-11-13, fixed it: `verdict_for_seat` now takes its subagent transcripts from `threshold_hook.session_subagent_transcript_paths` in `scripts/handoff-context-threshold-hook.py`, which also returns the Workflow-tool agents' transcripts, and `scripts/agent-seat-idle-sweep-verdicts-print-test.py` checks that a transcript under `subagents/workflows/<run>/` counts and that the workflow run's `journal.jsonl` does not.

## Why it matters

The open gap, part 2, lets running work be lost at a session-handoff without anyone being told: it decides what the successor learns about work the writer could not list.
