# main-gatekeeper — the single check-in gate (design: nc-systems/main-gatekeeper/main-gatekeeper-design.md)

**Remaining before the gate goes live — as ruled, superseding the 2026-08-10 list that stood here (slice 6 was ruled not built 2026-08-17; the account and token exist since 2026-08-29):** the gate opens a pull request instead of pushing to main (ruled 2026-08-29; the program still pushes directly); **at activation the merge lane keeps reviewing and approving the gate's pull requests, so review-at-the-gate (2026-08-17) is met by review at the pull request the gate opens, and a reviewer attached to the gate itself is a later addition (ruled 2026-09-14 at the merge-lane seat; wording merge-lane's, the user's whole reply "shape 1")**; **what the gate's pull request carries and how it merges, ruled 2026-09-15 at the merge-lane seat: shape A** — the pull request carries the single candidate commit the gate composes, and the merge lane reviews, approves and merges it as a merge commit pinned to the approved commit, exactly as it merges every pull request now (the user's whole reply was "a"; the record, with the shapes not chosen, is the slice plan § What the gate's pull request carries and how it merges — ruled 2026-09-15); the per-file staleness report (below); the move onto the dedicated Unix user and deployed copy (C2). Still open: the check battery's owner (below); cross-machine callers (C8). Build order goes in the slice plan, not here. The gate is dormant until that lands.

**Open (2026-08-14) — does this build own the check battery?** The [toolchain plan](https://github.com/nedschorus/nedschorus/blob/main/docs/cross-project/nc-python-toolchain-plan.md) § Phase 1, headed "built with the gatekeeper, step 7", specifies `nc-checkin-quality-gate` — gitleaks plus `ruff`, `mypy` and `pytest` on every check-in. Measured on main 2026-09-15: zero hits for those tool names in this build's specification, its bindings, or the program itself; only the slice plan names them, inside the § Open item 3 that records this disagreement. All five slices are built, so the gate runs no style check, no type check, no test suite and no secret scan. The ruling needed is which document governs. Detail: the slice plan § Open item 3.

**Requirement added 2026-08-31 (user-ruled): the gate reports per-file staleness at check-in.** For every path a check-in carries, the gate says whether main has changed that same path since the check-in's base commit, naming how many commits and the latest pull request — a report, never a refusal, because the false-positive case is real and a refusal that misjudges wedges the caller. This is slice 8, and nothing enforces it in the interim. The requirement in full — the user's ruling quoted, why it belongs to the gate rather than to a session hook, why per-file rather than a branch-level count with the measurement behind that, and the interim accepted deliberately — is the slice plan § The per-file staleness report — slice 8's requirement.
