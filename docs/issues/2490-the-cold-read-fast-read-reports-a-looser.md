# The cold-read-fast-read reports a looser word used where an SDLC-term fits, and an SDLC-term used with a meaning other than its standard one

`CLAUDE.md` tells every agent to name a software-engineering concept by its SDLC-term, and `docs/nedschorus-wiki/nedschorus-sdlc-terms.md` lists the SDLC-terms the project relies on. Agents still write a looser word where an SDLC-term fits, such as "error" for a finding, or use an SDLC-term with a meaning of their own. A reader then has to guess which meaning is meant, and a search for the standard term misses the passage. The cold-read-fast-read, `nc-systems/cold-read/cold-read-fast-read.py`, reads every document before it goes to the user, but its prompt never reads the SDLC-terms page and asks only for "undefined terms" (the prompt at `nc-systems/cold-read/cold-read-fast-read.py:271` and :285 on origin/main at the time of filing). This GHI adds that check to the cold-read-fast-read. Owner: reboot-test.

## What exists today

It relies on the cold-read-cell's own knowledge of standard terms and does not read the SDLC-terms page either.
- The cold-read-full-run reads only the documents the /cold-read skill's step 2 sends to it, and its triage declines findings on lines a pull request did not change. So a loose term the full run flags in older text stays: case 1 below was flagged in `CLAUDE.md` on 2026-10-29 and declined as outside that pull request's topic (`nedlern@ned-box:/home/nedlern/nedschorus-logs/cold-read-records/CLAUDE-2026-10-29-2/triage.md`, lines 3-5), and the term has since spread to another GHI-MD.

The "failure" and "finding" lines the user approved on 2026-10-20 have not landed; reboot-test lands them in a pull request of their own, which is on its task list.
