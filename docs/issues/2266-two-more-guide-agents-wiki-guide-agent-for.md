# Two more guide-agents: wiki-guide-agent for the wiki, and agent-instructions-and-hooks-guide-agent for how the project instructs and controls its agents

ghi-guide-agent answers other agents' questions about the GHIs, and answers "not-about-issues" to any question about the wiki or the code (`docs/issues/46-ghi-guide-agent-design.md` § What ghi-guide-agent is). This GHI-MD is the design of two more guide-agents, the class ghi-guide-agent belongs to: wiki-guide-agent, which answers questions about the wiki, `docs/nedschorus-wiki/`; and agent-instructions-and-hooks-guide-agent, which answers questions about how the project instructs and controls its agents, through agent-instructions, hooks and the refusals hooks give. It says what each returns, which parts of ghi-guide-agent's code they share, how much memory they take on ned-box, and which steps need judgment.

A guide-agent, in the entry the user approved for the glossary on 2026-10-30 (item 23 of the approval-walk agent-instructions-editor-open-decisions-2026-10-26), which is now in `docs/nedschorus-wiki/nedschorus-glossary.md` on main, is "a long-lived agent that answers other agents' questions about one domain (the GHIs, PRs, the wiki, one system) and keeps that domain's knowledge current. It is not an agent-seat: a script runs it one question at a time, with no seat-brief and no handoffs, and the user does not talk to it. ghi-guide-agent is the first." "One question at a time" means each invocation of the script carries one question. GHI [Dynamic agent-team model: sparring pairs, on-tap domain experts, spy-triaged oversight (design capture; research pending)](https://github.com/nedschorus/nedschorus/issues/26), `docs/issues/26-dynamic-agent-team-model.md` § The three tiers, item 2, already lists the wiki among the domains such agents cover, and sets the class's lifecycle: no process between questions, and a fresh cold start of the stored agent-session, which `docs/issues/46-ghi-guide-agent-design.md` calls reincarnation, on triggers a script can observe.

## Why

- `CLAUDE.md` tells every agent to read the style guide, to read the glossary when it meets a term it does not know, and to apply the naming page before it names anything. Other wiki pages, such as `docs/nedschorus-wiki/nedschorus-which-changes-need-the-users-approval.md`, an agent reads only when it knows to look. A rule read early in a long agent-session can have faded from the agent's context by the time it applies, and a rule on a page the agent never opened is not applied at all. The wiki is 19 files and 265,695 characters on main (measured 2026-10-30, `docs/nedschorus-wiki/*.md`, the queue excluded): too much for a working agent to re-read whenever it needs one rule, and small enough for one agent to hold whole.

## What each guide-agent returns

On item 23 the user said, 2026-10-30 (same walk-minutes, line 349): "It may be that there are guide agents and info agents. The info agents just report info and the guide agents do more than that. But it's so tempting to, and useful potentially, to turn any info agent into a guide agent because usually you want more than just raw info." So a reply to a question in the domain has two parts: citations, each giving a file and the text in it that the reply relies on; and guidance, which says what the cited text means for the asker's case and what to do.

**wiki-guide-agent** answers a question such as "may a hook's refusal cite a pull request?" with:

1. Citations: each wiki passage that rules on the question.
2. Guidance: what the rule means for the asker's case; where two passages disagree, both of them and which the agent judges to govern, and why; where the wiki says nothing on the question, that it says nothing; and which glossary term to use for a thing the question names in other words.

**agent-instructions-and-hooks-guide-agent** answers a question such as "an agent keeps forgetting to run the tests before pushing; what should make it?" with:

1. Citations: the agent-instructions, hooks and settings that already act on the case, and the passage of the techniques page whose flowchart picks the technique.
2. Guidance: the technique it recommends, why it fits this case, and what it would take to build; and, when the asker wants agent-instructions or a Claude Code setting changed, how to get the change made, quoting `CLAUDE.md` and agent-instructions-editor's seat-brief, `nedlern@ned-box:/home/nedlern/agents/agent-instructions-editor/CLAUDE.local.md`, as they read at the time of the ask. Quoting them, rather than restating them in its own prompt, keeps the guidance right when either file changes.

**A question outside the domain.** The shared module holds a table of the guide-agents, each with its ask script and its domain in one line, and each cold-start prompt includes it. A question partly in another guide-agent's domain gets a reply for its own part and the names of the guide-agents to ask about the rest. A question wholly outside the domain gets a reply of the kind `out-of-scope`, with the guide-agents to ask, or none when no guide-agent covers the subject, such as most of the code. Code checks that each name is in the table. A question on how to make agents do something belongs to agent-instructions-and-hooks-guide-agent. While the table has no row for it, code adds to wiki-guide-agent's cold-start prompt a sentence telling it to answer such questions from the enforcement ladder page.

**Neither agent changes any file.** The `claude -p` invocation allows only the Read, Grep and Glob tools. agent-instructions-editor changes agent-instructions and Claude Code settings, with the user's approval; the two guide-agents answer questions. The two jobs are meant not to overlap, and the builder confirms it: once agent-instructions-and-hooks-guide-agent's cold-start prompt is written, and before its pull request opens, the builder reads the prompt against agent-instructions-editor's seat-brief, and removes from the prompt any duty the seat-brief gives agent-instructions-editor, leaving guidance that sends the asker there.

**Keeping the domain's knowledge current.** For now this means only that each reply is drawn from the domain as it is on main (§ What each has of its own). A guide-agent that finds a contradiction, a stale passage or a gap says so in its guidance to the asker; it records nothing. Recording such finds in proposed-improvements-or-changes-files must wait: the user decided on 2026-10-27 that only GHI-MDs and architecture overviews get such files until the handler of GHI [Proposed improvements or changes to a GHI are handled by agents first, and reach the user only when they need him](https://github.com/nedschorus/nedschorus/issues/1132) has run for a week (`docs/issues/1132-concerns-about-a-ghi-are-handled-by-agents.md`, § Decided by the user). When that question comes back to him, it includes whether the guide-agents record their finds.

## The reply, and how code validates it

Each reply is a JSON object that `claude -p --json-schema` constrains, as GHI [ghi-guide-agent answers with a JSON object checked against a schema, so its callers stop sorting its prose replies](https://github.com/nedschorus/nedschorus/issues/2159) plans for ghi-guide-agent: its kind, its citations, its guidance, and the guide-agents to ask. The kind is `out-of-scope` for a question wholly outside the domain, and `answer` otherwise, including a reply for part of a question and a reply that the domain says nothing, whose citations may be empty. Each citation has a path, a quote, and, for a Markdown file with headings, the heading of the section the quote is in; for any other file it has no heading. A reply that does not fit the schema is a failed ask, as GHI 2159 says.

Code on ned-box, where the whole ask runs, validates each citation against the files the agent read: the repository checkout at the commit the ask used, or, for a file outside the repository, a file on the list of such files that code gave the agent (§ What each has of its own). The path exists; for a Markdown file the heading is a heading of that file; and the quote is text of that section, or of the file when it has no headings, such as a hook. When a citation fails, the agent gets one more turn in the same agent-session, within what is left of the ask's 300 seconds: one message naming each failed citation and asking for a corrected reply. The corrected reply replaces the first whole and is validated again. When the second turn fails or runs out of time, the first reply stands as it came. Either way, each citation that still fails is marked "not found in the checkout at <commit>" in the reply, and the verdict line says `answer-with-unverified-citations` instead of `answer`, so an asker that branches on the verdict sees it. The asker reads the file itself before acting on such a citation. The ask still succeeds.

## What they share with ghi-guide-agent, and what each has of its own

`scripts/ghi-guide-agent-ask.py` holds both kinds of code today. The parts that do not depend on the domain move into one shared module, `scripts/guide-agent-ask-scripts-common.py`, which `scripts/ghi-guide-agent-ask.py` and each new guide-agent's own ask script import:

- the re-run over ssh on ned-box when the script runs where the guide-agent's checkout is not, with the host and the checkout's path given by each ask script;
- the state file and its lock, one of each per guide-agent's checkout, and what happens when an ask finds another ask running, as `scripts/ghi-guide-agent-ask.py` does it when the build starts: today, the second ask runs in a throwaway agent-session of its own. When the fork that `docs/issues/46-ghi-guide-agent-design.md` § Decided and not yet built, item 1, plans is built, all guide-agents get it there;
- the `claude -p` invocation (`run_claude`), with `--setting-sources user`, `NEDSCHORUS_SESSION_REINCARNATION_OWNED_BY_CALLER`, the variable that keeps the handoff hook from answering in the agent's place, `CLAUDE_CODE_TMPDIR=/home/nedlern/.cache/claude-code-tmp` set in its environment, a list of the tools the agent may use, and `--json-schema` when the caller gives a schema. ghi-guide-agent gives none until GHI 2159 is built, so its replies and its tests stay as they are;
- the 300-second timeout, and the two reincarnation triggers that do not depend on the domain: the transcript's size, and the share of the context window in use.

Each guide-agent has its own:

- **ask script**, `scripts/wiki-guide-agent-ask.py` and `scripts/agent-instructions-and-hooks-guide-agent-ask.py`, with its own agent-facing-messages. It exits 0 with any reply, printing a verdict line naming the reply's kind and then the reply as JSON, and 1 with a failed ask, printing one line on stderr that says why: the user approved exactly this for ghi-guide-agent on 2026-10-24, item 9 of the approval-walk reboot-test-all-open-items-2026-10-22, "no code above 2, so ghi-info-ask's codes 2 and 3 go" (walk-document `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/reboot-test-all-open-items-2026-10-22.md` line 140). ghi-guide-agent keeps its exit codes until that item is built.
- **checkout** on ned-box, `~/agents/<guide-agent name>`, made the way ghi-guide-agent's is, which the ask script fast-forwards to origin/main before each ask. When the fast-forward fails, the ask goes ahead on what the checkout holds, and the script's output says which commit that is and that it is behind main. Neither new agent needs a mirror.
- **domain file list**, which the ask script computes on every ask. For wiki-guide-agent: every Markdown file under `docs/nedschorus-wiki/` outside `queue/`, except files whose name holds `-proposed-improvements-or-changes-`, which hold proposals, not rules; and each system glossary that the project glossary lists at its top. For agent-instructions-and-hooks-guide-agent: the techniques page and each repository file it links to, without following links inside those files; a link that is not a repository file on main is left out, and the cold-start prompt lists it. The ask script puts the contents of the domain file list into the cold-start prompt, so no file is skipped or cut short. agent-instructions-and-hooks-guide-agent also reads, when a question needs it, any agent-instructions file or hook in the checkout, and the files on ned-box that git does not track whose paths code lists in its cold-start prompt: each `~/agents/*/CLAUDE.local.md` and `~/agents/*/.claude/settings.local.json`, and `~/.claude/CLAUDE.md` and `~/.claude/settings.json`, which Claude Code loads into every agent-session on ned-box.
- **freshness trigger**. The state file records the commit of main the stored agent-session was cold-started from, and the domain file list it loaded. When any file in the domain file list changed since that commit, or the list itself changed, the ask cold-starts a new stored agent-session before it asks. A domain the size of the wiki loads in one cold start, so this costs little, and it means a reply never comes from a page main has since changed, renamed or deleted.
- **size limit**. When the domain file list exceeds a token limit, the cold start does not run and the ask fails, with an agent-facing-message naming the domain's size, the limit and this GHI, so the asker falls back to reading the files itself.
- **cold-start prompt and schema**.

## Memory on ned-box

On 2026-10-30, two `claude -p` invocations on ned-box held 260 MB and 264 MB of resident memory; each of the six interactive agent-seats then running held 507 MB to 846 MB (`ps -eo rss`), and `free` showed 46 GB available. ned-box has 59.6 GB of RAM and no swap. The kills GHI 1834 traced came from the Bash-guards replay check, from timeshift's hourly snapshot, and from the 21 GB held in the `/tmp` tmpfs.

The two guide-agents add no process between questions. An ask runs up to three `claude -p` invocations one after another, the cold start, the question and the correction turn, so it adds about 260 MB while it runs. Asks from different agent-sessions, or from one agent-session's parallel tool calls and subagents, run at the same time with nothing to stop them, as ghi-guide-agent's do today: ten at once would add about 2.6 GB. The shared `run_claude` sets `CLAUDE_CODE_TMPDIR`, so their temporary files go to `/home/nedlern/.cache/claude-code-tmp/` on disk, not to the `/tmp` tmpfs, even for an ask that arrives over ssh from the Mac.

Nothing more is built against memory. `CLAUDE.md` allows a guard only when the failure has happened or concrete evidence shows it is foreseeable within 30 days, and it would lose or damage work. The kills on ned-box have happened, but none came from asks, and asks of this size come nowhere near the memory free on 2026-10-30.

wiki-guide-agent's domain is about 66,000 tokens, before the system glossaries are added. ghi-guide-agent's corpus, with the GHI-MDs its open GHIs link to, measured near 200,000 tokens on 2026-09-19 (`docs/issues/46-ghi-guide-agent-design.md` § The GHI mirror). The size of agent-instructions-and-hooks-guide-agent's domain is not known yet: the techniques page exists only on a branch and in the user's uncommitted rewrite on the Mac.

## Who asks them

- **wiki-guide-agent.** Any agent at the moment it needs a wiki rule, such as when it writes a refusal, a file name or a glossary term. The build adds one sentence to the `CLAUDE.md` bullet that sends agents to the style guide, saying to ask wiki-guide-agent when a wiki rule is needed later in the agent-session; Codex agents read `CLAUDE.md` through `AGENTS.md`. That sentence relies on the agent remembering it, which is the problem this GHI-MD starts from, so the build also adds a line telling the agent to ask wiki-guide-agent to the agent-facing-message of each hook that fires at a moment a wiki rule applies and that no other check already covers. `scripts/new-shared-names-reminder-hook.py` does not qualify: it already sends names to the new-name-propose-and-check-fresh-agent subagent, which checks them against the naming page. The pull request description lists each hook the builder considered and why it qualifies or not.
- **agent-instructions-and-hooks-guide-agent.** An agent that has found a mistake agents repeat and must choose how to stop it, and an agent-seat writing an approval-walk item that proposes a hook or a change to agent-instructions. The build adds a line telling the agent to ask agent-instructions-and-hooks-guide-agent to the step of the walk-me-through skill where an agent writes an item, for an item that proposes such a change, and to the refusal of `.claude/hooks/instruction-file-guard.py`, naming each guide-agent for the files it covers: wiki-guide-agent for a wiki page, agent-instructions-and-hooks-guide-agent for agent-instructions and settings. GHI 1849's approval-walk holds proposed new wording for that refusal (items 7 and 8), so this change waits until the user decides those items.

## Judgment and code

Each guide-agent is code-prompt-code. The judgment steps, done by the agent: choosing which passages answer the question; writing the guidance, including the glossary term for a thing the question names in other words and which of two disagreeing passages governs; for agent-instructions-and-hooks-guide-agent, choosing the technique; deciding that the question is partly or wholly outside the domain, and which guide-agents to name; and correcting a reply whose citations failed validation. Everything else is code: the fast-forward, the domain file list, its contents in the cold-start prompt and its size limit, the list of files outside the checkout, the freshness trigger, the lock, the invocation of `claude -p` with its tools, schema and folder for temporary files, the timeout, the reincarnation triggers, the validation of citations and of guide-agent names, the verdict line, and the exit codes.
