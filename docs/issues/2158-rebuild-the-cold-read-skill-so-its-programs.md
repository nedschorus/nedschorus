# Rebuild the /cold-read skill so its programs do the mechanical steps and print each instruction when the agent needs it

## Why

The /cold-read skill, `.claude/skills/cold-read/SKILL.md`, is 2,983 words of prose that an agent reads before it has a document cold-read. Three programs do part of the work: `nc-systems/cold-read/cold-read-fast-read.py`, `nc-systems/cold-read/cold-read-grid.py` and `nc-systems/cold-read/cold-read-record-ship.py`. Much of the prose tells the agent what a program already decides or prints. Steps 6 and 7 together are 1,294 words, and step 6 spends most of its 683 words explaining what each line the grid prints means.

The user prefers code to prose wherever code can do a step correctly, with prompts kept for the steps that need judgment, and code built to fail gracefully so that an agent can take over; the rebuilt /cold-read is such a code-prompt-code. In the agent-seat cold-read-improvement's agent-session on ned-box on 2026-10-21 the user said: "generally mechanical solutions are better than prose in every way, assuming they're correctly constructed. And even then, if they fail gracefully, the agent can take over and do the same thing."

Keeping the same instruction in the skill and in a program's agent-facing-messages already breaks a rule of the design. `nc-systems/cold-read/cold-read-design.md` says that the grid "prints the next steps for the reviewing agent, which the skill does not repeat". The skill repeats it anyway. The grid prints "Keep your judgments provisional until you have read all six", or "every report that landed" when a report is absent, and step 7 of the skill says "keep your judgments provisional until every cold-read-cell has reported or failed". Item 5 of the cold-read-design approval-walk found this on 2026-10-21; its walk-document is `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/cold-read-design-2026-10-15.md`. The two copies say the same thing today, but nothing keeps them the same.

The opposite case also occurs: some instructions are only in the prose, although the agent needs them at the moment a program prints something. The grid prints `FELL BACK: <report> — <the cold-read-cell's line>` (`nc-systems/cold-read/cold-read-grid.py:754`), and the cold-read-cell's line ends "The report's provenance stamp records this." with no instruction. What to do about it, "naming that model in `triage.md` if its report drives a change", is in step 6 of the skill, which the agent read before the cold-read-full-run began.

## The work

1. Each program's agent-facing-messages give, at the moment of use, every instruction the agent needs to act on what the program just printed. The work item's one pull request also drops from the skill each instruction that the programs' lines now print, and does the work in this order: the grid's lines, then a closing text for `cold-read-fast-read.py` that gives the next step as the grid's closing text does, then the shipper's `REFUSED:` and `FAILED:` lines.
2. When `cold-read-fast-read.py`, `cold-read-grid.py`, `cold-read-record-ship.py` or a program this rebuild adds catches a failure, it says what it finished, what is left and, for each step left that can be done by hand, the command for it, so the agent takes over where the program stopped. A failure is never reported as success.
3. One entry program takes `--target`, and `--fast` when the user asks for a cold-read-fast-read, and runs the cold-read-fast-read or the cold-read-full-run as step 2 says. From the file's path and front matter it knows which kind of document the cold-read-target is. A GHI-MD whose front matter has the line `kind: design` is a design. From the diff against the merge base of origin/main and the cold-read-target's branch it sees a change only to the section headed `Deferred-decisions` (user-ruled 2026-10-23, approval-walk cold-read-skill-rebuild-ghi-md-decisions-2026-10-22, item 3, approved as obvious). What the program cannot see, the agent declares with a flag carrying its reason, such as `--leaves-what-it-tells-unchanged "corrects the path to the shipper"`: that a change leaves unchanged what the document tells a program or an agent to do, and what it decides or plans. The rewrite that answers a cold-read-full-run, and the commit that carries out the user's rulings on it, get the cold-read-fast-read with no flag; a later cold-read-full-run of the changed file is maintenance's job (user-ruled 2026-10-26, approval-walk cold-read-skill-rebuild-so-programs-do-the-mechanical-steps-2026-10-23, item 1). On such a flag the entry program runs the cold-read-fast-read instead of the cold-read-full-run, and writes the flag and its reason into the cold-read-record, where a reader can check the claim later (user-ruled 2026-10-23, approval-walk cold-read-skill-rebuild-ghi-md-decisions-2026-10-22, item 4, approved as obvious). The entry program passes `--user-ruled-cold-read-full-run-count-restart` and `--cold-read-full-run-count-skipped-inside-design-to-main` through to the grid.
4. `nc-systems/cold-read/cold-read-fast-read.py` reuses the phrase matching, and the filters for the glossaries and the ordinary-words list, of `scripts/new-shared-names-in-changed-files-list.py`, without its filter of names origin/main already has, to append to its report each hyphenated phrase in the whole document that is neither in a glossary nor on `docs/nedschorus-wiki/nedschorus-ordinary-hyphenated-words-list.md`. Step 1's message to the user, which proposes key-terms, moves to just after the cold-read-fast-read of step 3, and also lists the phrases the agent judges ordinary words used in their ordinary sense, such as "one-line"; and adds to `docs/nedschorus-wiki/nedschorus-ordinary-hyphenated-words-list.md` only each one the user approves (user-ruled 2026-10-23, approval-walk cold-read-skill-rebuild-ghi-md-decisions-2026-10-22, item 6, approved). `cold-read-fast-read.py` skips text in backquotes, such as a file name or a flag, whose names `docs/nedschorus-wiki/nedschorus-how-to-choose-a-name-for-files-code-and-glossary-terms.md` governs. Each phrase the user declines goes on a list of declined hyphenated phrases beside the list of ordinary hyphenated words, added in the same pull request as the approved words, and `cold-read-fast-read.py` skips the phrases on both lists (user-ruled 2026-10-28, approval-walk cold-read-skill-rebuild-so-programs-do-the-mechanical-steps-2026-10-23-remaining-items, item 1, approved). Once the user has answered the phrases listed, the agent copies his words, from his answer to the message that lists the phrases, into `.walk-approved` before each edit, as the instruction-file guard asks, and, in one separate pull request from origin/main, adds the phrases he approves to the list of ordinary hyphenated words and the phrases he declines to the list of declined hyphenated phrases (user-ruled 2026-10-28, approval-walk cold-read-skill-rebuild-so-programs-do-the-mechanical-steps-2026-10-23-remaining-items, item 2, approved).
5. A program builds the diff and the list of the findings the agent declined. The diff runs from the frozen-copy that the change's first cold-read-fast-read read, which the program finds among the document's cold-read-records, to the document as last committed, compared as two files, so the fresh-agent sees every change made since the first cold read, the fixes from that cold-read-fast-read included (user-ruled 2026-10-29, approval-walk SKILL-cold-read-2026-10-28, items 2 and 2.1, approved, on the user's question "is this cpc?"). The program launches a fresh-agent with the diff and the list, and does not show it the agent's own picks, and writes the fresh-agent's picks into the cold-read-record's `triage.md`. The program runs the fresh-agent with a JSON schema for its answer, a list of picks, so an empty list means it picked nothing (user-ruled 2026-10-28, approval-walk cold-read-skill-rebuild-so-programs-do-the-mechanical-steps-2026-10-23-remaining-items, item 6, approved after an advisor check). When the fresh-agent fails, or its answer does not fit the schema, the program says so, and the agent says so in the approval-walk's opening, or in the one line when there is no approval-walk, as step 9 asks (user-ruled 2026-10-23, approval-walk cold-read-skill-rebuild-ghi-md-decisions-2026-10-22, item 5, approved as obvious).
6. The skill shrinks to the judgment steps: which phrases are key-terms and which are ordinary words, revising, triage, deferral, what goes to the user, and asking the user. For every other step it says only which program to run, and to do what that program prints. Step 2 keeps only the cases the entry program cannot see.

Each work item is its own pull request. Work items 1, 2 and 4 need no design. Work items 3 and 5 are built from one design, which names the two programs and their flags other than `--target` and `--fast`. Work item 6 is built from a design of its own (user-ruled 2026-10-28, approval-walk cold-read-skill-rebuild-so-programs-do-the-mechanical-steps-2026-10-23-remaining-items, item 3: parts 1 and 2 approved, part 3 disapproved). The grid's flags stay as they are, because the design-to-main agent-instructions queued in `docs/agents/queue/`, such as `docs/agents/queue/design-to-main-design-writing-agent-instructions.md`, run the grid with `--cold-read-full-run-count-skipped-inside-design-to-main`.

Step 2's rule, which the entry program encodes, changed in a pull request of its own, https://github.com/nedschorus/nedschorus/pull/1889, merged on 2026-10-24, from items 1, 2, 7, 8 and 10 of approval-walk cold-read-skill-rebuild-ghi-md-decisions-2026-10-22: CLAUDE.md needs a cold-read-full-run; a change is exempt from the cold-read-full-run when it leaves unchanged what the document tells a program or an agent to do and what it decides or plans, or when it touches only the section headed `Deferred-decisions`, and gets the cold-read-fast-read instead; and a change only to the bulleted list of `docs/nedschorus-wiki/nedschorus-ordinary-hyphenated-words-list.md` gets no cold read. The entry program encodes step 2 as that pull request leaves it.
