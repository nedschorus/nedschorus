# ruling-agent keeps user-rulings, checks approval-walk items against them

Agents keep asking the user to decide what he has already decided, because nothing finds his earlier decision at the moment an agent needs it. This GHI builds `ruling-agent` and its code: one store of the user's user-rulings and verbatim words, a small index file of them that hooks read, and a program that checks each approval-walk item against his user-rulings before the item is shown. ## What ruling-agent keeps and reads

- **His words, verbatim**, each with its UTC time and a link to its line in the transcript it came from, and with the agent message he was answering. The index program, described below, reads them from both machines' transcripts, queued_command attachments included, and tags each message with the GHIs, pull requests, tasks and systems named in the agent message he was answering; a file named only there is tagged by its system, so a file is a tag only when he names it himself.
- **Agent-proposed notes**, kept only when he approves them as an approval-walk item, each with tags, triggers and a review date on which it goes back to him to keep or drop. A note's triggers name the moments GHI 30's hooks may show it: one or more of `read`, `edit` and `approval-walk-item-written`. A note lapses earlier when everything it is tagged to is closed or deleted. He said "User rulings quickly become obsolete" (`re-ask/prime-intellect.md` line 44).
- **The session dialogs.** These are the readable text of each agent-session, extracted from its transcript into `nedlern@ned-box:/home/nedlern/nedschorus-logs/session-dialogs/` every 10 minutes by `scripts/log-store-session-dialogs-refresh-nbd.py`. Asked about a tag, `ruling-agent` reads the session dialogs around the stored quotes, so its answer gives each quote in the discussion it came from: "the quotes should be in context of other discussions" (reboot-test walk-minutes line 182).

**Tags.** A tag is one of `GHI <number>`, `PR <number>`, `task <agent-seat> <id>`, a system, or a repository path he named. A system tag is the system's directory, `nc-systems/<system>/`, or the system's glossary name for a system that has no directory yet. Item 5.2's system wiki-page tag and this system tag are one key. A file is a tag only when he names that file: "often my messages are more about systems, which would mean more about directories than specific files" (reboot-test walk-minutes line 182).

## The store, the lookup and the index file

**The store.** Item 5.2's database, `nedlern@ned-box:/home/nedlern/nedschorus-logs/user-rulings/standing-user-rulings-decided-by-the-user-full-text-searchable.sqlite3`, not yet created, holds every entry: his verbatim words, the notes he approved, and the user-rulings recorded in walk-minutes. An entry is standing, superseded or lapsed; a lapsed entry is a note he dropped at its review, or one whose tagged items are all closed or deleted. A lookup returns only standing entries. Nothing is deleted.

**Pairs.** Item 5.2 has `ruling-agent`'s prompt judge whether a new entry conflicts with a held one, and links two conflicting standing entries as a pair; two entries with the same tags and different texts are not a pair unless the prompt judges them to conflict. A lookup that finds one entry of a pair returns both. His ruling on a pair is one of item 5.2's three outcomes: one entry is superseded by the other; one or both are changed, each changed entry superseded by his new wording; or all stand, and each entry notes the other, so the pair is not shown to him again. A pair is unreviewed until he rules on it.

**The lookup.** The code half of `ruling-agent` takes tags and key phrases and returns standing entries, newest first. The item check adds `ruling-agent`'s prompt, which judges whether each user-ruling it finds agrees with the item or goes against it.

**Writes.** `ruling-agent`'s code half, item 5.2's "Code", does every write. The index program is part of that code and runs on ned-box without `ruling-agent`'s prompt, because a prompt turn every minute would only run a program. Every write from another agent or program, such as a note he approved, his answer on a pair or a user-ruling sent at walk close, goes through the planned `scripts/ruling-agent-ask.py` to `ruling-agent`, which writes one entry at a time with the write commands of `scripts/standing-user-rulings-edit-and-approval-walk-item-check.py`, as item 5.2 says; only `ruling-agent` runs those commands. `scripts/ruling-agent-ask.py` works from either machine; it waits for an answer up to a timeout, then prints what failed and exits nonzero. Nothing is queued: the asking agent tells the user, and does not record the user-ruling elsewhere as stored. `ruling-agent` reuses the machinery of ghi-info, from GHI [Build ghi-info — the GHI knowledge agent](https://github.com/nedschorus/nedschorus/issues/46), `docs/issues/46-ghi-info-agent-design.md`: its `*-ask.py` wrapper, a resumed `claude -p` session restarted when it grows too large, and code that runs every write command and checks that each user-ruling a reply cites exists. Both are instances of the on-tap domain experts of GHI [Dynamic agent-team model: sparring pairs, on-tap domain experts, spy-triaged oversight (design capture; research pending)](https://github.com/nedschorus/nedschorus/issues/26).

**The index program and the index file.** The index program reads the raw transcripts that `scripts/transcript-mirror-to-log-store.py` mirrors into `nedlern@ned-box:/home/nedlern/nedschorus-logs/agent-session-files-by-machine/` every minute, and the walk-minutes of every ned-box agent-seat, `/home/nedlern/agents/*/docs/walk/*-minutes.md`, with the shipped walk-minutes under `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/`. It adds what is new to the store, then writes the index file from the store: one small file holding each standing quote and note with its tags, date and transcript-line link. A job on ned-box runs it each minute, after the transcript mirror, and `ruling-agent`'s code runs it again after each other write. It also writes, for GHI 30's hooks, the anchor list: resolved literal strings, never patterns, namely the tagged repository paths, the tagged `nc-systems/<system>/` directories, and each tagged GHI's GHI-MD path on origin/main. Pull request and task tags have no file, so they have no anchor: GHI 30's hooks reach them only if GHI 30 adds a moment for `gh` and task tool calls, and until then only the item check does. The index file records when it was built. The transcript index proposed in agent-instructions-editor's task #60 (`nedlern@ned-box:/home/nedlern/.claude/tasks/nedschorus-agent-instructions-editor-tasks/60.json`) is this same index program.

**What reads the index file.** GHI 30's hooks read it as it stands, because GHI 30's design proposes a budget of 25 ms for a hook (`docs/issues/30-trigger-first-instruction-delivery-design.md` line 66); when the mirror and index runs succeed it is about 2 minutes old at most, and a hook prints its build time. A check that can wait, such as the item check or an answer of `ruling-agent`, has `ruling-agent` run the index program first, so it is current to that moment, as item 17.2 says, once the index program reads the newest transcript lines (see Deferred-decisions); until then it is current to the last transcript mirror pass. A grep over the index file took under 10 ms on a 10,000-quote test index, against 0.68 s for a grep over all session dialogs (reboot-test walk-minutes line 195).

**A summary in the background.** A hook of GHI 30 may start `ruling-agent` in the background to write a summary of his quotes on a tag, which arrives a minute or two later.

## The check before an approval-walk item is shown

Once the planned `scripts/standing-user-rulings-edit-and-approval-walk-item-check.py` is on main, a sentence based on item 5.3's replaces the paragraph that begins "Before you first show any item" in `.claude/skills/walk-me-through/SKILL.md`, section "Each item": "After you draft an item, run `scripts/standing-user-rulings-edit-and-approval-walk-item-check.py check <walk-document> <item>` and do what it prints." Item 5.3's sentence began "After you draft an item with a #new line"; item 17.1 dropped that condition, because carried and revised items are where his user-rulings were re-asked. The agent runs it on every item before the item is first shown; open question 9 asks whether it runs again after a revision. The `check` subcommand writes nothing to the store. It asks `ruling-agent` through `scripts/ruling-agent-ask.py` to run the index program and look up the item's tags, its key phrases, and the file and section it concerns, and to judge each user-ruling found; it always writes a #rulings_checked block into the item, and prints one of these, which the agent then does:

- **Decided:** record the item in the walk-minutes as decided, citing the user-ruling; it keeps its number and place in the count, and is not shown.
- **Partly decided:** record the decided part likewise, and show only the rest.
- **Changes a ruling:** change the item to follow the user-ruling, as item 5.3 says, or, when a real defect needs the change, open the item with "You ruled <the ruling> on <date> (<citation>); this changes it because <the defect>.", so that he decides.
- **Rulings disagree:** show him both user-rulings in the item, and ask him which of item 5.2's three outcomes applies, and send his answer with `scripts/ruling-agent-ask.py`.
- **Done:** no user-ruling bears on the item, or the item already says why it departs from one.

The check is run by the agent, not by a hook, because it waits for `ruling-agent`'s judgment, which cannot fit a hook's budget; item 17.2 names it as a check that can wait. GHI 30's hook at the Write of `docs/walk/<name>.md` separately shows the newest matching quotes. A planned addition to the current-item Stop hook, `nc-systems/skills/walk-me-through/walk-me-through-current-item-shown-to-user-after-each-agent-message-stop-hook.py`, stops any reply that shows an item without a #rulings_checked block.

**When the lookup fails.** When the store cannot be read, ned-box cannot be reached or `ruling-agent` does not answer, the program writes a #rulings_checked block quoting the error, marks the item held, prints what failed, and exits nonzero. The agent tells the user what it printed, does not search by hand, and shows the item only after a later check prints one of the five outcomes above; open question 7 asks what the approval-walk does meanwhile.

- A decision given only in an agent's summary, with no words of his, does not enter.
