# Relaunch stopped agent-seats with open tasks daily

Once a day, a scheduled job finds every agent-seat whose task list still holds open tasks while no agent-session of that agent-seat is running, and relaunches each one, supervised, so the work on its list is picked up.

## Why

Work handed to an agent-seat lives on that agent-seat's task list. When the agent-seat stops and nothing brings it back, the work stops with it, and no one is told. The user raised this on 2026-10-02 while ruling how a request waiting in review is followed up (walk ghi-3-main-gatekeeper-specification-cold-read-findings-2026-10-01, item 7; minutes at `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/ghi-3-main-gatekeeper-specification-cold-read-findings-2026-10-01-minutes.md`): "Typically what should be done in daily maintence is to reincarnate any agents that have work to do. That could be mechanized I'd think as we do that stuff through scripts." He then approved filing it as its own issue, because it covers every task left on a stopped agent-seat, not only that one case.

Example: an agent-seat records a task to answer a review on its pull request, and its agent-session ends that evening with no successor. Without this job the task waits until someone happens to relaunch that agent-seat. With it, the next morning's run sees an open task on an agent-seat that is not running and relaunches the agent-seat, and the new agent-session reads its task list and does the work.

## What exists today

Every piece the job needs is built; nothing joins them on a schedule.

- **Reading the task lists.** `scripts/seat-task-list-read.py --seats` prints one line per task list with its agent-seat, machine, open count and total. Run on the Mac it reads both machines' stores (the Mac's over the filesystem, ned-box's over `ssh nedlern@ned-box`); run on ned-box it reads ned-box's store alone, because ned-box has no route to the Mac. It reads the store on disk, so it is not affected by the harness's `TaskList` reading empty when an agent-session has lost its task-list id (the defect recorded under GHI [Runtime-behavior research bundle: instruction compression + deliberate scrub, instruction precedence, output styles, context clearing, names reviewer, memory maintenance](https://github.com/nedschorus/nedschorus/issues/29)).
- **Deciding whether an agent-seat is running, and bringing it back.** `scripts/recover-crashed-seats.py <seat>...` assesses each named agent-seat and acts on what it finds: a live agent-session is left alone; an agent-session that died without a session-handoff is resumed from its last real transcript under the handoff-supervisor; a recorded clean exit, or a leftover idle shell, is asked about on the operator's terminal rather than restarted. Run with no terminal, as a scheduled job runs it, it asks nothing: a recorded exit is reported `NOT RELAUNCHED` and the agent-seat is left down. `--dry-run` reports every decision and launches nothing. Its design is GHI [Crash recovery for seats that died without a handoff: find the last live transcript, resume it supervised](https://github.com/nedschorus/nedschorus/issues/120) and GHI [recover-crashed-seats.py: the six changes ruled 2026-09-02 — exit record, process-identity liveness, parking marker, verified restart, by-hand resume, window](https://github.com/nedschorus/nedschorus/issues/242).
- **Launching.** `scripts/launch-claude-mac <name> [--no-attach] [--first-prompt-file <path>]` and `scripts/launch-claude-ubuntu <name> [--no-attach] [--first-prompt-file <box-path>]`, run from the Mac, attach to an agent-seat's tmux session or create it, with the handoff-supervisor inside. When an unconsumed session-handoff is waiting for the agent-seat, the new agent-session starts from it; this is the path for an agent-seat that stopped after writing a session-handoff, where `recover-crashed-seats.py` serves one that stopped without writing one.
- **Restarting after a reboot.** `scripts/restart-live-seats-at-login.py` restarts the agent-seats that were running when the machine went down, selected from the supervisors' heartbeats: GHI [Fleet survives a machine restart without losing seat context: detect, hand off on notice, relaunch at boot, resume from transcript](https://github.com/nedschorus/nedschorus/issues/116). That job selects by "was running at the stop"; this one selects by "has work to do", so it also covers an agent-seat that stopped days before a reboot, or with no reboot at all.
- **Scheduling.** `nc-systems/general-tools/scheduled-jobs-on-each-machine.json` lists each scheduled job and where it runs, and `nc-systems/general-tools/install-scheduled-jobs-on-this-machine.py --install` makes each machine's crontab and launchd jobs match it. The table holds `transcript-mirror-to-log-store` and `daily-full-test-run-of-main` (03:30 on both machines). This job is one more row.

## What is not decided

1. **What counts as work to do.** An open task is `pending` or `in_progress`. An agent-seat whose only open tasks wait on someone else, a pull request in review for example, would be relaunched every day only to check and stop. The same holds for an agent-seat that makes no progress on its tasks: it would be relaunched every day without end. Accept that cost, mark such tasks as waiting, relaunch only when something a task waits on has changed, or stop relaunching an agent-seat after some number of days without progress and report it instead.
2. **An agent-seat stopped on purpose.** `recover-crashed-seats.py` asks the operator before restarting an agent-seat whose exit was recorded, and a scheduled job has no operator. For the boot-time restart the user ruled "I'd just restart anything that looks like it was accidentally shut down at roughly the time of shutdown. It's easy to shut down an agent that isn't useful." Whether this job relaunches an agent-seat with a recorded exit, or only lists it for the user, needs his word.
3. **A retired agent-seat.** Retiring an agent-seat must first close its open tasks, or copy them by hand to another agent-seat's list and close them, or this job revives it the next morning. GHI [Before a seat is retired, report what still cites the paths the retirement removes](https://github.com/nedschorus/nedschorus/issues/226) is where retirement already reads the live task lists.
4. **Which machine runs it.** Only the Mac reads both machines' task stores and launches agent-seats on both. A run on ned-box sees ned-box's agent-seats alone, and a run on each machine would try to launch ned-box's agent-seats twice.
5. **When it runs, and what it reports.** After the 03:30 test run and before the user's day is one choice. The run should say what it relaunched and what it left alone and why. Its log goes to the `output` path its row in the table names, as the other jobs' logs do; whether a summary also reaches the noon step, the daily review a Mac agent-seat is asked for from noon Pacific (`memory_review_due_lines` in `nc-systems/handoff/handoff-supervisor.py`), is part of this point. When ned-box's `claude` is logged out, the run reports that and stops trying ned-box, per GHI [Tell the user when ned-box's claude is logged out or ned-box's subscription has run out](https://github.com/nedschorus/nedschorus/issues/337). A crash-recovered ned-box agent-seat currently runs without its own GitHub token, GHI [A crash-recovered ned-box seat runs without its own GitHub token, and the Mac launcher warns of a missing token when it only attaches](https://github.com/nedschorus/nedschorus/issues/759), and this job would hit that as often as it relaunches one.

## Next action

Put points 1 to 5 to the user. Then build the job as one program run from the scheduled-jobs table: it selects with `scripts/seat-task-list-read.py`, relaunches an agent-seat that stopped after writing a session-handoff with its launcher and one that stopped without writing one with `scripts/recover-crashed-seats.py`, and has a dry-run option of its own that reports what it would do and launches nothing, run first on the machine point 4 chooses.
