# One shared reader of a transcript's subagent start, resume and finish events for scripts/handoff-context-threshold-hook.py and nc-systems/handoff/handoff-write-and-check-supervisor.py

Two programs each read, with code of their own, the same events in an agent-session's transcript: a subagent started, a subagent was resumed by SendMessage, and a subagent finished, by a final task-notification or by a TaskStop. `scripts/handoff-context-threshold-hook.py` reads them in its function `work_in_flight`, to decide whether any subagent is still running before it lets a session-handoff start. `nc-systems/handoff/handoff-write-and-check-supervisor.py` reads them in its function `spawned_subagent_roster`, to list each subagent and its last event in the session-handoff. Whenever Claude Code starts recording one of these events in a form that one program's parsing code does not recognize, both programs' code has to be fixed, and a fix made to one alone leaves the two programs disagreeing about whether a subagent is running: the hook may let a session-handoff start while the roster lists the subagent as still working, or the hook may wait on a subagent the roster lists as finished. The next action: move both programs onto one shared reader of start, resume and finish events, and give both programs the same transcripts in their tests.

## Why this is filed

The same kind of gap has been fixed twice since the two readers were written:

- PR [Threshold hook's transcript scan counts a subagent resumed by SendMessage as in flight](https://github.com/nedschorus/nedschorus/pull/2926), merged 2026-11-11, taught `work_in_flight` to read a resume, which `spawned_subagent_roster` already read. Its `#root_cause` line says the two parsers were left separate "because the roster skips a line that does not parse while the hook refuses on one, and one shared parser is a design change of its own". Its Claude reviewer, posting as `mac-claude`, noted the second parser in `spawned_subagent_roster` and did not raise it as a finding, because the pull request's description declared it as a design choice.
- PR [Idle sweep and session-handoff: count a subagent or background command stopped by TaskStop as finished, and a later resume as in flight](https://github.com/nedschorus/nedschorus/pull/3059), merged 2026-11-11, had to teach both readers that a TaskStop ends a subagent, because Claude Code writes no task-notification for a task that TaskStop stops.

No one has seen the two readers disagree on a real transcript; this is a concern judged from reading the code. ## What is shared today, and what is not

`handoff-write-and-check-supervisor.py` already loads `handoff-context-threshold-hook.py` as the module `threshold_hook`, uses its constants `TASK_STOP_TOOL_RESULT_MARKER_KEY` and `BACKGROUND_TASK_LAUNCH_KEY`, and calls `threshold_hook.work_in_flight` for background tasks. It does not share the reading of subagent events: `spawned_subagent_roster` walks the transcript itself, matching spawn results (`status` `async_launched`), resume results (the key `resumedAgentId`), TaskStop results, and task-notifications in user, queue-operation and attachment records, and keeps for each subagent a description, a spawn time, and its last event with that event's time, counting a repeat of the same notification as an echo rather than a new event.

The two readers differ on purpose in one way that the shared reader has to keep. `spawned_subagent_roster` skips any transcript line that does not parse, because the roster must never block a session-handoff. `work_in_flight` raises `TranscriptCouldNotBeFullyRead` when a line that holds a spawn, resume or background-launch marker does not parse, because a scan that missed one of those must not be taken to mean that nothing is running; it ignores a TaskStop line that does not parse, because missing a stop only leaves the task counted as running.

Two things stay in `work_in_flight` and are not part of the shared reader: its reading of background-command launches, which it does in the same pass over the transcript, and its check of a subagent's own transcript when that subagent's last notification is interim.

## What to do

1. Write one function, in a module both programs import, that reads a transcript once and returns, for each subagent, each spawn, resume, interim or final task-notification, and TaskStop that names it, in transcript order, each with its time, and the spawn with its description. Return every event as read, echoes included, so each caller keeps its own rule for them. The function takes a required argument for a line that holds one of these events' markers but does not parse, with the two choices raise, which raises `TranscriptCouldNotBeFullyRead`, and skip, so that no caller can leave its rule out. Where the module lives, a new module of its own or the hook itself, is the builder's choice; `scripts/claude-code-subagent-task-notification-interim-recognizer-common.py` is the existing module both programs already import for interim notifications.
2. Rewrite the subagent part of `work_in_flight`, and `spawned_subagent_roster`, as callers of that function: `work_in_flight` passing raise, except for TaskStop lines as today, and `spawned_subagent_roster` passing skip. If `work_in_flight` then reads the transcript twice, once for subagents and once for background-command launches, say so in the pull request.
3. Add tests that give the same transcripts to both programs and check that they agree on each subagent: the hook's `spawned_subagent_ids_in_flight`, which calls `work_in_flight` without reading subagents' own transcripts, lists a subagent exactly when the roster's last event for it is one of the events in `STILL_WORKING_SUBAGENT_LAST_EVENTS` in `handoff-write-and-check-supervisor.py`. Cover at least a spawn, a final notification, an interim notification, a resume after a final notification, a TaskStop, a resume after a TaskStop, an interim notification that arrives after a TaskStop, two subagents in one transcript, and a line that does not parse.
4. Before and after the rewrite, run both programs over the agent-session transcripts kept on ned-box and compare, for each subagent, whether `spawned_subagent_ids_in_flight` lists it and the roster's last event, by the same rule as step 3; report each subagent on which the two disagree, and each subagent whose result the rewrite changed.
