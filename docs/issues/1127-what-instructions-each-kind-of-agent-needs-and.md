# What instructions each kind of agent needs, and where each kind's instructions live

This is a design task. The project runs three kinds of agent: long-lived agent-seats, such as merge-lane-2; ghi-info, a specialist that also lives long; and specialists started fresh for each job, such as pull request reviewers, cold-read-cells and builder subagents. Each kind gets its standing instructions from a different place today, and some of those places are outside the repository. This GHI asks for a design that says which instructions each kind needs, where each kind's instructions live, and how they are written.

## Why

- The written account of where an agent-seat's brief lives is false. The glossary's seat-brief entry and step 3 of `docs/agents/seat-first-prompt.md` name `docs/agents/<seat>-instructions.md`, but PR [docs/agents/ no longer holds the six seat instruction files no agent loads](https://github.com/nedschorus/nedschorus/pull/905) deleted every such file, because nothing loaded them after an agent-session's first start. Step 3 of the first prompt tells a new agent-seat to stop and ask the user when its brief does not exist, so every agent-seat started from that prompt now stops there. The launchers pass the prompt only when given `--first-prompt-file`, so an agent-seat launched without it never meets step 3.
- The most important brief is in no repository. `~/agents/merge-lane-2/CLAUDE.local.md` on ned-box, 365 lines, holds how merge-lane-2 reviews and merges every pull request. `.gitignore` excludes `CLAUDE.local.md`, so the text has no pull request history, no review, and no copy beyond ned-box's Timeshift snapshots.
- On 2026-10-05, in agent-session fleet-restart-at-login, the user proposed that a brief live in the repository with `CLAUDE.local.md` saying only to read it. Before anything moved he stopped the work: "I realized that the GHI-info agent is unusual in that it's long lasts. Many other specialized agents would work best if they were aways fresh. I guess fresh agents could be give some instructions in the claude.md, but since they are short lived, maybe that doesnt matter. However it may change how those instructions are written. so let's back up from 161 and figure out what we are trying to do first." Task 161, "ON HOLD — first decide what instructions each kind of agent needs: seat-briefs in the repository with a CLAUDE.local.md pointer", on agent-seat fleet-restart-at-login's task list (`python3 scripts/seat-task-list-read.py --seat fleet-restart-at-login --task 161`) holds the repository-brief plan, on hold until this design is settled. On 2026-10-09 he approved routing the design to a GHI.

## What is not decided

1. **The kinds.** Whether the three kinds above are the right split, and where agent-instructions-editor, a long-lived agent-seat with a narrow job, and ghi-info fall.
2. **What each kind needs.** Which instructions a fresh specialist needs beyond its job prompt, and whether `CLAUDE.md`, which every agent loads, should be written for all kinds or should shrink so that a fresh specialist reads less.
3. **Where each kind's instructions live.** For a long-lived agent-seat: the repository with a one-line `CLAUDE.local.md` pointer (the plan of task 161, named under Why), `CLAUDE.local.md` alone, or something else. For a fresh specialist: a prompt file the launching program reads, as reviewers have now, or text inside the program, as ghi-info has now.
4. **How each kind's instructions are written.** The user said the answer "may change how those instructions are written": for example, a fresh specialist's instructions name one job and its output, and a long-lived agent-seat's name a subject it owns.
5. **What follows.** Correcting the glossary's seat-brief entry, `docs/agents/seat-first-prompt.md` step 3, and the sentence of `docs/agents/seat-session-appended-system-prompt.md` that puts a rule belonging to one agent-seat in that agent-seat's `CLAUDE.local.md`; and the order in which existing instructions move.

## Next action

Put points 1 to 4 to the user, with the table above, in an approval-walk. From his rulings write the design, then reopen task 161, named under Why, or replace it.
