# A consumed session-handoff read as waiting, so a dead agent-session's conversation was not resumed

A supporting document of GHI [Handoffs become one pending file per session, archived only after a successor is up](https://github.com/nedschorus/nedschorus/issues/754), whose GHI-MD is `docs/issues/754-handoffs-become-one-pending-file-per-session-archived.md`. It records one event that the specification there would have prevented, and a direction proposed after it.

On ned-box at 2026-10-21T21:20:25Z (14:20 Pacific), the agent-session `658fc3c4-2e3f-4a86-bba4-117a093897a0` of the agent-seat `fleet-restart-at-login` ended between turns, with no error and no session-handoff. Its transcript is `nedlern@ned-box:/home/nedlern/.claude/projects/-home-nedlern-agents-fleet-restart-at-login/658fc3c4-2e3f-4a86-bba4-117a093897a0.jsonl`. That agent-session had been started on 2026-10-14 from the session-handoff written at 2026-10-14T21:13:32Z with `restart-counter: 27`, so that handoff had been consumed.

The agent-crash-watcher, `nc-systems/handoff/handoff-agent-seat-died-without-session-handoff-restart-watcher.py`, read that session-handoff, `~/.claude/handoffs/fleet-restart-at-login-handoff.md` on ned-box, as waiting. Its decision log, `nedlern@ned-box:/home/nedlern/nedschorus-logs/handoff-agent-seat-died-without-session-handoff-restart-watcher/decisions.jsonl`, records the verdict `defer-to-boot-ignition` at 21:22:01Z, then at 21:23:01Z "not restarted: a handoff waits that no supervisor acted on; user told", with the detail "an unconsumed handoff waits (counter 27, consumed None)". So the agent-seat was not resumed from its own transcript, which is the path GHI [The handoff-supervisor resumes a session that died without a handoff, instead of stopping the seat](https://github.com/nedschorus/nedschorus/issues/613) and change 5 of GHI [recover-crashed-seats.py: the six changes ruled 2026-09-02 — exit record, process-identity liveness, parking marker, verified restart, by-hand resume, window](https://github.com/nedschorus/nedschorus/issues/242) built for an agent-session that dies without a handoff.

The user relaunched the agent-seat when the watcher told him to. The handoff-supervisor's boot ignition started a fresh agent-session, `a03d3ebc-544a-4e0e-b30d-d75c77a68e86`, whose first prompt is the 2026-10-14 handoff's next step, with no conversation-tail. That agent-session first offered the user item 8 of a 2026-10-14 approval-walk, which he had answered a week earlier. A week of open questions had to be recovered by hand from the dead transcript, and two files that existed only in the dead agent-session's `/tmp` scratchpad were copied to `nedlern@ned-box:/home/nedlern/nedschorus-logs/seats/fleet-restart-at-login/`.

The agent-seat `prime-intellect` died in the same minute, at about 21:20:01Z, and the same log shows the same reading for it: "an unconsumed handoff waits (counter 2, consumed None)". Why both handoff-supervisor state files, `~/.claude/handoffs/fleet-restart-at-login-supervisor-state.json` and `~/.claude/handoffs/prime-intellect-supervisor-state.json` on ned-box, read `consumed_counter` as None was not found, and is still open. `fleet-restart-at-login`'s state file now holds `generation: 1`, which is what a fresh state (`fresh_supervisor_state` in `nc-systems/handoff/handoff-supervisor.py`, generation 0) reaches after one boot ignition; that suggests, and does not show, that the file had been replaced by a fresh one at some time after 2026-10-14.

Under the specification in that GHI-MD, the 2026-10-14 handoff would have been archived once its successor was up, so on 2026-10-21 no pending file would have existed and the watcher would have resumed the dead transcript. A novelty test kept in a separate state file fails whenever that file is lost or reset; the presence of a pending file does not depend on one.

A direction proposed on 2026-10-22 by the agent-seat `fleet-restart-at-login`, which the user has not ruled on: when a successor is started from a session-handoff after an agent-session died without writing one, it also gets a conversation-tail extracted from the dead agent-session's transcript, as `scripts/handoff-extract-conversation.py` extracts one, and is told how old its session-handoff is.

What to do with it: whoever builds GHI [Handoffs become one pending file per session, archived only after a successor is up](https://github.com/nedschorus/nedschorus/issues/754) takes this event as a case the build must pass: a consumed session-handoff and a dead agent-session that wrote none, where the correct outcome is that the dead agent-session's transcript is resumed; and brings the proposed direction to the user with the eight questions in that GHI-MD. The direction covers what consume by removal does not: the case question 8 of that GHI-MD names, a pending session-handoff left by an earlier agent-session, as when its successor never came up, beside a later agent-session of the same agent-seat that then dies without writing one.
