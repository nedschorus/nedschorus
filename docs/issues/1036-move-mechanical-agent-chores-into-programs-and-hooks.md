# Move mechanical agent chores into programs and hooks

Agents in this project are told, in skills and standing instructions, to do by hand eleven chores that a program, a hook or a scheduled job could do. Each chore costs every agent that does it some attention, and an agent that forgets one leaves the work undone, with nothing to report the gap. This GHI lists the eleven, says for each what already exists on main, and sizes what is left as small or large, so that the user can choose which to build first.

## Why

The user asked, in reboot-test session 1961bf92 on the Mac at 2026-10-02T21:45:56Z: "why run by hand when they can just be scheduled? Why give agents extra burden? Are there other things that can be shifted from agents to automation?" A survey of the standing instructions on main that day found the eleven chores below. The user approved filing this GHI at 2026-10-02T21:59:30Z, in the same session: "Y - but this might be tricker than it seems - as agents handle all sorts of problems, errors, special cases smoothly, so a script might have to pass back to the agent anything it stumbles on or something like that. So not easy to really test. But on the other hand they might be really sinple changes".

## The principle every chore follows

The program does only the normal case. Anything else stops and goes back to the agent with a plain message saying what failed, as CLAUDE.md's failure-reporting rule requires: print what failed and exit nonzero, or put the failure in the text the agent reads next. The program never tries to handle the special cases an agent handles; it only recognises that a case is not the normal one.

This also bounds the tests. Each build's tests check two things: the normal case works, and each unexpected case is reported to the agent rather than handled. The user accepted this answer to his concern in the same session, at 2026-10-02T21:59:51Z.

For example, a pre-push hook that runs the test selection lets the push through when every selected suite passes. When a suite fails, it refuses the push and prints the suite's name and its failing cases, and the agent fixes the test. When the test lock is held, or the test runner cannot start, it refuses the push and prints what it could not do; it does not wait, retry or guess.

Some chores below are only reduced, not removed: chores 6 and 11 become one command the agent runs in place of several steps, and the agent can still forget that command. The table says which.
