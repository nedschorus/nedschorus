# A replacement for the approval marker file through which the user approves an edit to a file the instruction-file guard protects

This is a design task. Today an agent that wants to edit a file the instruction-file guard protects quotes the user's approving words into a file named `.walk-approved`, and the guard lets one edit through when that file holds any text. This GHI asks for a design that replaces the marker with a way of approving that the guard can trust, that works when nobody is watching the agent-session, and that the user is willing to use.

## Why

- The guard cannot tell whose words the marker holds. `consume_approval_marker` in `.claude/hooks/guard_approval_marker.py` accepts any non-empty text and deletes the file; nothing checks that the user wrote or said the words. The same gap is why `.claude/hooks/backup-and-snapshot-write-guard.py` lost its override lane on 2026-08-17 and became a hard-block (glossary, entry hard-block).
- The guard's refusal text has grown to cover the ways cooperative agents went around the marker by accident: moving prompt text into a program's string, editing by another route so the marker was never spent, and quoting approval of something else (`ROUTE_AROUND_LINES` in `.claude/hooks/instruction-file-guard.py`). An unspent marker approves the next guarded write, whatever that write is.
- The user approved starting this design as item 8 of approval-walk nedschorus-where-agent-rules-live-decision-guide-draft-2026-10-05, answering "y" on 2026-10-07 although the agent had recommended keeping the marker (minutes: `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/nedschorus-where-agent-rules-live-decision-guide-draft-2026-10-05-minutes.md`). On 2026-10-09, in agent-session fleet-restart-at-login, he approved routing the design to a GHI.

## What exists today

- **Two guards share one marker module.** `.claude/hooks/instruction-file-guard.py` reads `.walk-approved` at the root of the session's own checkout before an Edit, Write or NotebookEdit of `CLAUDE.md`, `CLAUDE.local.md`, anything under `.claude/`, a `-prompt.md` or `-instructions.md` file, and the reviewed documents under `docs/agents/`, `docs/nedschorus-wiki/` and `nc-systems/skills/` or named `-design.md`. `.claude/hooks/session-location-write-guard.py` reads a second marker, `.location-write-approved`, through the same module. A replacement design covers both, or says why the second keeps its marker.
- **Approval is quoted words in a file.** The marker holds the user's exact words; the guard consumes the marker on the one call it approves. A memory-directory write is refused whatever the marker holds.
- **A standing approval rides the same marker.** `CLAUDE.md` lets an agent fix an obvious error in a guarded file without asking first, by writing "Obvious fix under CLAUDE.md's standing approval:" and the fix into `.walk-approved`. The guard cannot tell this sentence from the user's words.
- **One agent-seat exists to make guarded edits.** agent-instructions-editor on ned-box (its brief is `~/agents/agent-instructions-editor/CLAUDE.local.md`, outside git) shows the user each old and new text, waits for his answer, and writes his words into `.walk-approved` for each edit.
- **Claude Code's own approve-or-deny prompt is unused.** A PreToolUse hook can return `permissionDecision: "ask"`, which shows the user Claude Code's permission prompt for that one call. No hook in the repository returns "ask": in `.claude/`, `scripts/` and `nc-systems/`, `git grep -l permissionDecision` finds four hooks and their tests, and every one of the four hooks returns "deny": `.claude/hooks/ghi-issue-write-redirect.py`, `scripts/synthetic-keystroke-guard-hook.py`, `scripts/search-file-argument-read-as-option-guard-hook.py` and `scripts/force-push-with-open-pull-request-guard-hook.py`.
- **The user's dislike of multiple-choice questions is already enforced.** ned-box's `~/.claude/settings.json` runs `~/.claude/hooks/ask-user-question-tool-refusal-hook.py` before every use of the AskUserQuestion tool, the refusal approved as item 5 of the same approval-walk.
- **What a replacement must update.** Outside `docs/issues/`, twelve files name `.walk-approved`: `.claude/hooks/instruction-file-guard.py`, `.claude/hooks/instruction-file-guard-test.py`, `.claude/hooks/backup-and-snapshot-write-guard-test.py`, `.claude/hooks/session-location-write-guard-test.py`, `.gitignore`, `CLAUDE.md`, `.claude/skills/locate-before-saying-a-file-is-missing/SKILL.md`, `.claude/skills/start-new-agent-seat-on-ned-box/SKILL.md`, `docs/agents/seat-first-prompt.md`, `docs/nedschorus-wiki/nedschorus-fleet-git-worktree-working-model.md`, `docs/nedschorus-wiki/nedschorus-glossary.md` (the entry approved-by-walk) and `nc-systems/main-gatekeeper/main-gatekeeper-design.md` (from `git grep -l walk-approved` on main, 2026-10-09). The second marker, `.location-write-approved`, is named in `.claude/hooks/session-location-write-guard.py`, its test, `.gitignore` and `docs/nedschorus-wiki/nedschorus-fleet-git-worktree-working-model.md`.
- **Search receipt.** `scripts/ghi-info-ask.py --include-closed`, 2026-10-09, asked whether any GHI covers a replacement for the marker. ghi-info answered that none does, open or closed, and named these to read: GHI [wiki-write skill, and the detect-set-aside-ask hook that enforces it — checking the file, not the tool call](https://github.com/nedschorus/nedschorus/issues/343); GHI [MD-placement guidance as symmetric pre-tool remind hooks on both runtimes (boss-directed design, build deferred)](https://github.com/nedschorus/nedschorus/issues/11); GHI [main-gatekeeper — the single check-in gate (design: nc-systems/main-gatekeeper/main-gatekeeper-design.md)](https://github.com/nedschorus/nedschorus/issues/3), for its rule that a guard either honours its override or says plainly that it has none; and GHI [Every refusal and warning a program hands an agent says why and what to do instead](https://github.com/nedschorus/nedschorus/issues/956).

## What is not decided

1. **Approval when nobody is watching.** A `claude -p` agent-session has no one to answer a prompt. An agent-session on ned-box may run while the user sits at the Mac and is not looking at its terminal. A subagent has no conversation with the user at all. For each of these the design says whether a guarded edit is refused, held until the user answers, or approved some other way.
2. **Which interface the user accepts.** Whether Claude Code's approve-or-deny prompt, or a question drawn by a Claude Code mod, is the multiple-choice interface the user dislikes. The walk-document for item 8 said the prompt is close to it.
3. **What the guard reads instead of the marker.** For example the permission prompt's answer, a record the user writes himself, or the user's words found in the transcript by a program. Each choice must say how the guard knows the user, and not an agent, gave the approval. An agent can write any file its tools reach, so a record on disk shows the user's approval only if no agent can write that record.
4. **Obvious fixes.** How the standing approval in `CLAUDE.md` for obvious fixes works without a marker an agent writes itself.
5. **What a mod can do here.** Task 165, "Trial a Claude Code mod: a walk-position line recomputed before each model call; confirm it replaces rather than accumulates; also check whether CLAUDE.md is re-read after compaction", on agent-seat fleet-restart-at-login's task list (`python3 scripts/seat-task-list-read.py --seat fleet-restart-at-login --task 165`), a trial of a Claude Code mod, is pending; its findings bear on points 1 and 2.

## Next action

Then write the design: a short document that answers points 1 to 4, names what each file above that names a marker changes to, and states how the replacement is tested. Put the design to the user in an approval-walk before any code changes.
