# draft-md prompt research report: the defect catalog and the evidence behind each rule ([nedschorus#142](https://github.com/nedschorus/nedschorus/issues/142))

Research record behind the `draft-md` skill, gathered while that skill was designed as three passes — a write pass, a warm conflation cell, and a reconciliation pass — under `docs/issues/142-draft-md-skill-design.md` when it was still named `142-draft-md-passes-and-review-cells.md`. That three-pass design has been superseded: the skill is now one prompt written by one fork. This report is kept for the research, not for the design it was written against, so read its "Detector" column as naming the cells of the superseded design — the warm cell and its checks do not exist in the current skill, and the current skill's own single list is in the specification. A report, not an instruction: it records which defect each rule targets, what covers each defect after the user's rulings of 2026-08-26 and 2026-08-27, and the published evidence each rule rests on, for whoever revises a rule later. Four research runs (two Codex, two Opus, 2026-08-26) produced the findings distilled here; their full reports were session working material and are not kept.

## The defect catalog: one list, two prompt families

Writer prompts and reader prompts are different kinds of text — the writer gets operations to perform while composing, the reader gets questions to ask of a finished page — but they attack the same defects. Keeping one catalog and deriving both families from it means a newly identified defect gets a writer rule and a reader question at the same time, and the two sides cannot drift apart. (`cold-read` already keeps one prompt source for both runtimes, for the same reason.)

| Class | Pole | Writer rule (write pass) | Detector in the superseded three-pass design |
|---|---|---|---|
| Unintroduced term | ellipsis | Explain each project term in the sentence where it first appears; then keep the term. | `restate` stumbles; `defect-hunt` (d) |
| Unnamed referent | ellipsis | Across sentences, name the thing; "it", "this", "the restriction" only for a noun in the same sentence. | `restate`; `defect-hunt` (j) |
| Missing setting | ellipsis | The opening names the system, the purpose, the scope, and the starting state; the actor is each sentence's subject. | `restate` |
| Missing step or precondition | ellipsis | A condition comes before the action it governs; every step states its result, including when nothing changes. | `restate`; `defect-hunt` (e), (g) |
| Missing relation | ellipsis | Where the reader would guess how a sentence relates to the one before, say it with a plain connective. | `defect-hunt` (j) |
| Missing case | ellipsis | Every rule names one case it does not cover. | `defect-hunt` (g); the warm cell's state table |
| Merged referent | conflation | One name per thing; the repository's name when it has one. | The warm cell's check 1; the term-list diff |
| False universal | conflation | — | `defect-hunt` (f) |
| Wrong actor or cause | conflation | — | none (the warm check was cut as unworkable) |
| Identity drift | conflation | One name per thing, throughout. | The warm cell's check 2 |
| Merged sentence | conflation | One claim per sentence, under 25 words. | `restate` stumbles |

## What the evidence supports, by catalog row

Recorded so the next reader can weigh each rule. Full research reports are session working material (four files in the prof seat's scratchpad on ned-box: `codex-research-report.md`, `opus-research-report.md`, `codex-undetectable-report.md`, `opus-undetectable-report.md`); this section is the durable extract.

- **Unintroduced term.** GOV.UK style guide: specialist terms are allowed, "you just need to explain what they mean the first time you use them". Asthana et al. (EMNLP 2024): readers preferred an explanation of a hard concept over a plainer substitute — keep the term, add the explanation. Microsoft Writing Style Guide: "if you must create a new term, verify that it isn't already being used to mean something else" — the one rule found that is a check against the world, which in a repository is a search.
- **Unnamed referent, missing relation.** Clark and Haviland's given-new contract (1974–77): a reader treats a sentence's given information as a pointer to an antecedent in memory and silently builds a bridge when none matches. Google developer style: "helper words such as *then*, *that*, and *of* are frequently left out ... use these words to avoid ambiguity". INCOSE *Guide for Writing Requirements* R24 on pronouns. This project's own referring-phrase specimen (design notes §"A referring phrase names what it refers to").
- **Missing setting.** Joseph Williams, characters as subjects and actions as verbs — and a writer who has merged two components cannot name one actor, so the rule doubles as a conflation check. Red Hat modular documentation: each module makes sense read alone.
- **Missing step, precondition, case.** EARS (Mavin et al., IEEE RE 2009): the `while <precondition> when <trigger>` slot "forces the requirement author to separate the conditions" from the response, and "unwanted behaviour is a major source of omissions"; the Rolls-Royce case study reported omissions apparently eliminated. SCR tabular requirements (Parnas, Heninger): a state-by-event table has visibly empty cells; prose does not. Hillel Wayne's carbon-credit demonstration: readers hunting a bug in the prose failed; the state form exposed it.
- **Merged referent.** Zave and Jackson (1997): a "designation" for every primitive term, grounded in the event that creates the thing ("a message is the result of a particular call to send-msg"), which is what separates a request's identity from its content; "very few requirements methods ... enforc[e] the presence of a designation for every primitive term". Daniel Jackson, *The Essence of Software* (2021): "every concept should have exactly one purpose"; overloading "suggests splitting". The *Ambiguity Handbook* warns a glossary can hold a conflation through one fused definition — which is why the term list is written from the design and diffed against one written from the document, rather than trusted on its own.
- **False universal.** *Ambiguity Handbook* §5.2.1: "in any sentence containing a universal quantifier, there is a danger that the sentence is not true"; INCOSE R32, "each" over "all". "Not Wrong, But Untrue" (arXiv 2509.25498): the dominant hallucination in document-grounded generation was "attribution drift", tentative claims becoming universal facts; enforced citation cut the rate from 40% to 13%. Si et al. (2023): plausible wrong explanations cause overreliance, and a contrasting argument was the one thing that helped.
- **Wrong actor or cause.** ASD-STE100 itself warns that active voice names a false agent when the cause is unknown. Turpin et al. (NeurIPS 2023): a model's stated rationale can misrepresent the real reason for its claim, so a self-explanation is not a check. This class has no structured form that exposes it; labelling and independent verification are all the evidence offers.
- **Identity drift.** The most unanimously prescribed rule in the corpus: Federal Plain Language Guidelines ("don't feel that you need to use synonyms"), Microsoft ("one term, one concept"), ASD-STE100 ("each word has only one meaning"), INCOSE R36.
- **Merged sentence.** ASD-STE100: one instruction per procedural sentence, one subject per descriptive sentence, 20/25-word caps. Google: "the shorter the sentence, the easier it is to translate."
- **The fork mechanism.** Chain-of-Verification (above). "Plausibility as Failure" (arXiv 2512.16750): reviewers facing denser material "increasingly relied on surface cues, allowing erroneous yet well-formed answers to pass as credible" — the reason the conflation reviewer must know the design, not just read carefully.
## What the evidence does not support

- **Structure as a detector.** A glossary holds a conflation if the writer writes one entry for the merged thing; a well-formed table can be false in every cell. Structure is a forcing function that raises the chance the writer notices. The term-list diff is the one place this proposal gets detection by construction.
- **Mandated artifacts in agent tooling.** Böckeler's review of Kiro, spec-kit, and Tessl (martinfowler.com, 2025) found no evidence that their required requirements-design-tasks artifacts reduced errors, and observed agents ignoring specifications they had just written.
- **A writer who never knew.** Every catalog row assumes the writer knew and did not say. If the writer inferred two-things-are-one from a fluent prior, the conflation cell writes a confidently wrong design term list. The human at the end is the only catch for that case.
- **Any measurement of this.** No study tests whether a writer-side prompt improves a zero-context reader's comprehension of the document it produced, and no evaluation method scores confident misreading rather than confusion. The experiment is new; it is specified in the design document under § "Testing the prompt", not here.
