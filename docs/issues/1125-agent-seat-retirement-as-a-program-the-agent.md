# Agent-seat retirement as a program: the agent-seat marks itself retired, the handoff-supervisor confirms with the user and retires it, and the launchers refuse a retired name

This is a design and build task. Retiring an agent-seat, the glossary's retire-seat, is today a list of steps on a wiki page that an agent-session follows by hand. The user's design makes it a program. Before it marks itself, the agent-seat opens the pull request that removes its name from main (step 4 below). It then marks itself retired, for example with a command such as `scripts/retire-agent-seat.py <seat> --mark-retired`, the name proposed by task 156, "Build agent-seat retirement as a program: the agent-seat marks itself retired, and the handoff-supervisor confirms and retires it on exit", on agent-seat fleet-restart-at-login's task list (`python3 scripts/seat-task-list-read.py --seat fleet-restart-at-login --task 156`). When its agent-session exits, the handoff-supervisor, which runs on the agent-seat's own machine, finds the mark, asks the user to confirm, and does the remaining steps; an exit with no mark is handled as today. The launchers refuse to start an agent-seat under a name marked retired.

## Why

- The steps on main have drifted from the code. The "Retired" paragraph of `docs/nedschorus-wiki/nedschorus-agent-seat-model.md` has four steps. Step 2 moves only the session-handoff, leaving the state file, lock and numbered handoffs that a reused name's handoff-supervisor and the login restart read. Step 4 marks `docs/agents/<seat>-instructions.md`, which PR [docs/agents/ no longer holds the six seat instruction files no agent loads](https://github.com/nedschorus/nedschorus/pull/905) deleted. The page misses the agent-seat's tmux server, task list and Claude Code project directories. The retirement of the gatekeeper agent-seat, PR [The gatekeeper agent-seat is retired; the main-gatekeeper's design and plan stay](https://github.com/nedschorus/nedschorus/pull/1008), showed each gap.
- A rewrite of the steps grew to five careful steps, each with checks, after a cold-read-full-run. In approval-walk nedschorus-agent-seat-model-2026-10-04, item 2, the user said that the program which launches and reincarnates agents should let an agent mark itself retired and confirm the retirement on that agent's exit, and he approved building the steps as that program rather than as prose an agent follows (minutes: `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/nedschorus-agent-seat-model-2026-10-04-minutes.md`). On 2026-10-09, in agent-session fleet-restart-at-login, he approved routing the design to a GHI.
- Task lists are keyed by the agent-seat's name (`CLAUDE_CODE_TASK_LIST_ID='nedschorus-<seat>-tasks'`, set by `scripts/launch-claude-mac` and `scripts/launch-claude-ubuntu`). A retired or renamed agent-seat's open tasks stay in its store, where no running agent-session reads them and no one is told.

## What exists today

- **No program retires an agent-seat.** `git grep -i retire` on main over `scripts/` and `nc-systems/handoff/` finds the word only for retiring an agent-session or a tmux session (`scripts/recover-crashed-seats.py`, `scripts/resupervise-seat.py`, `nc-systems/handoff/handoff-write-and-check-supervisor.py`), never an agent-seat. Neither launcher checks for a retired name.
- **The specification is a held local branch.** Branch `agent-seat-model-retire-steps-drift` exists only on ned-box, unpushed, checked out in a worktree of agent-seat fleet-restart-at-login; commit 2a5e9b63, "Agent-seat retire steps match the code and how gatekeeper was retired", through commit b0fce08e, "Retire steps: step 3 removes the worktree and seat-branch and keeps nothing", rewrite the "Retired" paragraph and the glossary's retire-seat entry. Its five steps, as the user approved them in approval-walk agent-seat-retire-steps-drift-2026-10-04 and amended in approval-walk nedschorus-agent-seat-model-2026-10-04, were written for an agent-session to follow by hand on the agent-seat's own machine; in the program, step 1's check becomes the handoff-supervisor's knowledge that its own agent-session has exited:
  1. The user exits the agent-session; `python3 nc-systems/handoff/handoff-supervisor.py --agent <seat> --check` confirms no handoff-supervisor runs, or the steps stop and tell the user; then `tmux -L <seat> kill-server`.
  2. Every file in `~/.claude/handoffs/` whose name begins `<seat>-`, except the files of another agent-seat, one whose directory under `~/agents/` has a name beginning `<seat>-`, moves to `nedschorus-logs/seats/<seat>/retired-agent-seat-YYYY-MM-DD/handoffs/` in the log-store (UTC date; `-2`, `-3` when the directory exists; on the Mac through `/Volumes/nedhome/`, stopping if the mount is absent).
  3. `git worktree remove --force` on the agent-home (or `rmdir` for an empty directory a failed launch left) and `git branch -D <seat>`. Nothing is kept: the user ruled that Time Machine and Timeshift hold it and an agent's work can be redone.
  4. A pull request removes the name from main wherever main names the agent-seat as running or as the owner of a subject, and gives each subject a new owner or says it stops. History keeps the name. The name is not reused until the pull request merges.
  5. Open tasks, listed with `python3 scripts/seat-task-list-read.py --seat <seat>`, are shown to the user, and each is taken by another agent-seat or closed as he decides; then, with his approval, the task directory `~/.claude/tasks/nedschorus-<seat>-tasks/` and each directory under `~/.claude/projects/` whose name ends `-agents-<seat>` move into the retirement directory.
- **The cold read behind the rewrite.** Cold-read-record nedschorus-agent-seat-model-2026-10-04, `nedlern@ned-box:/home/nedlern/nedschorus-logs/cold-read-records/nedschorus-agent-seat-model-2026-10-04/triage.md`, lists every finding and how each was applied; findings F4 and F32 (an agent-seat's tmux session on the default server, and the unprefixed task directory `~/.claude/tasks/<seat>-tasks/`) were left to the program to check.
- **Where a retired mark could live.** The design of GHI [A small service on ned-box keeps one record of every agent-seat on both machines](https://github.com/nedschorus/nedschorus/issues/972) already has a "retired" event and a per-machine table recording whether each agent-seat is retired, sent from its build-slice 3; build-slice 1 merged as PR [Seat-database build-slice 1: one reader holds the agent-seat record rules](https://github.com/nedschorus/nedschorus/pull/1063). Until that service runs, the mark would be a file in the log-store.
- **Neighbours.** GHI [Before a seat is retired, report what still cites the paths the retirement removes](https://github.com/nedschorus/nedschorus/issues/226) asks for a check that overlaps step 4. GHI [Relaunch stopped agent-seats with open tasks daily](https://github.com/nedschorus/nedschorus/issues/936) would relaunch a retired agent-seat whose tasks are still open, and names retirement as a case it needs settled.
- **Search receipt.** `scripts/ghi-info-ask.py --include-closed`, 2026-10-09, asked whether a GHI covers retirement as a program. ghi-info named GHI [Before a seat is retired, report what still cites the paths the retirement removes](https://github.com/nedschorus/nedschorus/issues/226) as the closest existing coverage, scoped to one part, and said to reconcile it; it also named GHI [Fleet survives a machine restart without losing seat context: detect, hand off on notice, relaunch at boot, resume from transcript](https://github.com/nedschorus/nedschorus/issues/116), GHI [recover-crashed-seats.py: the six changes ruled 2026-09-02 — exit record, process-identity liveness, parking marker, verified restart, by-hand resume, window](https://github.com/nedschorus/nedschorus/issues/242), whose parking marker is a mark of the same kind, GHI [A small service on ned-box keeps one record of every agent-seat on both machines](https://github.com/nedschorus/nedschorus/issues/972), GHI [Run named agents on the Ubuntu box, reachable from iTerm2 by name: launch-claude with tmux attach-or-create, and the migration it requires](https://github.com/nedschorus/nedschorus/issues/45), GHI [Relaunch stopped agent-seats with open tasks daily](https://github.com/nedschorus/nedschorus/issues/936), and GHI [Move mechanical agent chores into programs and hooks](https://github.com/nedschorus/nedschorus/issues/1036). None covers the whole design.

## What is not decided

1. **Where the mark lives** until GHI [A small service on ned-box keeps one record of every agent-seat on both machines](https://github.com/nedschorus/nedschorus/issues/972)'s service runs, and how the launchers on both machines read it: a file in the log-store is reachable from the Mac only through the `/Volumes/nedhome/` mount or `ssh nedlern@ned-box`.
2. **Open tasks at retirement.** Task 156, named above, proposes that marking refuses while open tasks remain. Step 5 has the user give each open task a new owner or close it. The program can do either one, or refuse first and then ask.
3. **Open tasks of an agent-seat that stopped without retiring.** In approval-walk eight-deferrals-with-no-trigger-2026-09-29, item 1, the user worried that "tasks might get lost if we don't restart some agent with tasks in it". The agent proposed a program check that names every task list with open tasks and no running handoff-supervisor, in the login restart, crash recovery and `scripts/seat-task-list-read.py --seats`, with renaming and retirement carrying open tasks forward (minutes: `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/eight-deferrals-with-no-trigger-2026-09-29-minutes.md`). That question is still open; the user decides whether it belongs here, in GHI [Relaunch stopped agent-seats with open tasks daily](https://github.com/nedschorus/nedschorus/issues/936), or nowhere.
4. **The citation check.** Whether this design's step 4 replaces GHI [Before a seat is retired, report what still cites the paths the retirement removes](https://github.com/nedschorus/nedschorus/issues/226)'s citation check, or GHI [Before a seat is retired, report what still cites the paths the retirement removes](https://github.com/nedschorus/nedschorus/issues/226) stays a separate check run before marking.
5. **The confirmation.** What the handoff-supervisor asks the user on exit, and what it does when no terminal is attached, as at a boot restart.
6. **Reusing a retired name.** Step 4 says the name is not reused until its pull request merges, and GHI [A small service on ned-box keeps one record of every agent-seat on both machines](https://github.com/nedschorus/nedschorus/issues/972)'s design keeps a retired agent-seat's row and makes a name unique only among agent-seats not retired. When the launchers stop refusing the name, and what clears the mark, is not settled.
