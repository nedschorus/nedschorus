# Agent-seat retirement as a program: the agent-seat marks itself retired, the handoff-supervisor confirms with the user and retires it, and the launchers refuse a retired name

This is a design and build task. Retiring an agent-seat, the glossary's retire-seat, is today a list of steps on a wiki page that an agent-session follows by hand. The user's design makes it a program. Before it marks itself, the agent-seat opens the pull request that removes its name from main (step 4 below). It then marks itself retired, for example with a command such as `scripts/retire-agent-seat.py <seat> --mark-retired`, the name proposed by task 156, "Build agent-seat retirement as a program: the agent-seat marks itself retired, and the handoff-supervisor confirms and retires it on exit", on agent-seat fleet-restart-at-login's task list (`python3 scripts/seat-task-list-read-nbd.py --seat fleet-restart-at-login --task 156`). When its agent-session exits, the handoff-supervisor, which runs on the agent-seat's own machine, finds the mark, asks the user to confirm, and does the remaining steps; an exit with no mark is handled as today. The launchers refuse to start an agent-seat under a name marked retired.

## Why

- The steps on main have drifted from the code. The "Retired" paragraph of `docs/nedschorus-wiki/nedschorus-agent-seat-model.md` has four steps. Step 2 moves only the session-handoff, leaving the state file, lock and numbered handoffs that a reused name's handoff-supervisor and the login restart read. Step 3 copies the seat-brief, which the user ruled against, as the bullet on main's steps below says. The page misses the agent-seat's tmux server, task list and Claude Code project directories. The retirement of the gatekeeper agent-seat, PR [The gatekeeper agent-seat is retired; the main-gatekeeper's design and plan stay](https://github.com/nedschorus/nedschorus/pull/1008), showed each gap.
- A rewrite of the steps grew to five careful steps, each with checks, after a cold-read-full-run. In approval-walk nedschorus-agent-seat-model-2026-10-04, item 2, the user said that the program which launches and reincarnates agents should let an agent mark itself retired and confirm the retirement on that agent's exit, and he approved building the steps as that program rather than as prose an agent follows (minutes: `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/nedschorus-agent-seat-model-2026-10-04-minutes.md`). On 2026-10-09, in agent-session fleet-restart-at-login, he approved routing the design to a GHI.
- Task lists are keyed by the agent-seat's name (`CLAUDE_CODE_TASK_LIST_ID='nedschorus-<seat>-tasks'`, set by `scripts/launch-claude-mac` and `scripts/launch-claude-ubuntu`). A retired or renamed agent-seat's open tasks stay in its store, where no running agent-session reads them and no one is told.

## What exists today

- **No program retires an agent-seat.** `git grep -i retire` on main over `scripts/` and `nc-systems/handoff/` finds the word only for retiring an agent-session or a tmux session (`scripts/recover-crashed-seats.py`, `scripts/resupervise-seat.py`, `nc-systems/handoff/handoff-write-and-check-supervisor.py`), never an agent-seat. Neither launcher checks for a retired name.
- **The specification is a git bundle in the log-store.** Branch `agent-seat-model-retire-steps-drift`, commit 2a5e9b63, "Agent-seat retire steps match the code and how gatekeeper was retired", through commit b0fce08e, "Retire steps: step 3 removes the worktree and seat-branch and keeps nothing", rewrote the "Retired" paragraph and the glossary's retire-seat entry, and was never merged. The user approved saving it as a bundle and deleting the branch, answering "A" on 2026-10-24 to item 17 of approval-walk fleet-restart-at-login-every-open-question-combined-approval-walk-2026-10-22 (minutes: `nedlern@ned-box:/home/nedlern/agents/fleet-restart-at-login/docs/walk/fleet-restart-at-login-every-open-question-combined-approval-walk-2026-10-22-minutes.md`, in agent-seat fleet-restart-at-login's worktree until the walk closes and its minutes move to `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/`). The bundle is `nedlern@ned-box:/home/nedlern/nedschorus-logs/seats/fleet-restart-at-login/agent-seat-model-retire-steps-drift-2026-10-24.bundle`; `git bundle verify` passes on it, it needs commit 7c5561eb of main, and `git fetch <bundle> agent-seat-model-retire-steps-drift:agent-seat-model-retire-steps-drift` restores the branch. Its five steps, as the user approved them in approval-walk agent-seat-retire-steps-drift-2026-10-04 and amended in approval-walk nedschorus-agent-seat-model-2026-10-04, were written for an agent-session to follow by hand on the agent-seat's own machine; in the program, step 4 is the pull request the agent-seat opens before it marks itself, and step 1's check becomes the handoff-supervisor's knowledge that its own agent-session has exited. The branch's text of the five steps, in which step 5's `scripts/seat-task-list-read.py` is now `scripts/seat-task-list-read-nbd.py` on main:

  > 1. **Stop the handoff-supervisor and the agent-seat's tmux server.** An agent-seat whose handoff-supervisor is alive gets a fresh session-handoff each time it is replaced, so moving its files while the handoff-supervisor runs only clears them until the next one. The user exits the agent-session (`/exit`); an agent cannot. Then run `python3 nc-systems/handoff/handoff-supervisor.py --agent <seat> --check`, which exits 0 when a handoff-supervisor of the agent-seat is running. If it reports one running, tell the user and stop. Then run `tmux -L <seat> kill-server`, so a later agent-seat with the same name does not attach to the old tmux session.
  > 2. **Move the agent-seat's files in `~/.claude/handoffs/` to the log-store.** The retirement directory is `nedschorus-logs/seats/<seat>/retired-agent-seat-YYYY-MM-DD/` in the log-store, with today's UTC date: under `/home/nedlern/` on ned-box, and on the Mac under `/Volumes/nedhome/`, where the Mac mounts ned-box's home directory. If the Mac does not have that mount, tell the user and stop. If the retirement directory exists, add `-2` to its name, or the first of `-3`, `-4` and so on that does not exist. Create it and its `handoffs/` directory, and move into `handoffs/` every file in `~/.claude/handoffs/` whose name begins `<seat>-`, except the files of other agent-seats: for each directory under `~/agents/` whose name begins `<seat>-`, such as `~/agents/<seat>-2`, leave every file whose name begins with that directory's name followed by `-`.
  > 3. **Remove the worktree and the seat-branch.** Run `git -C ~/Projects/nedschorus worktree remove --force ~/agents/<seat>` (not `rm`: the worktree would stay registered, and `git worktree prune` would then be needed), or `rmdir ~/agents/<seat>` if it is not a worktree, which a failed launch can leave as an empty directory. Then delete the seat-branch with `git -C ~/Projects/nedschorus branch -D <seat>`, if it exists. Nothing in the worktree or on the seat-branch is kept: the machine's backups hold it, Time Machine on the Mac and Timeshift on ned-box, and an agent's work can be redone.
  > 4. **Remove the name from the repository.** From a topic branch cut from main, run `git -C ~/Projects/nedschorus fetch origin`, then search main for the agent-seat's name with `git grep -n -w <seat> origin/main` and `git ls-tree -r --name-only origin/main | grep -- <seat>`. Skip each hit that names a longer agent-seat name beginning with `<seat>-`. In a pull request, change each place that names the agent-seat as running or as the owner of a subject, and give that subject a new owner or say that it stops; a change to a file the user reviews goes to him first, as any change to such a file does. Leave history alone: commit messages, merged pull requests and records in the log-store keep the name. Do not reuse the name until this pull request merges.
  > 5. **Move the task list and the Claude Code project directories.** List the agent-seat's open tasks with `python3 scripts/seat-task-list-read.py --seat <seat>`. If there are any, show them to the user and, as he decides, have another agent-seat take each one or close it. Then, with the user's approval, since the agent-seat's memory is among them, move `~/.claude/tasks/nedschorus-<seat>-tasks/` and each directory under `~/.claude/projects/` whose name ends `-agents-<seat>`, where they exist, into the retirement directory from step 2.

## Deferred-decisions

1. **Where the mark lives** until GHI [A small service on ned-box keeps one record of every agent-seat on both machines](https://github.com/nedschorus/nedschorus/issues/972)'s service runs, and how the launchers on both machines read it: a file in the log-store is reachable from the Mac only through the `/Volumes/nedhome/` mount or `ssh nedlern@ned-box`.
2. **Open tasks at retirement.** Task 156, named above, proposes that marking refuses while open tasks remain. Step 5 has the user give each open task a new owner or close it. The program can do either one, or refuse first and then ask.
3. **Open tasks of an agent-seat that stopped without retiring.** In approval-walk eight-deferrals-with-no-trigger-2026-09-29, item 1, the user worried that "tasks might get lost if we don't restart some agent with tasks in it". The agent proposed a program check that names every task list with open tasks and no running handoff-supervisor, in the login restart, crash recovery and `scripts/seat-task-list-read-nbd.py --seats`, with renaming and retirement carrying open tasks forward (minutes: `nedlern@ned-box:/home/nedlern/nedschorus-logs/walk/eight-deferrals-with-no-trigger-2026-09-29-minutes.md`). That question is still open; the user decides whether it belongs here, in GHI [Relaunch stopped agent-seats with open tasks daily](https://github.com/nedschorus/nedschorus/issues/936), or nowhere.
4. **The citation check.** Whether this design's step 4 replaces GHI [Before a seat is retired, report what still cites the paths the retirement removes](https://github.com/nedschorus/nedschorus/issues/226)'s citation check, or GHI [Before a seat is retired, report what still cites the paths the retirement removes](https://github.com/nedschorus/nedschorus/issues/226) stays a separate check run before marking.
5. **The confirmation.** What the handoff-supervisor asks the user on exit, and what it does when no terminal is attached, as at a boot restart.
6. **Reusing a retired name.** Step 4 says the name is not reused until its pull request merges, and GHI [A small service on ned-box keeps one record of every agent-seat on both machines](https://github.com/nedschorus/nedschorus/issues/972)'s design keeps a retired agent-seat's row and makes a name unique only among agent-seats not retired. When the launchers stop refusing the name, and what clears the mark, is not settled.
