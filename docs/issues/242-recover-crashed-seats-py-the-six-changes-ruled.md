2. ~~**Record how the agent exited.**~~ **Done, PR [Supervisor records how its agent exited; recovery offers that seat instead of resuming it](https://github.com/nedschorus/nedschorus/pull/457).** At a terminal, recovery now asks before closing a leftover shell, and on a yes restarts a seat stopped on purpose (PR [Ask the operator about a seat's leftover idle shell](https://github.com/nedschorus/nedschorus/pull/471), PR [Recovery: the leftover-window question says whether the seat comes back](https://github.com/nedschorus/nedschorus/pull/484), PR [Recovery asks to restart the seat by name, and restarts a seat stopped on purpose on a yes](https://github.com/nedschorus/nedschorus/pull/498)). PR [Recovery asks to restart the seat by name, and restarts a seat stopped on purpose on a yes](https://github.com/nedschorus/nedschorus/pull/498) also fixed the printed by-hand resume, which told the resumed agent it had crashed. The supervisor writes the agent's exit code and time into its state file immediately before stopping. Recovery treats a recorded clean exit as not a crash — offer restart, park, or finished — and no record as a crash to resume. With that in place the tmux check is relaxed; the launch collision (`tmux new-session` failing on an existing name, swallowed into an exit-zero message) reports failure; and the occupancy check ignores only a shell with nothing running under it. **The `prof` specimen is gone** (2026-09-11): ned-box was rebooted on the user's word to confirm GHI [Fleet survives a machine restart without losing seat context: detect, hand off on notice, relaunch at boot, resume from transcript](https://github.com/nedschorus/nedschorus/issues/116)'s selection against a real boot, killing its tmux server. It is reproducible, not lost — the launcher's wrapper drops the pane to a shell, so any seat whose supervisor exits leaves this state — and **not recreated in advance** (the user, asked if it was worth restoring: *"probably not"*). Make one on a throwaway seat when change 2 is built, not before.
3. **A durable parking marker** that every automatic path consults before selecting a seat, and that a requested resume clears. It records the reason, because the same state is entered on the user's word and by the login restart when a seat cannot be brought back.

Confirmed live on ned-box in both directions; the evidence and the two timing constants are in the PR.
5. ~~**A by-hand launch resumes a crashed seat.**~~ **Done, PR [A by-hand launch resumes a crashed seat instead of minting an empty session](https://github.com/nedschorus/nedschorus/pull/566), merged 2026-09-21 as `69e63be`.** The change is in the supervisor's first-launch path; both launchers inherit it. **Verified live on ned-box 2026-09-20**, in an isolated worktree at the pull request's head with the durable checkout untouched: against a seat with a planted transcript holding real work and no recorded exit, the real supervisor printed "no waiting handoff and no recorded exit — resuming this seat's last transcript 4083d6f5-7c5f-4482-b5f8-1c02c3f06f4b rather than starting it empty", launched `claude --resume 4083d6f5-7c5f-4482-b5f8-1c02c3f06f4b` with the resume prompt, and that transcript grew rather than a new one being minted. **Two things it did NOT deliver**, both recorded rather than smoothed over: the parked-mark clear the same sentence asks for waits on change 3, which is not built; and "a resume that fails again under a by-hand launch is reported in the terminal" is NOT built — a first live run with a deliberately invalid session id had `claude` refuse it, and the supervisor said only "session ended without a handoff; supervisor stopping", never that the resume had failed. That reporting is change 4's shape applied to this path and is still owed. Original text follows. `launch-claude-mac <seat>` or `launch-claude-ubuntu <seat>` with no waiting handoff and no recorded clean exit resumes the last transcript and clears the parked mark. Measured 2026-09-02: today the supervisor's first launch mints an empty session ("No handoff exists yet; ask what to work on"), discarding the crashed context on both machines.
6. **Recover into a window**: an opt-in `--open-iterm-window-per-seat`, macOS only, through `scripts/open-iterm-window-running-command`, with the resume argument encoded into the command text because an iTerm custom command does not inherit this script's environment.

## Why

The fleet-restart program `restart-live-seats-at-login` (GHI [Fleet survives a machine restart without losing seat context: detect, hand off on notice, relaunch at boot, resume from transcript](https://github.com/nedschorus/nedschorus/issues/116)) calls this tool at login with nobody watching. Without 1 and 4 it recovers nothing in the machine's first minute and misreports what it did. Without 2, 3 and 5 a seat the user closed on purpose comes back as a paid session, or a crashed seat launched by hand loses its context. The user's constraint, 2026-09-02: "as long as when I use the launch-claude-mac or launch-claude-ubuntu it does the right thing. That is key."

**Revised 2026-09-11:** GHI [Fleet survives a machine restart without losing seat context: detect, hand off on notice, relaunch at boot, resume from transcript](https://github.com/nedschorus/nedschorus/issues/116)'s build step 4 — the login restart itself — is the only thing left in that program, and it was blocked on 1 and 4, not on 2.
