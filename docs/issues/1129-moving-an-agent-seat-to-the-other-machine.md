# Moving an agent-seat to the other machine in one handoff that stops it on the old machine and starts it on the new one without restart prompts

This is a design task. Moving an agent-seat between the Mac and ned-box is today a by-hand sequence built on a handoff that asks the user "restart? y/n" on both machines, where the two questions need opposite answers. This GHI asks for a move that one handoff carries out: the handoff-supervisor on the old machine stops without asking, the agent-seat starts on the new machine without asking, and the design says what, if anything, should still ask the user, and when.

## Why

On 2026-10-04 agent-seat fleet-restart-at-login moved from the Mac to ned-box. Its agent-session wrote its session-handoff with `--dont-restart`, so that the Mac's handoff-supervisor would ask before relaunching and the user would answer "n". The question, "restart? y/n", means "relaunch this agent-seat on this machine?", and twice it was answered "y", so the agent-seat relaunched on the Mac instead of moving; the second successor found itself on the Mac and stopped. The move succeeded only after the agent-session told the user to answer "n" on the Mac, run the ned-box launcher, and answer "y" to the same question on ned-box. The user found the prompts annoying, and one agent-seat name must never run on both machines at once, which a wrong answer risks. Sources: task 153, "A seat-move handoff stops the old machine without asking and starts on the new one without asking", on agent-seat fleet-restart-at-login's task list (`python3 scripts/seat-task-list-read.py --seat fleet-restart-at-login --task 153`), and the Mac agent-session's transcript mirrored at `nedlern@ned-box:/home/nedlern/nedschorus-logs/transcripts/mac/projects/-Users-el-agents-fleet-restart-at-login/34683cb7-3e88-4154-9474-957e094efa67.jsonl` (2026-10-04, 02:16 to 02:24 UTC). On 2026-10-09, in agent-session fleet-restart-at-login, the user approved routing the design to a GHI.

## What exists today

- **No program moves an agent-seat.** Searches of `nc-systems/handoff/` and `scripts/` on main, of every local and remote branch's handoff code and launchers, and of the log-store's Markdown files, for "seat move", "move seat" and machine-move options, found no code that moves an agent-seat between machines. The phrase "the seat move" in `nc-systems/handoff/handoff-design.md` ("Open question — attached to the seat move") and in `docs/issues/45-remote-named-agent-launch-and-reattach.md` means an earlier event, the 2026-08 move of the fleet onto ned-box under GHI [Run named agents on the Ubuntu box, reachable from iTerm2 by name: launch-claude with tmux attach-or-create, and the migration it requires](https://github.com/nedschorus/nedschorus/issues/45), not this design.
- **The two questions.** `nc-systems/handoff/handoff-supervisor.py` asks "restart? y/n" in two places when the session-handoff carries the `dont-restart` field: at line 1721, when a running agent-session writes the handoff; and at line 1564, when a handoff-supervisor starts and finds an unconsumed handoff, as the new machine's does. Any answer but "y" stops and records an exit. Without a terminal, both stop without asking.
- **The by-hand steps used on 2026-10-04.** The Mac's agent-sessions copied the session-handoff and the task list's files to ned-box by hand (the transcript shows `scp` of a task file; the handoff, counter 21, was on ned-box before the launch), wrote the handoff with `--dont-restart`, and asked the user to answer "n" on the Mac, then to run `scripts/launch-claude-ubuntu fleet-restart-at-login` from the Mac and answer "y" on ned-box. The launcher created the agent-home on ned-box. Nothing recorded which machine the agent-seat now runs on.
- **Related designs.** GHI [A small service on ned-box keeps one record of every agent-seat on both machines](https://github.com/nedschorus/nedschorus/issues/972) records each agent-seat per machine, which a move changes. GHI [Seat mailboxes across machines and runtimes](https://github.com/nedschorus/nedschorus/issues/749) and GHI [Cross-session messages between agent-seats reach stale offline Remote Control entries instead of the live agent-session](https://github.com/nedschorus/nedschorus/issues/1115) concern reaching an agent-seat after it moves. GHI [A crash-recovered ned-box seat runs without its own GitHub token, and the Mac launcher warns of a missing token when it only attaches](https://github.com/nedschorus/nedschorus/issues/759) is a ned-box start that lacks something the Mac start had.
- **Search receipt.** `scripts/ghi-info-ask.py --include-closed`, 2026-10-09, asked whether a GHI covers moving an agent-seat between machines or asking the user before it. ghi-info answered that none does, and named the precedents listed under point 1 below.

## What is not decided

1. **Whether anything asks, and where.** Two precedents pull opposite ways. GHI [Fleet survives a machine restart without losing seat context: detect, hand off on notice, relaunch at boot, resume from transcript](https://github.com/nedschorus/nedschorus/issues/116) and GHI [Relaunch stopped agent-seats with open tasks daily](https://github.com/nedschorus/nedschorus/issues/936) restart agent-seats by a rule, with no question each time. GHI [recover-crashed-seats.py: the six changes ruled 2026-09-02 — exit record, process-identity liveness, parking marker, verified restart, by-hand resume, window](https://github.com/nedschorus/nedschorus/issues/242) keeps a by-hand resume, and the closed GHI [The handoff-supervisor resumes a session that died without a handoff, instead of stopping the seat](https://github.com/nedschorus/nedschorus/issues/613) records when a supervisor should resume on its own. The candidate answer is one question, asked by the agent-session in prose in its conversation with the user before the move begins, with no question on either machine afterwards.
2. **Which program starts the new machine's agent-session.** A Mac agent-session can reach ned-box with `ssh nedlern@ned-box`, but ned-box has no route to the Mac, so a move from ned-box to the Mac may need the user to run the Mac launcher.
3. **What the move carries.** The session-handoff, the task list, and whatever the new machine lacks, such as a GitHub token; commits the old agent-home has not pushed; and what happens to the old agent-home and seat-branch, which a later move back would reuse.
4. **How the move is told apart from `--dont-restart`.** `--dont-restart` is an option of the handoff writer, `nc-systems/handoff/handoff-write-and-check-supervisor.py`, which writes the `dont-restart` field into the session-handoff. Task 153, named under Why, proposed a second option on the same writer, for example `--moving-to-machine`, which copies the handoff, stops the old handoff-supervisor with no question, and lets the new machine's boot ignite with no question.
5. **What happens when the new machine cannot be reached** or its `claude` is logged out, as GHI [Tell the user when ned-box's claude is logged out or ned-box's subscription has run out](https://github.com/nedschorus/nedschorus/issues/337) requires to be reported: whether the move checks the new machine before the old agent-session stops, and keeps the agent-seat running on the old machine when the check fails, or says clearly that it stopped.
6. **Never on both machines.** How the new machine's handoff-supervisor knows that the old one has stopped before it launches, so that a failure partway through cannot leave the agent-seat running on both.

## Next action

Put points 1 to 6 to the user in an approval-walk. Then write the design for the move, with a test that runs a move between two handoff directories on one machine and checks that neither handoff-supervisor asks and that only one agent-session of the agent-seat is running afterwards, and one supervised move of a test agent-seat from the Mac to ned-box and back.
