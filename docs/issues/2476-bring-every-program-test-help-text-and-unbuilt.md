# Bring every program, test, help text and unbuilt design into line with the wiki page on how a program reports success, failure and findings with its exit code

Every program in this project ends with an exit code, and the programs, shells, CI steps and agents that run it act on that code before they read any output. Today the same code means different things in different programs: some exit 0 after a step failed, some exit 1 when they crashed, and about 25 use codes above 2 that a caller testing for nonzero cannot tell from 1. A caller then stops on success or carries on after a failure. The wiki page in pull request [Add the wiki page on how a program reports success, failure and findings with its exit code](https://github.com/nedschorus/nedschorus/pull/2474) sets one meaning for each code: 0 yes, 1 no, 2 could not answer, each program's yes-or-no question stated in its `--help` and its docstring, the answer and verdict line on stdout, progress and causes on stderr, and Claude Code hooks and git hooks following their hosts' codes. Once that pull request merges, the page's path is `docs/nedschorus-wiki/nedschorus-how-a-program-reports-success-failure-and-findings-with-its-exit-code.md`; until then, read the page in the pull request. This GHI is the work of changing every program, test file, `--help` text, docstring, caller, instruction and design not yet built so that each follows the page. Owner: not yet assigned; merge-lane-2 assigns one.
