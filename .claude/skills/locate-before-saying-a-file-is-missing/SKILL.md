# Locate before saying a file is missing

Files agents call missing are usually somewhere they did not look: another checkout, the other machine, the log-store, an agent-session transcript, git history or a backup. Say what you searched and what you could not search; never say a file does not exist.

1. For an approval or another passage written inside a file, go to step 7. For a file, from the root of a checkout of this repository, run `python3 scripts/locate-file-copies-across-machines.py '<name>'`, quoting the file's full name or its path. The locator, as this skill calls that program, searches checkouts, the log-store, the session-handoffs and conversation-tails in `~/.claude/handoffs/`, and git history. Run from the Mac, it also searches ned-box over ssh; a run on ned-box cannot search the Mac. When it lists nothing under its "Same name" or "Same path" heading, it then runs `scripts/find-deleted-path-across-backups.py`, the backup search, which also greps agent-session transcripts for the name you gave.
2. Read all of the output, and follow the instructions the locator and the backup search print for you: they name what to check, which places they did not search or searched only in part, and what to tell the user. The exit code covers only the locator's own search, before the backup search; it is not the answer.
3. Before you rely on a listed file, check that it is the file you want, not only a file with its name: a file with the same name can hold something else, a file listed as a candidate can be the one you want, and a transcript is listed whenever the name was only typed in it. If you cannot open a listed file, for example a Time Machine copy that needs root to read, report it as listed but unchecked, counted neither as found nor as ruled out.
4. If a listed file is the one you want, say where it is. If ned-box or the Mac was not searched, say that too: a newer copy may be there.
5. If none of the listed files is the one you want, say where the output says you looked, what it says was not searched, and which listed files you ruled out and why. If the locator listed files under "Same name" or "Same path" and you ruled them all out, the backup search did not run: say so, and run `python3 scripts/find-deleted-path-across-backups.py '<name>'` yourself from the root of the checkout, with the same name or path you gave the locator.
6. If the locator or the backup search fails, by printing an error or a traceback instead of a report, or by stopping before its report is complete, say so and quote what it printed: a search that failed is not a search that found nothing. The locator's report includes a "Took N s." line; when the backup search runs, its output includes a summary line that opens "Recoverable from:" or "No surface that could be searched has it."; output missing either line is a run that did not finish.
7. An approval has no file name, and the user's answer is usually just "y", so search for the subject of the question the user answered: from the root of a checkout, run `python3 scripts/locate-user-approval-by-question-subject.py` with one to three words naming that subject, read the question-and-answer pairs it prints, follow the instructions it prints, and report each place it searched. If it finds nothing, say "not found in" those places, never "no approval". A `.walk-approved` marker is deleted by the one edit it approves, so not finding one says nothing about whether an approval was given.
