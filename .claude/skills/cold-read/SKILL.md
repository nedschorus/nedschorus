# cold-read

## What to do

1. If the user asks for a fast or quick cold-read, skip the cold-read-full-run. If the cold-read-target is the walk-me-through MD file, the session-handoff, the PR description, an issue body, or CLAUDE.md, also skip the cold-read-full-run. Wiki files, skills and their prompts, the files under `docs/agents/`, designs, test designs, and design contracts need a cold-read-full-run. Everything else gets the cold-read-fast-read only.
2. Run `scripts/cold-read-fast-read.py --target <path>`. It writes a report at `docs/walk/<name>-suggestions.md` for an approval-walk draft or at `cold-read-records/<stem>-<date>/fast-read.md` for any other document, and prints the path. The report shows exactly how a fresh-reader interprets this prose, what confused it, and what it thinks is missing from the document. If it prints a line opening FAILED, tell the user and stop.
3. Your job is to make sure this prose is correctly understood by a fresh-reader. Revise the document accordingly. Fix what it misread, revise the text to resolve its issues, add what is missing. If you do not know how to resolve the fresh-reader's problems, or how to fill in what is missing, stop and ask the user to walk through these issues. If this document is not getting a cold-read-full-run, also stop here and run through your changes with the user. The cold-read-fast-read's own report is all the cold-read-record holds; there is nothing else to write.
4. If you are doing a cold-read-full-run, continue.
5. Run `scripts/cold-read-grid.py --target <path>` as a background task, and arm a Monitor on its output that emits an event per `saved:`, `RETRYING:`, `FAILED`, `AGENT-CLI DOWN:`, `STRAY WRITE:`, `WRITE CHECK DID NOT RUN:`, `FELL BACK:`, `RECOVERED:` and `TARGET CHANGED DURING RUN:` line. Each line is addressed to you: `saved:` means a finished review has landed and can be read now; `RETRYING:` means a cold-read-cell's first attempt produced no review and it is being relaunched once with the same model, which needs no action; `FAILED` means its retry produced no review either, so that report is absent, with the cause on the line (its line opens `FAILED (exit …)`, the one marker of the nine that carries no colon); `AGENT-CLI DOWN:` means every cold-read-cell of that agent-cli is absent for one cause, and the closing text names it for you to pass to the user; `STRAY WRITE:` means a reviewer changed a file that was not its own report — inspect it and revert it before triage, which is ordinary cleanup for you rather than something to escalate; `WRITE CHECK DID NOT RUN:` means that check could not run at all for a cold-read-cell, which is a failure to look rather than a clean result, so look yourself before you triage: `git status` tells you what changed but never who changed it, so read what it lists against the edits you know are your own, and revert only what you did not write; `FELL BACK:` means a cold-read-cell's first-choice model did not produce a report and names the model that actually wrote the one you are about to read, which needs no action beyond naming that model in `triage.md` if its report drives a change; `RECOVERED:` means the model wrote its report under the file name it was given but somewhere else under `cold-read-records/`, and the cold-read-cell moved it into place — the review is intact, and the line is there so a model that put its report in the wrong directory is not invisible to you; a report written under some other name, or outside that directory, is not looked for and its cold-read-cell reports `FAILED`; `TARGET CHANGED DURING RUN:` means the cold-read-target's bytes differed between the moment the cold-read-cells launched and the moment the last one finished, so the set was read against a document that moved under it and no report in it can be trusted to describe the file as it now stands — the script marks every report in the cold-read-record with a `<!-- TARGET CHANGED DURING RUN: … -->` line and exits 3, and the right response is to stop editing the document and start a new cold-read-full-run rather than to triage a set whose reports may review an earlier version of it. Keep your edits and keep the marked cold-read-record; the new run reads the cold-read-target as it now stands.
6. It launches six cold-read-cells and saves their reviews to the `cold-read-records/` directory. The reviews exist to be triaged. Read each report as it arrives. Triage as you go, but keep your judgments provisional until every cold-read-cell has reported or failed. These reports say what the reviewers think your prose means, which words they think are poorly chosen, which phrases confused them, what defects they found, and which key-terms fail the criteria in `.claude/skills/cold-read/prompts/terminology.md`. Those reviewers stand in for the fresh-reader who will have to act on your prose. Do not dismiss a report as stupid: it is what that reviewer honestly understood, and a fresh-reader without your context may understand it the same way. So favor the reviewer's reading of your words over your own sense of what you meant. A report can still get a fact wrong; record the correction in `triage.md`. If it's a misreading, rephrase your prose to make it unequivocal. If you are uncertain whether or how to clarify prose, ask the user. When every cold-read-cell has reported or failed, rewrite the document to fix the issues they found; do not edit it while the cold-read-cells are still running, because that invalidates every report in the run. When a cold-read-cell fails, the script's closing text names it and its error; pass an error the user could fix to the user, and triage the reports that landed unless the closing text says the cold-read-target changed.
7. Ask the user in four cases: before you reject a criticism, when you do not know how to address one, when addressing one would add or remove more than a sentence, and when it would need a new section. A criticism that goes against a user-ruling is not disposed of by that ruling: present the issue, the ruling, and your suggested fix, so the user can rule again. Record every finding you did not apply, with the reason, in `triage.md` beside the reports, then run `scripts/cold-read-record-ship.py <cold-read-record>` so the cold-read-record reaches the log-store on ned-box, and keep the directory after the work it served lands. A finding about an input you cannot fix here — a document this one relies on — goes in `triage.md` too, with the reason it does not change your result; if you cannot establish that reason, it is a step 3 stop, not a disposition. Commit the rewrite on the topic-branch you cut from main for this change.
8. Then walk the user through your committed changes and the findings you did not apply, with the walk-me-through skill, naming the walk after the cold-read-record; when it closes, write `docs/walk/<record>-dispositions.md`, one line per finding with what was ruled. A document that took the cold-read-full-run gets this approval-walk only; a document that stopped at step 3 gets its approval-walk there.
