# cold-read

## When Used

When a document of lasting value is finished, so future agents can clearly understand it (wiki files), use it properly (skills), or encode it (designs). A cold read is typically the final step before pushing such a document to main. Drafts in progress, and plans under development, are not ready for one.

## What to do

1. Run `scripts/cold-read-grid.py --target <path>` as a background task, and arm a Monitor on its output that emits an event per `saved:`, `FAILED`, `STRAY WRITE:`, `WRITE CHECK DID NOT RUN:`, `FELL BACK:`, `RECOVERED:` and `TARGET CHANGED DURING RUN:` line. Each line is addressed to you: `saved:` means a finished review has landed and can be read now; `FAILED` means a cell produced no review, surfacing immediately instead of being discovered at the end (its line opens `FAILED (exit …)`, the one marker of the seven that carries no colon); `STRAY WRITE:` means a reviewer changed a file that was not its own report — inspect it and revert it before triage, which is ordinary cleanup for you rather than something to escalate; `WRITE CHECK DID NOT RUN:` means that check could not run at all for a cell, which is a failure to look rather than a clean result; `FELL BACK:` means a cell's first-choice model did not produce a report and names the model that actually wrote the one you are about to read; `RECOVERED:` means the model wrote its report under the file name it was given but somewhere else under `cold-read-records/`, and the cell moved it into place — the review is intact, and the line is there so a model that put its report in the wrong directory is not invisible to you; a report written under some other name, or outside that directory, is not looked for and its cell reports `FAILED`; `TARGET CHANGED DURING RUN:` means the document's bytes differed between the moment the cells launched and the moment the last one finished, so the set was read against a document that moved under it and no report in it can be trusted to describe the file as it now stands — the grid marks every report in the record directory with a `<!-- TARGET CHANGED DURING RUN: … -->` line and exits 3, and the right response is to stop editing the document and run the grid again rather than to triage a set whose reports may review an earlier version of it. It launches eight reviewers and saves their reviews to the `cold-read-records/` directory — machine-local working material, gitignored and never committed (user-ruled 2026-08-14). The reviews exist to be triaged; what survives on main is the change they produce in the reviewed document and the rulings recorded in its governing document. The reviews themselves stay on the machine: keep the record directory after the work it served lands — like other logs, these records are useful for analysis later (user-ruled 2026-08-25). The script output tells you what to do next.
2. Read each report as it arrives. Triage as you go, but keep your judgments provisional until all eight reviews are in, as the later reviews may offer more insight than the earlier ones.
3. When you have processed all reviews and formulated a draft response, use the walk-me-through skill to walk through what problems were detected, and what you propose to do about them. Order the walk from items of most importance to least.
