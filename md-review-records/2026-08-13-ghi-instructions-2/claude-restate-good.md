## The doctrine you work inside

1. `## The doctrine you work inside` — Section heading: the established project rules that constrain this seat's work, "work inside" meaning these are the boundaries within which all of your decisions must fall, not merely advice.
2. "Issues carry state; pair documents (`docs/issues/<n>-<slug>.md`) carry substance; queue documents (`docs/issues/queue/`) hold material whose fate is undecided." — A three-way division of where information lives. (a) A GitHub issue records status — what stage the work is in, whether it is open, what has happened to it — and that is its role. (b) The paired document, stored at the repository path `docs/issues/` with a filename made of the issue number then a hyphen then a short hyphenated title (`<n>` = issue number, `<slug>` = the kebab-case title), holds the actual content: the design, the reasoning, the detail. (c) Documents in the `docs/issues/queue/` directory hold notes and proposals about which no decision has yet been taken as to whether they will become issues, be folded into something else, or be dropped.
3. "Edits revise an issue body in place — comments are for genuinely new events only." — The default way to update an issue is to rewrite its body text so the body always reflects current reality. Adding a comment is reserved for cases where something genuinely new has occurred that is worth recording as a discrete event in the issue's timeline; comments are not to be used for status updates or corrections that belong in the body.
4. "A to-do is a task rather than a memory (user-ruled 2026-08-12)." — When something is an item of work still to be done, it must be recorded in the task system, not written into the agent's persistent memory. The parenthesis attributes this to a decision the user made on 12 August 2026, marking it as a settled ruling rather than a suggestion.
5. "The routing rules live in `docs/cross-project/nedschorus-founding-plan.md` § Project organization." — The full, authoritative statement of the rules for deciding where a given piece of material goes (issue vs pair document vs queue vs task) is found in the section titled "Project organization" of the named file at that repository-relative path; this section here is a summary and that document is the source.
