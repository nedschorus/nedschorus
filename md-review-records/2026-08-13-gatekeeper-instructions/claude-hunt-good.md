## Findings, in document order

**1. Line 3 — "Your pile: **taking the git-gatekeeper from built-but-dormant to live.**"** — Class (d). "Pile" is the file's very first load-bearing noun and is never defined here. The pointer that would resolve it (`agent-seat-model.md`) arrives two sentences later and does not define the word either — it only uses it ("The pile it owns", "the seed of a seventh pile", "never merge two unrelated piles"). An agent must infer "pile" ≈ "the group of related tasks this seat owns" from usage. Harm: an agent that reads "pile" as a backlog/queue of enumerated items will go looking for a task list that does not exist and may treat the three road steps as the complete queue. Sure that the term is undefined here; unsure whether the author considers it project vocabulary already established elsewhere.

**2. Line 3 — "Every task here shares one specification, one program, and one threat model"** — Class (d). Two of the three have named locations in this file (specification = `docs/cross-project/git-gatekeeper-design.md`, program = `scripts/git-gatekeeper.py`). The threat model has none: no path, no section name, no issue. Harm: line 16's safety argument ("that is only safe once…") and line 17's constraints ("never an org owner") are threat-model claims the agent is expected to reason from, but it has nowhere to check them, so it either accepts them unexamined or invents its own model. Sure.
