# cold-read programs design

This design covers the programs in `nc-systems/cold-read/` and the reviewer prompts in `.claude/skills/cold-read/prompts/` that /cold-read runs. The skill itself, `.claude/skills/cold-read/SKILL.md`, says when and how an agent uses them. How a cold-read-full-run handles a cold-read-cell that fails is designed in `nc-systems/cold-read/cold-read-grid-cell-failure-handling-design.md`. Each program's docstring gives the user-rulings behind its behaviour.

## Programs

1. **`cold-read-grid.py`** runs a cold-read-full-run: `--target <path>`. It exits 0 when every report arrived and the cold-read-record reached the log-store, 1 when one or more report is absent or the cold-read-record did not reach the log-store, 2 when it launched no cold-read-cell, and 3 when the frozen-copy changed during the cold-read-full-run, whether or not the cold-read-record reached the log-store.
   - It refuses a cold-read-target whose file name ends in `-log`, `-report` or `-capture`, the names of a document that only reports what happened.
   - It counts the document's cold-read-full-runs since origin/main last took a change to it, prints "cold-read-full-run N of 3", and refuses a fourth. A cold-read-full-run counts when it saved a report, did not stop because its frozen-copy changed, and its cold-read-record is in the log-store or this checkout. After the user decides to run again, `--user-ruled-cold-read-full-run-count-restart` starts the count again at 1; inside design-to-main, `--cold-read-full-run-count-skipped-inside-design-to-main` keeps the cold-read-full-run out of every count, and the grid neither counts nor refuses it. When the log-store or git history cannot be read, the cold-read-full-run goes ahead and prints `EARLIER COLD-READ-FULL-RUNS NOT COUNTED:`.
   - It creates the cold-read-record `cold-read-records/<file stem>-<YYYY-MM-DD>/`, or `cold-read-records/SKILL-<skill directory name>-<YYYY-MM-DD>/` for a skill's `SKILL.md`, with `-2`, `-3` for a later read of the same document that day. The names come from `cold-read-record-names-common.py`.
   - It freezes a copy of the cold-read-target, the frozen-copy, into the cold-read-record, and the cold-read-cells read that copy; when the copy cannot be made, no cold-read-cell is launched.
   - It writes `reference-check.md`, a lead for the reviewing agent, not a finding. It lists each path, bare file name and `file://` link in the cold-read-target as `ok`, `UNRESOLVED` or `not checkable on this machine`, and leaves web URLs out; `not checkable on this machine` is a `file://` link under a home directory this machine does not have, and a bare file name is `ok` when exactly one file in the checkout has it; anything else is `UNRESOLVED`.
   - It launches six cold-read-cells in parallel: the defect-hunt prompt on the `deep` and `second-strongest-model` cold-read-tiers, and the terminology prompt on `deep` at reasoning effort `max`, each on both agent-binaries, `claude` and `codex`. Each cold-read-cell writes its report to `<agent-binary>-<hunt|terminology>-<cold-read-tier>.md` in the cold-read-record, `hunt` standing for defect-hunt, and the grid prints `saved:` as each one arrives.
   - A cold-read-cell that ends without a report is retried once, and the grid reports its cause; a cause the user can clear, such as a logged-out agent-binary, ends the closing text with "Tell the user: ...". A report still absent after the retry leaves the set incomplete: the grid marks every report in the cold-read-record with a comment naming each absent report and its cause, exits 1, and tells the reviewing agent to triage the reports that arrived and record each absence in `triage.md`. There is no timeout.
   - When the frozen-copy changes, the grid stops every cold-read-cell still running, marks every report with a `#frozen_copy_changed_during_run` comment line, and exits 3. That cold-read-full-run does not count toward the three, and a marker file in its cold-read-record records the stop; after the third such stop in a row, with no counted cold-read-full-run between them, the grid refuses to launch until it is given `--user-ruled-cold-read-full-run-count-restart`. An edit to the cold-read-target itself stops nothing: the cold-read-full-run finishes, counts and exits as it would have, and prints a `#cold_read_target_changed_during_run` line naming the frozen-copy the reports reviewed.
   - At the end, whatever the outcome, it ships the cold-read-record to the log-store and prints the next steps for the reviewing agent, which the skill does not repeat; an exit 2 ships nothing. A shipping failure is reported and does not fail the cold-read-full-run; the cold-read-record stays on disk.
2. **`cold-read-claude-cell.py`, `cold-read-codex-cell.py` and `cold-read-agy-cell.py`** each run one cold-read-cell on one agent-binary: `--cell <prompt> --tier <cold-read-tier> --target <path> --report <path>`, with `--target-origin`, `--prompt-file`, `--model` and `--effort` optional. The Claude and Codex cold-read-cells serve the `deep` and `second-strongest-model` cold-read-tiers, the agy cold-read-cell serves `fast`, and the Claude cold-read-cell also serves `fast` as the cold-read-fast-read's backup. Each pins its model and reasoning effort per cold-read-tier at the top of the file, with no fallback model; `--model` and `--effort` override the pin, and the grid gives `--effort max` to the terminology cold-read-cells. Each reads its prompt from `.claude/skills/cold-read/prompts/`, or from the file `--prompt-file` names, fills in the cold-read-target's path and the report's path, adds the frozen-copy's original path when the grid gives one with `--target-origin`, and runs the reviewer in the checkout's root, so all three agent-binaries read the same `CLAUDE.md`, Codex and agy through `AGENTS.md`. The reviewer may read the checkout, fetch the web pages the cold-read-target links to, and write its report, and a write to any other file is caught and reported; credentials are hidden from it. Only the Claude reviewer has no shell: the Codex reviewer runs commands under a permission profile, and agy runs inside the operating system's sandbox; the agy cold-read-cell refuses to start without it. Everything the three share, the report contract, the provenance comment with the sha256 of the bytes reviewed, and the check for writes outside the report among it, is in `cold-read-cell-common.py`. A cold-read-cell prints progress to stderr and nothing to stdout, and exits 64 when it refuses an invocation.
3. **`cold-read-fast-read.py`** runs a cold-read-fast-read: one fast-clarify cold-read-cell on the `fast` cold-read-tier, through `cold-read-agy-cell.py`, retried once unless the launcher refused the invocation or Gemini reported its spending cap; if the Gemini attempts fail, the same cold-read-cell runs once on Sonnet through `cold-read-claude-cell.py`. Its prompt is its own copy of `fast-clarify-prompt.md`, `FAST_CLARIFY_PROMPT_TEMPLATE`, passed with `--prompt-file`, which a test holds byte for byte equal to `.claude/skills/cold-read/prompts/fast-clarify-prompt.md`. A second cold-read-cell then asks Question 4, "What should be code", and its answer becomes the report's fourth section.
   - For a file `docs/walk/<name>-draft.md` in any git worktree it writes `docs/walk/<name>-suggestions.md` beside it, and lists there every bare GHI, pull request or task number in the file, or on stderr when the read fails. For anything else it writes `fast-read.md` in a new cold-read-record and ships the cold-read-record. A suggestions file left by an earlier read is replaced, never appended to.
   - The reviewer reads a copy with an id on every sentence, and the report gets a coverage section naming each sentence no restatement claimed. When step 2 of the /cold-read skill sends the cold-read-target to the cold-read-full-run, the program warns that this cold-read-fast-read does not finish the review. An edit to the cold-read-target during the read is named by a `#cold_read_target_changed_during_run` comment line in the report and on stderr.
   - It prints one line on stdout, the report's path or a line opening `FAILED`, and exits 0 on success, 1 on a failure, and 64 when `--target` is not a file; a read that wrote its report but whose cold-read-record did not reach the log-store prints the report's path and exits 1, and a walk draft's read, which ships nothing, never exits 1 for that; when `CLAUDE_CODE_SESSION_ID` is set, it writes `<report name>.agent-session.json` beside the report, naming the agent-session that ran it. On the Mac, a document in a ned-box worktree is read on ned-box over ssh; when ned-box cannot be reached, the program says so and exits 1. The Mac waits for that read at most 95 minutes, 30 minutes for each of the two Gemini attempts and the Sonnet attempt, and five minutes more, then ends ssh and exits 1; a read on ned-box that fails exits with that read's own exit code, or 1 when a signal killed ssh.
4. **`cold-read-record-ship.py`** copies a cold-read-record to `nedlern@ned-box:/home/nedlern/nedschorus-logs/cold-read-records/`. It never replaces a stored file except the cold-read-record's own `triage.md`, refuses a cold-read-record when the store holds one of its other files with different bytes, and prints `FAILED:` when ned-box cannot be reached or a copy fails, naming any staging directory it could not remove.
5. **`cold-read-restater-judge-runner.py`, `cold-read-restater-judge-cell.py` and `cold-read-reviewer-score.py`** measure reviewers: they judge a restater's output and score reviewers against a list of known defects.

Each program takes a relative path given on its command line from the current directory, not from the checkout that holds the program. A git or ssh command that fails is reported as a failure, never read as an empty answer.

The tests are in `nc-systems/cold-read/tests/`: each program has a suite of its own except `cold-read-claude-cell.py`, which `cold-read-cell-common-test.py` and `cold-read-grid-test.py` test.

## Reviewer prompts

A cold-read-full-run uses `defect-hunt-prompt.md` and `terminology-prompt.md`; a cold-read-fast-read uses its own copy of `fast-clarify-prompt.md`, so a change to that prompt is made in both. The fourth, `restate-prompt.md`, is still a `--cell` choice of the cold-read-cell programs, but no program runs it. The defect-hunt prompt's classes (g) and (h) check a mechanism or term that the cold-read-target itself defines, and never ask it to add one: class (g), a case the mechanism will meet that the document does not settle; class (h), a term that duplicates or conflicts with one in the checkout's root `CLAUDE.md`.

## cold-read-records

A cold-read-record is gitignored. It is kept after the work it served is merged to main, and shipped to the log-store, so that later analysis can read it. A cold-read-record has no README: each report starts with its provenance comment, and the file names follow the pattern above.

## Direction

The writing rules the project adopts for agent-instructions are candidates for new defect-hunt classes: where the project does not want agents instructed a certain way, the prompt would look for such instructions in the documents it reviews. The kept cold-read-records are the evidence for choosing such classes. No prompt change is commissioned.
